# V0.1 release evidence guide

V0.1 is the Transformer reference checkpoint after the immutable `v0.0.0` tag.
This guide and the [SPEC](../specs/versions/v0.1-reference-runner.md) are frozen
before the final gates. Prepared version strings, checked boxes and release
metadata are not publication proof. A completed release requires the verified
`release/v0.1.0/manifest.json`, every required profile, independent CI, and the
matching annotated remote `v0.1.0` tag.

## Required facts

| Gate | Evidence in the completed bundle |
|---|---|
| Canonical sampling | published Philox known answers, fixed processor/CDF stages, request-bound prepare/discard/commit and RNG tests |
| Tiny model | deterministic synthetic safetensors, tokenizer/config, strict spec, storage and alias manifest |
| Numerical oracle | tiny FP32 per-op/20-input comparison; pinned real model BF16 and FP16 CUDA comparisons with predeclared tolerances |
| Loading faults | config, missing/unexpected/duplicate, shape/dtype/storage/alias rejection tests |
| Generation and replay | one accepted terminal; metadata-only capture; R0 and R1_REFERENCE, not numerical R2 |
| Real GPU failure | isolated allocator-budget OOM, actual failed-request capture and R1, allocator restored before process exit |
| Performance | contexts8/32/128, warmups/repetitions and all observations, explicit stability rule, off/request/ops sampled-output invariance |
| Learning views | `screenshots/model-and-diff/` derived SVG diagrams with independently rebuilt bytes and input/output provenance |
| Rollback | source-bound release-mode rehearsal of the fixed previous tag; no local-only environments or large weights published |
| Portability | fresh Linux CPU environment, actual offline-bootstrap/quality/test/demo/replay/baseline transcripts; portable fact verification |

All three required profiles share `project_root_digest`, `bootstrap_digest` and
`base_lock_digest`. CPU/CUDA runtime locks are deliberately different; their
combined lock digests must not be falsely equated. The Windows formal profile
uses Python3.12.14 and Linux uses Python3.12.3. The separate Windows Actions
Python3.12.10 profile is development-CI-only and is rejected by the release
qualification producer/reader.

See [the execution recipe](../../evidence/v0.1/commands.txt),
[numerical decisions](../adr/ADR-005-reference-model-and-sampling.md),
[rollback procedure](v0.1-rollback.md) and [teach-back](../teach-back-v0.1.md).
Measured values and test counts live in the final source-bound artifacts, not
manually copied numbers in this guide. Forward wall time is not kernel time;
host export and sampling are separate partial spans, not a complete overhead
accounting or a telemetry latency comparison. No speedup over other engines is
claimed.

## Development history is not release qualification

Actual tiny CPU, real BF16/FP16, TF32-guard, OOM and previous-tag rollback
experiments were run during development. The original RoPE/oracle and FP16
causal-mask failures remain preserved; neither tolerance was relaxed.

The first fixed-source Windows/GPU preflights (`out/v01-preflight-cpu-2` and
`out/v01-preflight-gpu-1`) passed their model, capture, baseline and failure
phases, but **failed qualification** because pytest merged successful subtests
into parent XML cases while incrementing summary counts. Those failed runs
remain failed. The test-side adapter now preserves each real executed subtest,
including failures/skips, and the original strict JUnit reader remains intact.

Only reruns from the final frozen source can grant the three release profiles.
Old development manifests intentionally stop working after source changes.
WSL clean rooms use unique native-ext4 checkouts under the user's workspace;
their environments are not copied across checkouts. The network policy is
offline resolution/local-model loading, not a claim of enforced network
isolation. This project still has no service daemon or interactive Web UI.
