# V0.1 → V0.0 的隔离回退演练

这是独立目录中的 artifact 回退演练，不是对当前工作目录执行 `git reset`，也不会停止正在运行的其他 V0.1/GPU 进程。
真正替换在线服务时，仍必须先停止该服务，再切换到经过演练的旧版本；本项目目前没有 HTTP daemon。

## 它验证什么

1. 本地 annotated tag `v0.0.0` 必须精确指向 `02f7068be26ed921b56857b563312177b7c2582d`；不 fetch、不重写 tag。
2. 从固定 commit 创建 ZIP，检查文件名、类型、大小预算和路径边界后，只解压到新的 `out/` 子目录。
3. 使用旧源码、旧仓库内 wheel 和旧 bootstrap 创建独立的最小环境；没有 Torch、Transformers 和 V0.1 engine。
4. 实际运行旧 toy scheduler、R0、R1 和完整的旧发布包验证。
5. 旧 reader 必须对 V0.1 capture 返回 `UNSUPPORTED_SCHEMA`；旧 CLI 必须拒绝 `generate` 和 `model`。
6. V0.1 capture、toolchain、model/weight/tokenizer manifests、SamplingSpec 和 numerical reports 复制到只读 quarantine，原文件不移动、不删除。

模型数值证据在这里仅被保留和校验链接；不会让 V0.0 解释它，也不会把原先的数值结论迁移成旧版本结论。
只读指创建时移除了文件写位（Windows 对应只读属性），不是面向恶意同账户程序的安全沙箱。

## 使用

在 finalized V0.1 环境内运行；下列路径必须替换为同一冻结源码对应的实际通过门禁的产物：

```sh
python scripts/in_env.py --manifest out/v01-gate/toolchain.json -- python scripts/rollback_v01.py --output out/v01-rollback --v01-capture out/v01-gate/capture --v01-toolchain-manifest out/v01-gate/toolchain.json --validation-directory out/v01-gate/validation --evidence-mode release
```

开发期可直接使用托管环境解释器与 `PYTHONPATH=src`，并传 `--evidence-mode development`。
开发演练不能满足正式发布包的 release-mode 门禁。输出必须是新目录，失败时保留日志与 `INCOMPLETE`，不能覆盖既有证据。

## 可移植事实与大文件

`verify_reference_rollback(root)` 只读取 `rollback-report.json`、精确 checksum inventory、实际命令/输出、旧 capture/发布包和隔离证据；
不依赖作者当时的 Python 环境路径，也不会执行旧程序。

`local-only/` 中的 ZIP、旧源码、旧环境是可重建工作材料，**不可盲目复制进 Git 发布包**。
发布者应只复制 `report.files` 列出的事实，再复制报告、`checksums.json` 与 `COMPLETE`。

tiny safetensors 约 110 KB，可以随事实保存。约 988 MB 的真实模型不会嵌入发布包。
可选 `--weights <固定真实模型的本地文件>` 会额外产生本地只读副本和 SHA-256 receipt；
副本只留在 `local-only/quarantine-weights/`。原权重缓存保持不变，portable verifier 只能确认 receipt 的身份与处置记录，不能在缺少外部大文件时重新验证其字节。

演练后明确失去真实模型推理、generate、sampling、model inspect/validate 和 R1_REFERENCE；保留 toy scheduler、R0 与 R1_TOY。
