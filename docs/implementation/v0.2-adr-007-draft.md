# ADR-007 拟稿：Versioned numerical execution policies for V0.2

- Status: proposed; **not accepted, not implemented**，2026-10-21。
- 此文件在 `docs/implementation`，不是已生效的 `docs/adr/ADR-007`。
- 方向B已获认可；以下具体协议及正式落地仍待独立确认。
- Normative draft: [具体协议](v0.2-numerical-policy-protocol.md)及
  [SPEC v3 amendment](v0.2-spec-v3-amendment-draft.md)。

## Context

既有V0.1 full-context A保持不变；当前cached C0在真实BF16/FP16上未满足
原逐元素阈值。受控诊断支持矩阵形状相关舍入，但未证明所有实现都不可能修复。
不能用文档把失败改成通过，不能用一个相同token或CPU/tiny代替GPU证据。

数值执行方式需要与数学模型身份、KV模式和环境分离：`none`不应同时隐含
旧A和新control。跨版本审计还需要知道cast、reduction shape、policy及兼容边界。

## Proposed decision

1. 保留V0.1 API/forward、ModelSpec/weight/tokenizer身份、sampler与历史资产。
2. 独立注册versioned、canonical-digest policy；先评估本文附件的rowwise +
   显式FP32 contraction/cast-boundary候选，不自动设默认。BF16/FP16/tiny
   storage实例不同；同profile B/C实例相同，KV mode单列。
3. B每步真全量重算并计算全部位置logits；C只算新增query并复用committed
   post-RoPE K/V。物理row/head调用、sidecar/prefix copies等成本如实记录。
4. 直接B↔C、普通Transformers D-native、独立tiny FP64 D-high、原golden、
   完整A/B/C fixed20 greedy、state/RNG/terminal/resource均为硬门。
5. **唯一拟降级的是新A↔B/C低精度逐元素旧兼容比较**：原threshold仍原样
   执行、失败仍记fail，保存首差/超差，不称与A数值等价；与release硬门结果分轴。
   C0退出新policy发布候选，但旧fail/INCOMPLETE和证据字节绝不改标。
6. D-native保持普通native-dtype/batched full-context。它可能继续否决候选；
   不在运行后改为rowwise、放宽threshold或设advisory。任何这种变更需另一决策。
7. 显式policy-aware格式迁移：capture3/envelope1/new catalog/[R0]、MemoryPlan2、
   stream API revision2与GenerationResult JSON3（旧JSON2不改）、新report kinds、
   qualification/release3、rollback-v2；保留旧版本reader。
   schema2的policy未记录事实不改变，不回填新ID。格式号不是replay能力级别。
8. 沿用累计3600秒预算及完整矩阵；历史余额unknown不启动CUDA。先有限pilot，
   成本/正确性任一no-go就安全停止；不自动追加额度、deps、kernel或实验范围。

## Supersedes / preserves

只在**批准后、V0.2新policy作用域**替代ADR-006隐含的单一oracle/fallback
及低精度数值验收路由。ADR-006其他单请求、状态、fence/lease、cancel、
stream/UTF8、隐私、metrics和R0规则不变。ADR-005对V0.1、原threshold、
canonical sampler、独立oracle及固定模型身份的权威不变。
不修改V0.1 tag/bundle或给旧capture追认policy。

## Alternatives and rejected shortcuts

- 方向A：继续直接修复A↔cached数值一致性，不修契约；仍合法但当前未解决。
- 原生低精度rowwise：可另提policy，但不能虚构后端内部FP32归约树；不在
  本候选失败后无需审批地切换。
- 自写CUDA/Rust/Triton或新增依赖：超本决策实验范围，需独立方案/预算。
- 拒绝：放宽阈值、换oracle自证、只比首token、GPU用FP32 shadow替代、
  prefix重算伪报query1、补零藏成本、少测矩阵、修改golden/历史失败。

## Consequences and no-go

优点是执行与兼容边界可审计，而不是承诺更快。代价是新增身份、版本分派、
独立验证和成本；FP32镜像、rowwise大量启动、完整head可能OOM或超预算。
不保证D-native通过、完整序列一致、跨环境逐位复现或性能领先。

任一硬门失败/未完成、预算无法核定或预计超限均no-go；不默认启用、不发
v0.2.0。实际实现后还要重新冻结最终source并完整验收，旧preflight不拼装。

## Rollback

只在新请求前显式选A+none，资源已知安全回收后才能复用；未知fence继续
quarantine/fail-stop。独立旧V0.1 binary与原tag/bundle照常验证，并明确拒绝
schema3。新reader保留schema0/1/2；原schema2回退与新增schema3回退都测。
旧binary没有新policy ID，不追认；新rollback报告绑定from/target/config/
source/capture及真实11项资源/fence证据。

## Approval and follow-through

具体协议/输入草案审核并明确批准后才将本稿移入正式ADR并应用SPEC v3。
可先批准规范+CPU实现，GPU须另满足已核清预算。发布目标仍为按既有17版本
路线逐阶段推进；此决策不宣布V0.2完成，更不缩小总目标。
