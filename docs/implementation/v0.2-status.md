# V0.2 development status

> Snapshot date: 2026-10-21. Package version: `0.2.0.dev0`.
> Release stage: `dev_snapshot`. Qualification tier: **unqualified**.

This page records implementation progress for the current working source. It is
not a release manifest and does not grant CPU, GPU, clean-room, or tag status.
The authoritative requirements remain the
[V0.2 SPEC](../specs/versions/v0.2-stateful-streaming.md) and
[ADR-006](../adr/ADR-006-stateful-streaming.md).

## Implemented development surface

| Area | Current development implementation | Boundary |
|---|---|---|
| Public facade | Separate `illm.engine.streaming.Engine` and tensor-free V0.2 DTOs | V0.1 `illm.engine.Engine` and DTO imports remain unchanged |
| Execution | Synchronous eager prefill/decode with `none` and `contiguous` KV modes | One accepted request; no queue or batching |
| Ownership | `ExecutionTicket`, completion fence, leases, staged KV commit/abort, quarantine | No asynchronous CPU/GPU overlap |
| Streaming | metadata → ordered token chunks → terminal; stateful detokenizer and `final_text_delta` | Terminal-ready requires proved cleanup |
| Cancellation | Idempotent cancel, unique logical winner, CLI first/second interrupt policy | Unknown fence fail-stops; it is not reported as successful release |
| Admission | Immutable single-request `MemoryPlan`, context and memory checks | No live free-memory admission policy |
| Capture | schema2 metadata-only capture, Request Story and Chrome trace derivation | Capability is exactly R0 |
| Metrics | Pure-stdlib `MetricRegistryV1`, five IDs, censors and outcome strata | Experimental; CLI does not invent client timestamps |
| CLI | `run`, `verify --fixture tiny-decoder`, `inspect request`; schema2 trace replay | No service or interactive Web UI |

The source also contains V0.2 real-model BF16/FP16 profiles with context capacity
512. Their presence is configuration, not proof that either GPU profile passed.

## Reproduce the development surface safely

The runtime artifact alias remains `v01-cpu`; that name identifies a dependency
lock, not V0.1 qualification. Environments are bound to the exact project source
digest. Never copy an environment from an old checkout or reuse an old manifest
after source changes.

Use CPython 3.12.14 for the locked Windows profile or 3.12.3 for locked Linux.
Bootstrap one fresh profile for the current source, then run every child command
through its manifest:

```sh
python scripts/fetch_runtime.py --runtime-profile v01-cpu --artifact-cache .illm/cache/runtime
python scripts/bootstrap.py --profile study-v02-current --runtime-profile v01-cpu --artifact-cache .illm/cache/runtime --locked --offline --write-manifest out/study-v02/toolchain.json --write-manifest-digest out/study-v02/toolchain.sha256
python scripts/in_env.py --manifest out/study-v02/toolchain.json --expected-manifest-digest-file out/study-v02/toolchain.sha256 -- python -m illm verify --fixture tiny-decoder
python scripts/in_env.py --manifest out/study-v02/toolchain.json --expected-manifest-digest-file out/study-v02/toolchain.sha256 -- python -m illm run --model fixture:tiny-decoder --prompt hello --max-new-tokens 4 --seed 7 --stream
```

If the source, lock, interpreter, environment root, manifest digest or handshake
differs, the runner must fail before project code executes. A convenient local
`PYTHONPATH=src` run is useful for development only and is never release evidence.
