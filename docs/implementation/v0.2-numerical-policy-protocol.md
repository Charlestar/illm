# V0.2 方案 B：具体数值与实验协议（待批准）

> Protocol ID: `v02-numerical-policy-protocol-draft-1`。
> 2026-10-21，proposed / not implemented / unqualified。
> 方向认可不等于本附件已经获准实施。本文命令中标为“拟新增”的工具均不存在。
> 不修改正式 SPEC v2、ADR-005/006、V0.1 代码、历史报告或标签。

## 1. 一页决策边界

本轮只把[架构提案](v0.2-numerical-policy-proposal.md)补齐为可审阅协议。
采用一个具体候选：**逐位置、逐 attention head 的 FP32 contraction，明确
cast 回 profile dtype 的 eager 策略**。这不是把整个模型改成 FP32：参数、
KV、op 边界和 logits 仍为 BF16/FP16（tiny 为 FP32），只有规定的运算使用
FP32。报告必须同时写出 storage 与 compute dtype，不能简称“原生 BF16 算法”。

它是数值可解释性的开发候选，不是性能优化承诺。既有 r21 仅使用共同 FP32
contractions 仍失败；本候选额外固定所有行形状和 causal-prefix 调度，也
**没有经过验证**。不能把 r21 改名为本候选的结果。

| 路径 | 执行 | 角色 |
|---|---|---|
| A | 冻结 V0.1 eager full-context，原 profile dtype | 旧行为权威，永不重写 |
| C0 | 现有 cached 开发实现 | 原失败保留，不进入新策略发布候选 |
| B | 新 policy，每步从头重算全部位置，输出全部位置 logits | 未验证 control，不自封 oracle |
| C | 同一 policy，只计算新 query，KV 真正复用 | 未验证 incremental candidate |
| D-native | 未改写的 Transformers 4.57.1 ordinary full-context eager | **原 tolerance 的独立硬门** |
| D-high | 独立 CPU binary64 tiny 公式实现 | 数学语义硬门，非 GPU/低精度替身 |

唯一拟变为 report-only 的比较是 **A↔B/C 的低精度逐元素兼容**。
B↔C、D-native、D-high、完整 fixed-20 greedy、状态与资源、全性能矩阵仍为硬门。
因此 D-native 或成本仍可能让此候选 no-go；方案 B 不是发布豁免。

### 2.2 算术边界和顺序

令 `s` 为 profile storage dtype，`cast_s` 为 PyTorch 显式 dtype 转换。
Qwen 的完整参数/shape、RMS eps、RoPE theta 均取经过验证的 ModelSpec。

1. 从原 safetensors 独立验证后构建 `s` 参数。FP32 compute sidecar 从已转换的
   `s` 参数生成一次，不能从更精确的源直接生成以避开 storage rounding；tied
   embedding/head 只有一个 canonical storage 和一个 sidecar。转换时间/显存计入初始化。
2. 每个 linear（Q/K/V/O、gate/up/down、LM head）输入复制为 contiguous `[1,K]`；
   `F.linear(x.float(), W32, None)` 产出 FP32，再单独 FP32 加 bias（仅 Q/K/V），
   最后一次 `cast_s`。不可把多个 token 合并 GEMM、融合 bias 或只算最后一行 head。
3. RMSNorm 对每一行：`u=x.float()`，FP32 `mean(u*u)`（最后一维），加转换为
   FP32 的 model eps，`rsqrt`，FP32 乘 u，`cast_s`，再与 `s` norm weight 相乘。
   均为独立 eager op，不融合、无原地覆盖。
4. RoPE 对每个绝对位置独立计算：FP32 `arange(0,D,2)` 与 model theta 得到
   `1/(theta ** (i/D))`，乘该位置的 FP32 scalar，复制两半；cos/sin FP32 后
   `cast_s`。rotate-halves 为 `[-x[D/2:], x[:D/2]]`，两次 storage 乘后 storage
   加。固定单位置 shape，B 的最后一行不借用多位置频率矩阵。
5. 对绝对位置 p 的每个 Q head h，`kv_head=floor(h/(Hq/Hkv))`。只读取 key
   位置 `0..p`；Q/K promote FP32 后做 `[1,D]@[D,p+1]`，FP32 乘
   `float32(D**-0.5)`，再 `cast_s`。softmax 在 `[1,p+1]` 上以 FP32 计算，
   `cast_s`；PV 为 FP32 `[1,p+1]@[p+1,D]` 后 `cast_s`。不做 future padding，
   不让 cache capacity/stride 改变 contraction shape；prefix 的 contiguous
   materialization 时间和临时 bytes 必须计入。head 按升序拼回 hidden。
6. attention residual、SiLU、gate×up、MLP residual 全部逐行、storage dtype、
   独立 eager op；norm/head 如前。embedding lookup 与输出均 storage dtype。
   sampler 仍使用 ADR-005 CPU canonical sampler，不换成 GPU argmax/采样。

FP32 contraction 规定算术类型与调用 shape，不虚构 cuBLAS 的内部标量归约树
或禁止硬件 FMA 的保证。固定 Torch 2.8.0/平台锁、flags、环境并进行独立进程
验证；发生不确定算子报错即失败，不把 `warn_only` 打开。
[PyTorch 的确定性开关](https://docs.pytorch.org/docs/2.8/generated/torch.use_deterministic_algorithms.html)
不单独保证跨环境复现；[数值说明](https://docs.pytorch.org/docs/2.8/notes/numerical_accuracy.html)
也不保证数学等价的不同 shape 逐位一致。本文没有这种承诺。

### 2.3 真 KV 与完整 control

B 每步重算 `prompt + 已提交输出` 的每层全部行，并生成 `[1,T,vocab]` 全部 logits；
无跨步 KV 或 hidden memoization。C prefill 处理 prompt 全部行；每个 decode 只
处理上个已提交 token，新 query=1。缓存 post-RoPE K 与 V，storage dtype。
C 的 prefix K/V 必须与同一步 B 相应层/位置直接比较，不仅检查 append 长度。
最终输出不一定写入 KV：第 j 个输出后的 valid tokens 是 `prompt+j`（j 从0起）。

每个请求 acceptance 前冻结 policy，policy 变更使 MemoryPlan/KV/派生缓存失效。
未知/缺失新 policy 拒绝执行。回退只在新请求前显式 `legacy + none`，不在请求
中把 C 偷换成 B/A。fence、lease、staged commit、cancel/RNG 原合同不变。

## 4. 谁与谁比较、何时停止

### 4.1 逐步对齐与硬门

所有20 real case、两 dtype、每个输出步骤：记录 B↔C 全 vocab logits、token、
position、query/KV 长度、committed RNG counter-address、finish 和真实资源。
tiny50 + tiny20 同样执行，不只检查最终文本。以 B 为 expected；阈值用提案
§7.1 的原数字。任何 hardgate fail 后停止候选资格流程；已接受的请求安全回收。

real fixed-20 每步另执行 A/B/C 各自完整 greedy，输入各自已提交输出，直至
EOS 或8输出。比较整个 token列表、数量和 finish reason，不能靠 teacher forcing
掩盖 token 分叉。A↔B/C 元素差异另在 **A 的输入历史** 上逐步 teacher-force
计算，以隔离输入差异；这个额外成本也记入预算，不能从 free-running 差异
直接归咎于某个 op。compatibility 的元素 fail 不提前结束完整 greedy 轴。

全 op/全层采集固定为 tiny50+tiny20 的每步、real20 的 prefill 和第一次 decode
（若自然 EOS 无 decode，明确 N/A）；后续 real 输出仍全 vocab 比较。对齐每个
query 绝对位置，B prefill 的全部 query 和 C 全部 query逐行比较；decode 只比
最后一行并另核对 cached prefix K/V。D-native 同样覆盖这些采集点及每步 logits。

Q/K/V、RoPE、context、O、两种 norm、MLP 所有边界和 logits 用原 activation
tolerance；probabilities 用原 probability tolerance。attention trace 使用每个
query 的真实合法 prefix，slice D-native 同一 head/position 的 `0..p`，不
填充伪造 measured 值。单独硬检查 support 是且仅是 `0..p`、head 映射及
D-native future 概率为0，不能通过删除错误 mask 区域逃过比较。
shape、storage dtype、NaN/Inf 都是硬门；prefix 内不得容许 Inf sentinel。

### 4.2 D-native：普通 Transformers 不跟着候选改写

仅测试进程使用 pinned 4.57.1 的 `Qwen2ForCausalLM._from_config`，
`dtype=profile runtime dtype`、`attn_implementation="eager"`、`use_cache=False`。
独立从本地已校验 safetensors 严格加载，构造时保护全局 RNG；tied head 按
原配置绑定。只 `.to(device=...)`，不得 blanket cast model/buffers；原始
RoPE `inv_freq` 必须仍是 FP32。禁止读取 A/B/C 已构建参数或 helper 输出当 oracle。

普通 forward 的全位置 logits 与其独立 trace adapter 每次 `torch.equal`
交叉检查；adapter 必须由 Transformers-owned modules/RoPE/GQA 产生，不能
改用候选 rowwise/FP32 contraction。所有 profile 参数dtype、RoPEdtype、
package/source/asset 身份写入报告。B/C↔D-native 以 D 为 expected，原
activation/probability tolerance，tiny20 与 real20 同上采集范围；任何失败 no-go。
若它与候选的舍入不同，仍不许事后降为 advisory。

### 4.3 D-high：独立 binary64 tiny 数学语义

单独 CPU 进程，从 tiny 原 safetensors 重新校验/加载并转 binary64。
独立实现 embedding、RMSNorm、linear、RoPE、GQA、stable softmax、SiLU、
MLP、tied head 的数学公式；禁止导入 A/B/C、Transformers modeling helper 或
runtime KV/executor。允许 CPU Torch FP64 基础张量原语，不允许调用模型模块。
不模拟低精度 cast：这是数学语义比较，不是新 lowdtype oracle。

固定8例（所有 token 均是 tiny IDs）：

| case | 输入 | position IDs | 检查 |
|---|---|---|---|
| high-00 | `[3]` | `[0]` | 单 token、GQA、head |
| high-01 | `[4,5]` | `[0,1]` | causal prefix、非零 RoPE |
| high-02 | `[2]` | `[0]` | EOS 作为输入，不强制提前结束数学 forward |
| high-03 | `[0,0,0,0,0,0,0]` | `0..6` | repeated tokens、GQA |
| high-04 | `[1,2,258,3,257,4,256]` | `0..6` | vocab 边界、非等长prefix |
| high-05 | `[3,4]` | `[31,32]` | 仅公式级绝对位置测试；非普通请求的新起点 |
| high-06 | `3+((43*6+17*p)%256)`，31个 | `0..30` | 长prefix、两层累计 |
| high-07 | `3+((43*7+17*p)%256)`，255个 | `0..254` | capacity-1 边界 |

B 与 C 对除high-05外的7例均逐op/全位置直接比D-high；B为全量，C以1行
append重建同一token序列。这是无采样的底层forward测试，不伪造公共请求输出。
high-05 **仅检查独立RoPE公式原语**，不调用当前从position0开始的C lease/
request：Q[h,p,d]=(2*h+d-9)/16，K[h,p,d]=(3*h-d+5)/32，均先转FP32；
Q shape `[1,4,2,8]`、K `[1,2,2,8]`，位置31/32。两条policy执行模块的RoPE
入口分别比较独立FP64 expected，不据此声称公共请求支持非零起点。
expected 为 FP64，实际首先硬检查 FP32 storage，然后双方显式提升 FP64 计算
误差，沿用 tiny `atol=1e-4, rtol=1e-3`。报告角色必须区分此跨精度语义比较与
native-dtype 的 dtype 相等门；禁止把 FP64 expected cast FP32 来掩盖误差。
mask/GQA/position/tie 结构精确检查，非有限值失败。它不构成 real FP64 全模型
或 GPU correctness pass，也不新增 GPU50-case。

### 4.4 故意错误与独立进程

固定 mutation：tiny layer0 q weight 在正方形形状下错误转置（首差 q projection）、
decode absolute position +1（首差 RoPE/position）、GQA 映射错一组（首差
scores/context）、未来 key 可见（support 硬门）、替换一个 prefix K 元素
（prefix KV 硬门）、错误 policy digest/未知字段（acceptance前拒绝）、错误
cast/bias fusion（policy conformance 拒绝，不能等待最终文本）。每个反例须
真的触发失败；同样保存被修改的输入身份和观察，不以 unit mock 成功替代。

独立进程：tiny20 在新进程重跑一次；real 两 dtype 各自 fixed-00 在新进程
重跑完整最多8步，复用已存在固定用例而不扩 GPU50。比较原生 tensor bytes/
token/state digest；同硬件/环境不一致即 no-go。不共用 CUDA context、KV、
已算 tensor 或生成器状态，耗时计入预算。

## 5. 预算、外推和 no-go

### 5.1 账本先于 CUDA

预算沿用原 SPEC 的3600秒累计占用墙钟，**本次确认不重置、不追加**。
历史开发报告并无覆盖所有 r1..r21、初始化、失败及清理的连续计时；报告的
时间戳、进程存活时间或文件 mtime 都不是可直接相加的 GPU 占用证据。
当前余额标为 `unknown`，不可写0或3600；未核清或明确重新授权预算前，
**任何 CUDA 初始化/探针/正式实验均不得启动**。CPU 协议/实现工作不因此冒充GPU进展。

未来 ledger schema1 字段：budget ID、授权来源、cap_seconds3600、已核实
historical intervals（start/end/monotonic domain/evidence digest）、unknown
intervals、reservation、每次 stage/source/policy/environment identity、start/
end、safe cleanup/fence status、result、remaining。并发区间取 union 不重复
记账；缺项余额 unknown。以进程独占 GPU 的占用墙钟记账，包含初始化、等待、
transfer、校验/capture/export、失败和清理；不是只累计 CUDA event kernel 时间。
旧诊断账本与新 protocol 分列，但不默默从总预算扣除范围中排除旧诊断。

### 5.2 探针与成本模型

CPU 语义/输入/负测试通过后，若GPU余额明确且获得实施批准，先做 tuning-only
成本探针：两 dtype × 四组 ×（1 warmup+1 measured）=16完整请求、8次初始化。
顺序固定 BF16 none/request、none/off、contiguous/request、contiguous/off，
然后 FP16 同序；不看 heldout。最昂贵预期组优先，允许因预算提前 no-go，
不允许把未完成的探针标为完整矩阵。它不算正式 warmup/repetition。

正式 B/C 矩阵仍为两 suite × 两 dtype × 四组 ×（3+7）=160完整请求、
16次初始化，顺序按 dtype→tuning/heldout→上述组顺序，不能挑最快序列。
每个 B 请求18400 rows，每个 C 请求319 rows，合计1497520 rows；仅
24层×7linear 约251583360次行调用，**本候选还有 FP32 sidecar、复制和 head
成本，不能拿此下界当真实总耗时**。A 不另做完整性能矩阵，但 correctness/
compatibility 中的 A forward 全部计时。

探针+正式合计176请求、24次初始化、1647272 token-rows；仅上述7linear就
276741696次行调用。不是“1小时能完成”的证据。每次只保留被测必要模型，
A/D-native与candidate可顺序进程运行，以CPU快照对齐；不能假设8GB GPU能
同时常驻A/B/C/D。额外load/transfer/teardown照实计账，不从初始化计数中隐藏。

每个 timing：同步设备后记录 host monotonic 开始，初始化另计；请求从
acceptance前准备至 terminal-ready/必需capture完成，结束前同步。另记录
CUDA event、transfer/CPU/export 区间，不从总墙钟删减这些区间。
measured 与 warmup 各自保留原始值；显存包括常驻 sidecar、KV capacity、
prefix copies、全位置logits、临时workspace和 allocator peak，不只报 KV。

保守规划上界（规划值不是统计置信保证）：每组 `U_g=2*max(warmup,measured)`，
`U_init=2*max(8次init)`；正式剩余估算为所有未跑请求的 `U_g` 之和加剩余
init×`U_init`。已开始但未完成的请求不为其捏造 U；预算风险只能 no-go。
correctness pilot固定为real **BF16与FP16各自fixed-00** 的前两个模型step：
prefill→output0，再将各自已提交output0放回上下文→output1；C的第二步query=1，
A/B/D-native仍完整prefix。不是完整8步，不覆盖output2..7，也不授予资格。
若output0自然EOS或任一硬比较失败，该profile pilot incomplete/no-go，不能
teacher-force伪造第二步。D-high仅CPU，不计GPU占用，仍要独立通过CPU硬门。
以这两dtype的A/B/C/D-native实测耗时分别为pilot，
按后续各路径的 token-row 与合法 attention pair 数分别外推，取两个估算最大值
再乘2；20例各自完整序列、teacher-forcing兼容、per-op capture和独立进程均
单列，不以 A/B/C 三条共享一次forward虚减。后续观测只能上调 U，不能用
更快样本下调预算。heldout 从未参与参数/策略选择。

预留180秒安全清理、至少60秒封存；remaining ≤240秒时不启动新请求。
每个非pilot stage启动前必须满足
`remaining >= U_current + sum(U_future) + 180(cleanup) + 60(seal)`。
`U_current`仅为即将启动stage的保守完整成本；`U_future`是不含当前stage的
其他全部未完成stage。两者都须覆盖各自load/init、A/B/C/D-native、teacher-force、
per-op capture、独立进程、transfer/export/teardown等GPU-owned区间；不能
遗漏验证成本，也不能把同一任务同时放入current和future。reservation在唯一
GPU/budget租约下原子扣除，stage安全完成后按actual结算，未消费部分才能释放。
没有覆盖全部剩余阶段的估算时只允许限额pilot，不能启动正式矩阵。
future清单还必须显式列出最终同源GPU qualification（包括任何因source修改
重跑的成本）、需要CUDA的lifecycle/fault/100-cycle步骤以及rollback新primary
请求；纯CPU部分不冒充GPU覆盖，也不算GPU占用。已在其他stage计入的同一
执行不能再次相加，未计入的额外执行不能漏记。不得将最终重新验收假设成零成本。
pilot总上限120秒（含两dtype correctness pilot、tuning成本探针及相关初始化/
清理）且须仍保留240秒；在row/head/layer安全边界检查host
deadline，不再launch，等待已launch fence后abort/清理。禁止硬杀未知工作再报零资源。
首次full-request探针若不能在pilot限额内完成，保留incomplete/no-go，不继续16请求。
120秒不是免费额外预算。实际fence/清理超出预留时仍安全等待，ledger标
overrun/incomplete，停止新launch；不能硬杀未知工作或谎报预算合规。

任何 hardgate fail、OOM、不能自然完成64输出、余额不明、预计超限或 cleanup
不确定，立即 no-go/安全fail-stop。不能少测dtype/组/rep、强迫忽略EOS、改
阈值、换D-native或追加自写kernel挽救同一次结果。需要变更就先提交新决策。
