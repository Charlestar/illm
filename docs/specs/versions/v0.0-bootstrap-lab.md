> V0.0 把空目录变成可复现、可测试、可记录决策的 AI Infra 实验室。它不执行真实模型，但先固定后续所有版本依赖的工程、领域事件、Capture 和证据规范。

## 1. 本版本学习目标

### 1.1 必须掌握

- 能解释“可复现环境、代码版本、模型版本、硬件版本”为什么共同决定一次推理实验；
- 能实现不依赖 GPU/框架的请求状态、调度计划和事件 reducer；
- 能区分领域事件、日志、指标和 trace；
- 能从 checkpoint + ordered events 重建 toy scheduler 状态并验证 digest；
- 能使用 ADR 记录不可逆或跨模块决策。

### 1.2 建议先修

- Python package、typing、dataclass、pytest 基础；
- Git、虚拟环境、JSON/YAML、单调时钟基本概念。

### 1.3 进入门槛与预热实验

| 预热实验 | 命令/材料 | 通过标准 | 预计时间 |
|---|---|---|---:|
| 干净虚拟环境 | 在临时目录创建 venv，安装一个最小本地 package 并运行 pytest | 能解释 interpreter、lockfile/package 与工作目录分别影响什么 | 1 h |
| 纯 reducer | 用 5 个手写 event 折叠出最终 counter state | 交换两个非交换事件会让 digest/test 失败 | 1 h |
| 有界队列 | 写容量为 3 的 toy sink 并让 exporter 停顿 | producer 不无限阻塞，drop 被显式计数 | 1 h |

陌生术语先查[统一学习术语表](../GLOSSARY.md)。未通过预热实验时先补 Python/Git/测试基础，不开始正式 slice。

### 1.4 Teach-back 产物

- `teach-back-v0.0.md`：用一页说明 request、plan、event、checkpoint、replay 的关系；
- 一段 3～5 分钟演示：运行 toy scheduler、打开 capture、故意破坏一个事件并观察 replay 失败。

## 2. 用户可观察的成果

### 2.1 Release demo

```text
python scripts/bootstrap.py --profile dev --locked --write-manifest out/v0.0/toolchain.json
python scripts/in_env.py --manifest out/v0.0/toolchain.json -- python -m pytest tests/cpu
python scripts/in_env.py --manifest out/v0.0/toolchain.json -- python -m illm demo toy-scheduler --seed 7 --steps 20 --capture out/v0.0
python scripts/in_env.py --manifest out/v0.0/toolchain.json -- python -m illm replay out/v0.0 --mode trace
python scripts/in_env.py --manifest out/v0.0/toolchain.json -- python -m illm replay out/v0.0 --mode state --assert-state-digest
```

第一条命令使用系统 Python 仅建立环境；其余命令必须由 `in_env.py` 读取 manifest 后转交给环境内解释器。将一个会立即失败的假 `python/uv/illm` 放到 PATH 最前方时，上述四条 runner 命令仍必须命中 manifest 环境且假入口调用数为 0；篡改 interpreter、environment ID、lock/bootstrap/project-root digest 时必须在导入 `illm` 前失败。

## 3. Scope

### 3.1 本版本新增

- 跨平台 `scripts/bootstrap.py`：校验 Python/OS、安装或验证项目内固定版本工具链、按 lockfile 建环境并输出 `ToolchainManifest`；
- 跨平台 `scripts/in_env.py`：只消费 finalized `ToolchainManifest`，验证环境握手并在不调用 shell 的前提下执行环境内解释器/entrypoint；
- 模块化单体目录与依赖边界；
- 强类型 ID、不可变值对象、稳定枚举；
- toy request state machine 与纯函数 scheduler；
- R0 Event Playback、R1 toy Control-plane Replay；
- schema validation、state digest、capture checksum；
- `NoopSink` 与有界内存 sink；
- PR CPU gate。

### 3.2 本版本保持不变

- 无上一版本公开契约；本版首次建立后续版本的文档与证据格式。

### 3.3 Feature flags 与 fallback

| 能力 | 默认值 | Reference/fallback | 失败时行为 |
|---|---|---|---|
| telemetry | `metrics` | `off/NoopSink` | exporter 失败不影响 toy engine |
| replay | R0 + R1 | R0-only | 缺关键事件时 R1 fail closed |
| event serialization | JSONL v0 | in-memory typed events | schema 不支持则拒绝读取 |

## 5. Architecture Delta

### 5.1 相对空项目的变化

```text
empty workspace
  ↓
package + pure domain + toy scheduler
  ↓
canonical events → capture writer → checkpoint/events/checksums
  ↓
trace playback + state reducer + digest assertion
```

### 5.2 新增或修改的模块

| 模块 | 变化 | 责任边界 | 禁止事项 |
|---|---|---|---|
| `domain` | add | IDs、states、commands、plans、errors | 框架/GPU/HTTP 依赖 |
| `scheduler.reference` | add | snapshot → immutable plan | IO、全局状态、副作用 |
| `observability` | add | event schema、bus、sink | 修改 engine state |
| `capture` | add | manifest/checkpoint/event/checksum | 推测缺失事实 |
| `replay` | add | R0/R1 reducer 与 digest | 调用在线可变对象 |
| `cli` | add | demo/replay 参数与退出码 | 绕过 public facade |
| `scripts/bootstrap.py` | add | 建立锁定环境并原子写 manifest | 激活父 shell或默用全局工具 |
| `scripts/in_env.py` | add | 校验 manifest/握手，解析环境内命令并转发退出码 | PATH fallback、shell 拼接、执行环境外入口 |

### 5.3 数据流与状态迁移

```text
ToyWorkload → Command → ToyState → ToySchedulePlanV0 → DomainEvents
                                     │              │
                                     └─ checkpoint ─┴→ Capture
                                                        ↓
                                             Reducer → StateDigest
```

所有 event 使用 producer-local `seq_no`；duration 使用单调时钟。R1 reducer 只能消费 checkpoint 与 canonical event，不能导入 scheduler 再运行一次。

## 6. Contracts

### 6.1 API/CLI contract

- `bootstrap.py --write-manifest` 只有在环境安装、锁文件校验和握手全部成功后才原子 finalize；失败只留下明确标记的 incomplete 临时文件；
- `in_env.py --manifest MANIFEST -- ARGV...` 将首个 `python` 重写为 manifest 的解释器，将 console entrypoint 解析到 environment root 内，按原始 argv 启动且不经过 shell；
- runner 启动项目前验证 manifest schema/finalized、project root、bootstrap/lock digest、environment root containment，以及子进程返回的 `sys.executable/environment_id/lock_digest`；任一不符返回稳定 `TOOLCHAIN_MISMATCH`；
- 找不到环境内入口时返回 `TOOL_NOT_IN_LOCKED_ENV`，即使全局 PATH 存在同名命令也不得 fallback；子进程启动后 runner 原样返回其退出码；
- `demo toy-scheduler` 接受固定 seed、step 数和 capture 目录；
- `replay --mode trace|state` 显式选择能力；
- `--assert-state-digest`：一致返回 0，不一致返回稳定非零退出码并报告首次路径；
- 参数非法返回 `INVALID_ARGUMENT`，不产生半成品 bundle。

### 6.2 Config/manifest contract

| 字段/对象 | 稳定性 | 兼容规则 |
|---|---|---|
| `RunManifest v0` | experimental | 保存 git SHA/dirty、runtime、seed、schema、privacy、drop count |
| `ToolchainManifest v0` | experimental | 保存 schema/finalized、OS/arch、project/environment root、环境内 Python/entrypoints、environment ID、bootstrap/lock/project-root digest；全局隐式工具不得冒充 locked toolchain |
| `ReleaseManifest v0` | experimental | 保存 `spec_status/release_stage/qualification_tier/qualification_profiles/performance_outcome/lts_state`；profile 绑定 environment/evidence digest，聚合 tier 由 verifier 重算 |
| `DomainEvent v0` | experimental | enum number 不复用；未知必需事件拒绝 R1 |
| `ErrorRegistry v0` | experimental | code 稳定，内部堆栈不进入公开错误 |
| `StateDigest v0` | experimental | canonical field order + digest version |

### 6.3 Event/capture/replay contract

- 必需事件：request arrival/selected/deferred/completed、scheduler step、checkpoint、capture truncated；
- V0.0 支持 R0 与 toy R1，不支持 R2/R3；
- bundle 标注 replay capability、critical-event drops 和 `non_replayable_reasons`；
- 默认 `metadata_only`，不存任何 prompt/token 内容。

### 6.4 资源、并发与失败 contract

- event ring buffer 有界，达到上限时先丢低优先级诊断事件；
- state-transition/transaction 事件不可静默丢失；
- best-effort exporter 在独立有界 worker 中执行；异常或阻塞不得改变 toy scheduler 输出；队列满时统计 exporter drop，critical capture sink 仍同步保存必需事实；显式 close 的等待有界，不能强杀 Python 回调，超时报告仍在运行的 daemon worker；
- capture 写入采用临时状态 + 完成标记；进程中断后的 bundle 必须标为 incomplete。

## 8. Correctness and Invariants

### 8.1 Golden/differential

- 同 seed/config 的 toy plan 与 event-kind/ID 序列一致；时间戳不进入语义 digest；
- online state 与 R1 reducer 每 step digest 一致；
- JSONL encode/decode 后 typed payload 无损。

### 8.2 Property/state invariants

- request ID、step ID 唯一且单调；
- accepted toy request 恰好一个 terminal event；
- selected 与 deferred 集合无交集且覆盖 eligible requests；
- producer `seq_no` 连续；缺口被检测；
- capture checksum 覆盖所有事实文件。

### 8.3 Failure/stress matrix

| 场景 | 注入方式 | 必须结果 | 禁止结果 |
|---|---|---|---|
| 事件丢失 | 删除 critical event | R1 拒绝并定位 seq gap | 静默给出 digest |
| exporter stall | sink 阻塞 | engine 完成，drop counter 增长 | scheduler 被阻塞 |
| 中途终止 | writer 未 finalize | bundle 标记 incomplete | 被当作成功 capture |
| schema 未知 | 修改 required enum/version | reader fail closed | 猜测字段语义 |

固定 gate：至少 100 个随机 workload seeds、每个 100 steps；online/replay digest mismatch 为 0；CPU CI 在声明的时间预算内完成。

### 11.2 Rollback

- V0.0 没有前一个 release。rollback 定义为停止 toy process，并通过同一 `ToolchainManifest` 的 runner 从专用环境卸载 package；不得用另一个全局 Python 的 import failure 代替验证。
- 卸载后执行 `python scripts/in_env.py --manifest out/v0.0/toolchain.json -- python -c "import importlib.util,sys; sys.exit(0 if importlib.util.find_spec('illm') is None else 1)"`。它必须在**原环境解释器**中证明 package 已不可导入，再验证无后台进程/端口/项目环境变量残留。
- 只清理 manifest 明确列出的 `out/v0.0/` 临时 artifact；源码、用户目录和未列入 manifest 的文件不得删除。若销毁整个专用环境，先保存 manifest、卸载/验证 transcript 和 checksums 到 `rollback/`；需要重开时从 V0.0 tag 重新 bootstrap。
- `telemetry=off` 可禁用所有 sink，但不能绕过 domain tests；
- 未 finalized bundle 不允许迁移到后续版本。
