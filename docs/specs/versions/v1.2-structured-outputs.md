> v1.2.0 只交付 structured outputs：受限 regex、`json-subset-v1`、byte-level DFA、`SamplingSpec` v2、可视化与一致性语料。它不包含 draft model、speculative decoding、accept/reject 或 tentative KV；这些能力独立进入 v1.3.0。v1.1 无论是 NoCandidate、Adopt 或 No-go，v1.0 reference path 都是本版 correctness oracle。

## 1. 本版本学习目标

### 1.1 必须掌握

- 能解释 grammar source、规范化 byte-level 文法、NFA/DFA、token-byte transition 与 allowed-token mask 的关系。
- 能明确 regex full-match 与有限 JSON schema 的支持边界，并用 normative ABNF/EBNF 和 conformance corpus 区分合法、非法与 unsupported。
- 能实现 `SamplingSpec` v2 的 processor 顺序，证明 grammar mask、EOS、temperature、top-k、top-p 与 per-request RNG 的组合语义。
- 能在 tokenizer byte mapping、UTF-8 多字节 token、special token、DFA accepting/dead-end 和 max-token 边界上 fail closed。
- 能为 compiler cache、allowed-token cache、bitset workspace 与并发 compile 建立有界 `MemoryPlan`、配额和失效规则。
- 能把一次结构化生成解释为 `grammar state → allowed token set → sampled token → next state`，并用 capture/R1 replay 验证状态摘要。

### 1.2 建议先修

- v1.1.0 已发布，理解 v1.0 stable API、reference execution、SamplingSpec v1、paged KV、R0/R1、MemoryPlan 与唯一 terminal outcome。
- 熟悉有限自动机、ABNF/EBNF、UTF-8、tokenizer vocabulary、FP32 categorical sampling 和 property-based testing。
- 能读取 `SupportedModelSpec`、`WeightLoadManifest`、tokenizer digest、metric registry 与 release evidence bundle。

### 1.3 预热与进入门槛（Warm-up / Entry Gate）

- 预计用时 30～45 分钟；toy grammar、DFA 与 byte transition 预热全部可在 CPU 环境完成。
- v1.1 outcome 已冻结为 NoCandidate、Adopt 或 No-go；reference config digest、模型/tokenizer revision 与 R0/R1 fixture 可独立校验。
- `SamplingSpec` v1、tokenizer token→byte mapping 和普通 unconstrained decode 具备 golden；无法得到稳定 byte mapping 的 tokenizer 不进入 v1.2 support matrix。
- regex 与 JSON subset 的候选语法已经过威胁建模：无递归引用、无无界 schema expansion、无宿主语言 backtracking 执行。
- compile CPU 时间、DFA state 数、transition bytes、cache bytes 和单请求 workspace 均有预注册硬上限与拒绝错误码。
- 预热练习已完成：用不超过 16 个 byte terminal 的 toy grammar 手画 DFA，并逐 byte 验证一个跨 token UTF-8 样例；结果收录在 entry evidence。

### 1.4 Teach-back 产物

- `release/v1.2.0/teach-back.md`：从一条 grammar source 开始，展示 canonical bytes、DFA、token mask、采样、state transition、EOS 与 terminal outcome。
- 一段不超过 15 分钟的演示：同一 prompt 分别运行 unconstrained、regex 和 JSON subset，打开 Grammar Explorer 定位一次合法转移和一次 dead-end 拒绝。
- 一个 conformance walkthrough：说明 normative ABNF/EBNF 的三条边界样例为何分别是 accept、reject 和 unsupported，而不是依赖实现猜测。

## 3. Scope

### 3.1 本版本新增

- `regex-byte-v1`：anchored full-match、byte alphabet `0x00..0xFF`、有限 alternation/concatenation/group/class/quantifier 子集；具体接受语法以 normative ABNF 为唯一事实源。
- `json-subset-v1`：有限 object/array/string/number/boolean/null、required、有限 enum、界限明确的长度/数值约束；支持项与组合限制以 normative EBNF 和 profile schema 为准。
- grammar source canonicalization、quota-aware compile、deterministic DFA numbering、tokenizer-aware allowed-token calculation与 content-addressed cache。
- `SamplingSpec` v2：确定的 logit processor 顺序、grammar mask、EOS/budget 规则、FP32 计算与 error semantics。
- normal structured decode reference path；可选 optimized allowed-token bitset 只能通过相同 DFA/SamplingSpec contract 接入。
- Grammar Explorer 与 canonical events，可从 request/token 跳到 grammar state、token bytes、allowed/rejected reason 和 terminal。

### 3.2 本版本保持不变

- v1.0/v1.1 的单进程单 worker 单 GPU、模型/weight 支持范围、paged KV、scheduler、prefix、chunk、preemption 与 API terminal contract。
- unconstrained request 默认仍走 `SamplingSpec` v1 兼容语义；只有显式 grammar request 使用 v2 structured profile。
- sync/eager reference 始终存在；v1.1 Adopt fast path 若 capability 不含 structured output，则显式 fallback reference。
- canonical events、R0/R1、隐私级别、lease/fence、MemoryPlan 和 admission 仍是资源与回放事实源。

### 3.3 Feature flags 与 fallback

| 能力 | 默认值 | Reference/fallback | 失败时行为 |
|---|---|---|---|
| `structured_outputs.enabled` | on for supported request | reject grammar option | feature 全局关闭时 admission error |
| `grammar.kind` | request explicit | unconstrained only when absent | unknown kind/keyword fail closed |
| `grammar.compiler` | `reference_dfa` | 无 regex backtracking fallback | quota/compiler error before accepted |
| `grammar.mask_backend` | `reference` | reference token scan | optimized capability miss before RNG/KV side effect fallback |
| `sampling.spec_version` | structured request 固定 2 | unconstrained v1 | grammar + v1 被 schema 拒绝 |

fallback 只能切换 execution/mask 实现，不能删除 grammar、改变 grammar source 或把 invalid structured request 变成 unconstrained success。

## 4. Non-goals

- 不实现 speculative decoding、draft model、accept/reject、residual sampling、bonus token 或 tentative KV transaction；这些只属于 v1.3。
- 不支持任意 PCRE、lookaround、backreference、宿主正则 backtracking、任意 JSON Schema、递归 `$ref`、remote reference 或用户代码 action。
- 不承诺任意 tokenizer；只有能在固定 revision 下提供 deterministic token→bytes 和 special-token policy 的 tokenizer 才受支持。
- 不加入 CFG/PDA、tool calling、多轮 schema negotiation、多 GPU、量化、LoRA、MoE 或多模态。
- 不以 grammar 性能胜出作为发布条件，也不允许为降低 mask 成本而放宽合法 token 集。

## 5. Architecture Delta

### 5.1 相对上一版本的变化

```text
Grammar source + tokenizer digest + quota profile
  → canonicalize → byte-level normative parser → bounded DFA
  → current DFA state + token byte table → AllowedTokenSet
  → SamplingSpec v2 processors → sample one token
  → consume every byte atomically → next DFA state
  → accepting + EOS = success; dead end/incomplete = explicit error
```

### 5.2 新增或修改的模块

| 模块 | 变化 | 责任边界 | 禁止事项 |
|---|---|---|---|
| `grammar/spec` | add | GrammarSpec、profile/version/digest、quota | 不接受实现私有语法 |
| `grammar/parser` | add | 只解析 normative ABNF/EBNF 子集 | 不调用宿主回溯正则执行生成 |
| `grammar/dfa` | add | deterministic state/transition/accepting/dead-end | 不创建无界 state graph |
| `tokenizer/byte_manifest` | add | token ID、bytes、special policy、digest | 不用 decoded text 猜原始 bytes |
| `sampling/v2` | add | processor order、mask、EOS、sample/error | 不让 backend 重排 processor |
| `grammar/cache` | add | content-addressed compiled DFA/allowed sets | 不跨 tokenizer/compiler/quota digest 复用 |
| `web/grammar_explorer` | add | 展示规范、state、bytes、allowed set 与证据 | 不把未记录 rejected reason 推断为事实 |

### 5.3 状态与原子性

authoritative grammar state 只在 token 被正常 decode commit 时推进。一个 token 的 byte sequence 必须从旧 state 完整消费到新 state；中途某 byte 无 transition 时，该 token 不可进入 allowed set，运行期若仍发生则视为 invariant violation 并 fail-stop。cancel/OOM/backend error 不推进 grammar state；输出 token、KV token、grammar state 和 RNG position 在同一 step commit boundary 对齐。

## 6. Contracts

### 6.1 Byte-level normative grammar contract

- alphabet 是单 byte `0x00..0xFF`；规范文件编码为 UTF-8，但 grammar terminal 在 canonicalization 后显式映射到 bytes。
- regex 是 whole-output full match；隐含 `^...$`，用户提供 anchor 若与 profile 冲突则 admission error，不采用 substring/search 语义。
- `regex-byte-v1.abnf` 定义词法、escape、class、alternation 与有界 quantifier；`json-subset-v1.ebnf` 定义实际输出 byte language，profile schema 定义允许的 schema keyword。规范与实现冲突时规范 + conformance corpus 优先，修复实现需要 patch release。
- DFA state 编号由 canonical BFS 和 byte ascending transition 固定；digest 输入包含 canonical grammar bytes、grammar profile、compiler contract version、quota profile 与 tokenizer byte manifest digest。
- token 合法当且仅当它的全部非 special bytes 从当前 state 依次存在 transition；EOS 不是普通 byte token，只在 state accepting 且 request policy 允许结束时合法。

### 6.2 SamplingSpec v2 contract

每 step 先把 target raw logits 转为 FP32，并在 grammar mask 前沿用 SamplingSpec v1 的 raw NaN/±Inf 检查；随后只执行**先前 SamplingSpec 已明确版本化并在 request 中声明**的 pre-mask processor，再把 grammar disallowed token 置为 canonical `-inf`。V1.2 首版没有已版本化的 history、presence/frequency/repetition penalty 或 logit-bias processor，因此这些字段必须在 accepted 前 fail closed，不能因 backend 恰好支持就执行。相同 spec version 内 backend 不得重排，也不得把 processor/mask 产生的 exclusion `-inf` 误判成 raw numerical error。

`sample` 路径的后半段规范固定为：

1. `temperature` 必须有限且 `>0`，对仍有限的 score 做 FP32 除法；
2. `top_k=0` 表示关闭，否则按 score 降序、token ID 升序打破 tie，保留前 `min(top_k, finite_candidate_count)` 个；
3. 令 top-k 后候选为 `K`、FP32 score 为 `s_i`、`m=max(s_i)`；按 token ID 升序求 `w_i=exp_fp32(fp32(s_i-m))`，再以 FP64 顺序和 `Z=sum(fp64(w_i))`。冻结 `p_i=fp32(fp64(w_i)/Z)`，以 FP64 顺序和 `T=sum(fp64(p_i))` 并定义 top-p 输入概率 `r_i=fp64(p_i)/T`；`Z/T` 必须有限且 `>0`；
4. `top_p` 的合法域为 `0<top_p<=1`；`top_p=1.0` 表示关闭并保留整个 `K`。否则按 `(r_i descending, token_id ascending)` 得到排列 `π`，以 FP64 按该顺序累加（最后一个累计值规范化为 `1.0`），取 `j*=min{j>=1 | sum(r_π[1..j]) >= top_p}`，retained set 恰为 `π[1..j*]`；
5. 令 `S=sum(fp64(r_i))`（只遍历 retained set，token ID 升序），并定义 `q_i=r_i/S`；再按 token ID 升序构造半开 CDF，最后一个正概率 token 的累计值规范化为 `1.0`。使用继承的 V1 per-request RNG `[0,1)` draw，选择唯一第一个满足 `u < cumulative_probability` 的 token。

`greedy` 路径在已版本化的 inherited processor（首版为空）+ grammar mask 后直接选择最大有限 processed logit，tie 取最小 token ID，不执行 temperature/top-k/top-p/softmax，也不消耗 RNG。任一路径若 mask/筛选后无有限候选、softmax/归一化非有限或概率和不为正，不消费 sampling draw、不写 KV、不推进 state，并以公开 terminal `FAILED` + `error_reason=GRAMMAR_DEAD_END` 完成唯一 terminal 仲裁。参数越界在 accepted 前以 `INVALID_ARGUMENT` 拒绝。

greedy 在合法 token 中取最大 processed logit，tie 取最小 token ID。sampled path 沿用 v1.0 per-request RNG contract；batch reorder、其他请求和 scheduler step 不改变该请求 draw sequence。成功 token commit 后才推进 RNG position 与 grammar state。EOS/stop 字符串的优先关系由 manifest 固定；stop 不得截断成不被 grammar 接受的成功 bytes。

### 6.3 API/config/manifest contract

`GrammarSpec` 至少包含 `kind`、`profile_version`、canonical source digest、tokenizer byte manifest digest、quota profile、compiler contract version。API 同一请求只能提供一种 grammar。错误 reason 分为 `UNSUPPORTED_GRAMMAR_FEATURE`、`GRAMMAR_QUOTA_EXCEEDED`、`TOKENIZER_BYTE_MAPPING_UNSUPPORTED`、`GRAMMAR_DEAD_END`、`CONSTRAINT_INCOMPLETE` 和 internal invariant error；前三级发生在 accepted 前并返回 rejection，后两级发生在 accepted 后且映射到唯一公开 terminal `FAILED`。公开 terminal enum 始终只有 `FINISHED | CANCELLED | FAILED | DEADLINE_EXCEEDED`；reason code 不能扩充该枚举。

cache key 缺任一 identity 字段都不可复用。compile 采用 bounded worker pool、deadline、per-request/per-process bytes 与 entry count 配额；相同 key 可 single-flight，waiter cancel 不销毁仍被其他 waiter 使用的 compile。

### 6.4 Event/capture/replay contract

新增 `GrammarAccepted`、`GrammarCompiled`、`GrammarCacheHit/Miss`、`AllowedSetComputed`、`GrammarTransitioned`、`GrammarRejected` 与 `GrammarTerminal`。`GrammarTerminal` 同时记录四值 request terminal 与可选 grammar reason，二者不可混用。

默认 `metadata_only` capture 只记录 digest、count、DFA state ID、output byte length、reason 和 terminal，不记录 grammar source、token IDs、output bytes、token→byte 序列或完整 allowed set；`equality_only` 只可增加 capture-local opaque equality ID。两者的 R1 reducer可以重建 grammar control state、length、allowed-set digest 与 terminal，但必须把逐 byte/output 内容标为 `unavailable_by_privacy`，不能从 tokenizer 或 digest 反推。只有显式 opt-in 的 `encrypted_tokens` capture 在密钥分离、权限和保留期均满足时才可携带受保护 bytes；manifest 必须逐项声明字段与最高 capability。字段不足时 fail closed 或降低声明能力，不伪装 structured replay。

## 8. Correctness and Invariants

### 8.1 Golden/differential

- normative parser、DFA walker 与独立 corpus oracle 对每个 accept/reject/unsupported case 一致；corpus 条目有稳定 ID 和预期阶段。
- 每个 supported tokenizer token 在随机 DFA state 比较 reference byte walk 与 optimized allowed bitset；覆盖空 bytes、multi-byte UTF-8、byte fallback、prefix token 与 special token。
- structured reference 与 mask backend 比较 allowed-set digest、processed logits、greedy token、sample distribution、state digest、output bytes 和 terminal。
- JSON success 必须由同 revision 独立 validator 再验证；regex success 必须由 normative DFA full-match，不以宿主 regex 库作为 oracle。

### 8.2 Property/state invariants

- emitted token 的全部 bytes 必须被旧 grammar state 接受；commit 后 state 等于逐 byte reference walk 的终态。
- EOS 只在 accepting state 合法；success output 必须 accepting，dead-end/incomplete 不能标 success。
- compile/DFA/cache/workspace 不超过 MemoryPlan 和 quota；identity digest 改变必 miss。
- cancel/failure 不推进 grammar/RNG/KV authoritative state；accepted request 恰好一个 terminal。
- unconstrained request 不经过 grammar mask，行为与 v1.1 reference digest 一致。
- 本代码库和 v1.2 artifact 不得出现 draft model、acceptance ratio、residual distribution 或 `SpecTxnV1` 实现。

### 8.3 Failure/stress matrix

| 场景 | 注入 | 必须结果 | 禁止结果 |
|---|---|---|---|
| grammar state explosion | 低 state quota + adversarial source | admission quota error、bounded RSS/time | hang/OOM/部分 DFA 入 cache |
| unsupported schema | `$ref`/unsupported keyword | 明确 unsupported path | 忽略 keyword 后生成 |
| tokenizer drift | 改 vocab/normalizer digest | cache miss + request reject/recompile | 复用旧 allowed set |
| no legal token | DFA state 与 vocab gap | dead-end terminal、无 RNG/KV advance | 选择 EOS/unk 绕过约束 |
| cancel during compile | cancel one single-flight waiter | waiter 取消；共享 job/其他 waiter 正确 | use-after-free/泄漏 |
| cancel after sample before commit | fault barrier | token/KV/state/RNG 全不提交 | partial grammar advance |
| corrupted capture | 改 state/digest/event | replay fail closed + first mismatch | 显示伪造 R1 success |

## 9. Visualization Learning Story

### 9.1 本版本必须回答的问题

1. 用户 grammar 被哪个 normative profile 接受，canonical digest 如何得到？
2. 当前 DFA state 为什么允许或拒绝某 token，它的每个 byte 走了哪条 transition？
3. grammar mask 位于 SamplingSpec v2 的哪一步，top-k/top-p 后还剩什么？
4. EOS 为什么此时合法或非法；budget exhaustion 为何是 success 或 incomplete？
5. compile/cache/mask 花了多少时间和内存，数据是 measured、declared 还是 unknown？
6. fast path 为何 fallback reference，fallback 是否发生在 RNG/KV 副作用之前？

### 9.2 视图与证据映射

| 视图 | 事实源 | 交互 | 事实边界 |
|---|---|---|---|
| Grammar Source | GrammarSpec + normative spec digest | source/profile/quota/canonical diff | source 默认 redacted |
| DFA Explorer | compiler manifest + transition table | state、byte、accepting/dead-end | 未 capture bytes 不反推内容 |
| Token Mask | TokenizerByteManifest + allowed-set event | token→bytes walk、allowed/rejected | full set 未记录时只显示 digest/count |

## 10. Performance Hypothesis

### 10.1 本版本性能立场

structured correctness 是 release gate，速度不是。实验只验证 bounded compiler/cache 与 optimized bitset 是否降低参考 token scan 成本；若收益不足，reference backend 仍可发布。不得改变 grammar、tokenizer、allowed set 或 workload 来制造收益。

### 10.2 Experiment card

```yaml
question: optimized allowed-token bitset 是否在固定 grammar/tokenizer workload 上降低每步 mask 成本且保持完整语义？
hypothesis: content-addressed DFA cache plus bitset lookup reduces mask CPU time without changing allowed-set or SamplingSpec v2 output distribution
primary_metric: illm.grammar.mask.server_duration.token_weighted.p99.v1
guardrails: [illm.correctness.grammar_allowed_set.v1, illm.server.ttft.request_weighted.p99.v1, illm.client.e2e.request_weighted.p99.v1, illm.gpu.memory.peak_bytes.v1, illm.request.terminal.failure_rate.accepted_request_weighted.v1]
tuning_suite: benchmark/suites/v1.2-grammar-tuning.yaml with immutable digest
held_out_suite: benchmark/suites/v1.2-grammar-held-out.yaml with immutable digest
budget: max 6 configs, 3 pilot runs, 5 confirmation runs, equal per-config time
success: primary median improves at least 15% with bootstrap CI beyond noise, all allowed-set digests exact and end-to-end guardrails pass
no_go: correctness differs, cache/memory cost exceeds plan, or end-to-end effect is below threshold by timebox
```

报告还必须给 `illm.grammar.compile.server_duration.request_weighted.p99.v1` 的 cold/hit 分层，以及 exact accepted-request failure denominator。duration 全为 server clock；client E2E 只使用 `illm.client.e2e.request_weighted.p99.v1`，不得混用。

## 11. Compatibility and Migration

### 11.1 Compatibility matrix

| Artifact | 读取 v1.1 | v1.2 写入 | Breaking 条件 | 降级/迁移 |
|---|:---:|---|---|---|
| unconstrained API/config | 是 | stable v1 + optional grammar block | 默认行为/terminal 改变 | 删除 grammar block即 v1.1 behavior |
| GrammarSpec | 无 | grammar schema 1 | profile/canonicalization/byte semantics 改变 | 新 profile/version；不原地解释 |
| SamplingSpec | 读取 v1 | structured 写 v2 | processor order/EOS/RNG 改变 | unconstrained 保持 v1；structured fail closed |
| TokenizerByteManifest | v1.1 tokenizer identity | byte manifest 1 | vocab/normalizer/special bytes 改变 | 重新生成并清 cache |
| capture/replay | 读取 v1.1 | compatible grammar events | 必需 state/reason 语义改变 | 老 UI 忽略新事件；新 UI 声明 capability |
| compiled cache | 不复用 | DFA cache schema 1 | 任一 key digest/ABI 改变 | 删除并重编译 |

### 11.2 Rollback

先 stop admission、drain structured requests，再关闭 `structured_outputs.enabled` 或回退 v1.1 binary。进程内 DFA/allowed cache 可直接丢弃；不得把 v1.2 SamplingSpec v2 structured request 在 v1.1 解释为 unconstrained。v1.2 capture 由旧 reader 打开时只展示其可证明的通用事件。release evidence、normative spec 与 conformance corpus始终保留，不因 rollback 覆盖。

## 13. Known Limitations

- 只支持 normative `regex-byte-v1` 与 `json-subset-v1`，不是 PCRE 或完整 JSON Schema。
- byte-level correctness 不等于人类自然语言质量；合法但语义不理想的输出仍需应用层验证。
- 大 vocabulary/DFA 的 allowed-token 计算可能昂贵；reference 可解释性优先于极致速度。
- 只有 support matrix 固定 tokenizer revision；tokenizer 改变会使 DFA allowed cache 全部失效。
- 默认 `metadata_only/equality_only` R0/R1 不包含敏感 grammar/output bytes、token IDs 或 token→byte 序列；逐 byte/output UI 必须显示 `unavailable_by_privacy`。只有 manifest 显式声明的 `encrypted_tokens` opt-in capture 才可在授权解密后显示对应内容。
- v1.2 没有 speculative decoding；任何性能结论都只针对 normal structured decode。

### 13.1 下一版本输入

- v1.3 复用原样冻结的 GrammarSpec、SamplingSpec v2、TokenizerByteManifest、DFA state transition 与 structured conformance corpus。
- speculative proposal 必须在 shadow grammar state 上逐 token 受同一 mask；commit/rollback 后 authoritative grammar state 与 committed output 对齐。
- v1.2 normal structured reference 始终是 v1.3 structured-speculative oracle；不能为 speculation 改写 v1.2 规范。
- draft/target tokenizer 不完全相同、完整 CFG/PDA 和多卡 speculation 继续留在后续版本。
