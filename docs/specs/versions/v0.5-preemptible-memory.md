## 1. 本版本学习目标

### 1.1 必须掌握

- 区分逻辑 committed token history、物理 KV 副本、已发布 output position 与只统计实际 draw 的 `rng_draws_consumed`/counter-address 集。
- 把 victim selection 写成对 immutable snapshot 的纯函数，把 preempt/detach/reclaim 写成验证版本后的事务。
- 解释为何 in-flight reader/writer 只能产生 pending preemption intent，不能立即释放 page。
- 实现 `ACTIVE → PREEMPT_PENDING → PREEMPTED → RECOMPUTING → ACTIVE`，并保证唯一 terminal。
- 用 max preemptions、minimum residency、aging 和 no-eligible reason 防止 thrash/livelock。
- 证明 recompute 不重新采样、不重复发送已发布 token，且旧 `PageHandle` 在 reclaim 后因 epoch 失效。

### 1.2 建议先修

- v0.4 allocator/page table/epoch/lease/fence/Attention ABI与rollback evidence全部通过。
- 理解抢占、checkpoint/recompute、确定性排序、liveness、starvation和两阶段状态转换。
- 能复现 pool exhausted trace，并区分 offered、accepted、deferred、rejected、failed 请求。

### 1.3 进入门槛与预热实验

- 预计用时 30～45 分钟；先用 CPU toy engine 证明 victim 选择、fence 与恢复游标，再运行 GPU fault case。
- 门槛：v0.4 `pool-exhausted` capture只出现defer/reject，无ownership/fence/epoch错误。
- 预热 A：对3个候选手算`recompute_cost_v1`排序，并交换输入迭代顺序，结果必须不变。
- 预热 B：冻结一个未完成writer fence，证明preempt intent只能pending，fence resolve后才detach。
- 预热 C：在CPU toy engine中preempt一次decode request，清空物理KV后由committed history重算，验证output/RNG不变。
- 预热 D：构造所有request都ineligible，系统必须有界defer/reject而非强制victim。

### 1.4 Teach-back 产物

- `release/v0.5.0/teach-back.md`：逐事件解释一次pressure→victim intent→fence wait→detach→epoch reclaim→full-history recompute→resume，并说明哪些状态被保留、哪些被重建。

## 3. Scope

### 3.1 本版本新增

- `PREEMPT_PENDING/PREEMPTED/RECOMPUTING`内部状态及versioned transitions。
- `recompute_cost_v1` pure victim selection、eligibility、deterministic tie-break与DecisionRecord。
- between-step preemption transaction：intent→validate→wait fence→detach→release request ownership→reclaim。
- CPU-side committed history保存；resume执行一次full-history prefill并恢复decode-ready。
- `max_preemptions_per_request`、`min_residency_steps`、aging与连续pressure liveness检查。
- preempt/resume/recompute R0 events和指标。

### 3.2 本版本保持不变

- v0.4 `KVLayoutSpec`、homogeneous `AttentionPlanV1`、PageHandle allocation epoch、allocator transaction、page table和MemoryPlan。
- v0.3 scheduler主优先级、hard admission、terminal/stream/RNG contract。
- prefill仍为full group；resume history必须一次完成，不允许隐藏chunking。
- 所有page只由request独占；无cache owner、跨请求sharing或eviction。

### 3.3 Feature flags 与 fallback

| 能力 | 默认值 | Reference/fallback | 失败时行为 |
|---|---|---|---|
| `preemption.mode` | gate后`recompute` | `disabled` | 无eligible victim则defer/reject |
| `preemption.victim_policy` | `recompute_cost_v1` | 无 | unknown version启动失败 |
| `max_preemptions_per_request` | 2 | 0等价disabled eligibility | 达cap后ineligible |
| `min_residency_steps` | 2 | 0仅测试 | 未达阈值ineligible |
| `telemetry.profile` | metrics | engine/request/off | 关键事务drop使capture incomplete |

## 4. Non-goals

- chunked/mixed prefill；超过单次full-prefill上限的history不得靠隐式chunk恢复。
- prefix index、cache eviction、跨request KV sharing或cache-only page。
- host swap、copy preemption、partial-layer KV checkpoint或speculative rollback。
- 更改paged layout、Attention ABI或实现fast kernel。
- deadline/SLO optimizer、adaptive victim ML policy、cross-worker preemption。
- R1 replay、高级UI、compile/graph/overlap。

## 5. Architecture Delta

### 5.1 相对上一版本的变化

```text
v0.4 pressure → defer/reject
v0.5 pressure → policy(snapshot).select_victim() [pure]
              → PREEMPT_PENDING (if in-flight)
              → validate lease/fence/table versions
              → detach request page table
              → pending_free → epoch++ → FREE
              → PREEMPTED
              → full-history recompute into new pages
              → ACTIVE decode; output/RNG commit position unchanged
```

### 5.2 新增或修改的模块

| 模块 | 变化 | 责任边界 | 禁止事项 |
|---|---|---|---|
| `scheduler.preemption` | add | pure eligibility/victim intent/DecisionRecord | mutation allocator或等待fence |
| `domain.request_state` | change | versionedpreemption transitions | 发布重复terminal |
| `engine` | change | validate intent、detach、resume编排 | 在in-flight时强制释放 |
| `kv_cache` | change | release request owner、fence后reclaim | 选择victim或改变epoch语义 |
| `executor` | change | full-history recompute ticket | 重新采样/发布历史token |
| `observability` | change | preempt/reclaim/resume事实 | 用估计reclaimed替代实际值 |

### 5.3 数据流与状态迁移

```text
snapshot{request states, page tables, leases, fences, free pages}
→ select_victim(snapshot, required_pages)             # pure
→ SchedulePlan{PreemptionIntent(expected versions)}
→ engine validate
   ├─ stale: rollback/replan
   ├─ in-flight: PREEMPT_PENDING until ticket resolves
   └─ safe: detach owner → PREEMPTED
→ page release waits last-use fence → allocation_epoch++ → free
→ admit blocked work
→ reserve fresh pages for victim history
→ one full-history prefill ticket over prompt + all committed output tokens
→ success: atomically publish rebuilt KV + base_next_logits + ResumeCursor
→ RECOMPUTING→ACTIVE; sampler consumes base logits for next output
→ failure/cancel: explicit unique terminal, pages safely released
```

Preemption不回滚 `committed_output_tokens`、stream sequence、terminal arbitration或 RNG draw state。recompute query 不调用 sampler，但必须保存 full-history prefill 得到的 canonical `base_next_logits`；只写 KV 而丢弃 logits 会让下一步重复消费最后 token。

`ResumeCursorV1` 固定记录 `logical_history_token_count=prompt_tokens+committed_output_tokens`、`kv_valid_token_count`、`next_output_position=committed_output_count`、`pending_input_token=none`、base-logits digest 与 request generation。recompute 成功时 KV、cursor 与 base logits 同一 commit 发布；随后从 base logits 产生下一个输出，再按 V0.2 一步 KV/output lag 把该新 token 标为 pending-input。不得既把最后 committed token 写入 rebuilt KV 又在下一 decode model call 重复输入。

## 6. Contracts

### 6.1 API/CLI contract

- preemption对客户端透明，不关闭stream；可选metadata报告`preemption_count/recomputed_prompt_tokens`。
- 同arrival/seed下preemption on/off的accepted request最终token、terminal、actual seed、RNG与transcript相同。
- 无eligible victim时DecisionRecord为`DEFERRED_KV_CAPACITY/NO_ELIGIBLE_VICTIM`；不把它伪装OOM。
- `committed_history_tokens > max_prefill_tokens_per_step`的request在本版ineligible；不得隐藏拆分。
- worker无法归属async error、ownership corruption或epoch mismatch时fail-stop并为accepted request产生明确terminal。

### 6.2 Config/manifest contract

| 字段/对象 | V0成熟度 | 兼容规则 |
|---|---|---|
| `PreemptionPolicyV1` | `candidate` | pure input/output，unknown version fail closed |
| `PreemptionIntentV1` | `format_frozen_for_v0` | 带snapshot/table/request version、victim key和required pages |
| `max_preemptions_per_request` | `candidate` | 非负、run内冻结并进入manifest |
| `min_residency_steps` | `candidate` | 非负；从成功resume/首次active step计数 |
| `PageHandleV1` | `format_frozen_for_v0` | 继承 v0.4；reclaim仍按 epoch 规则，preemption不得旁路 |

eligible必须同时满足：ACTIVE、非terminal、无不可取消副作用、preemption_count未达cap、residency达阈值、history可在一次full-prefill完成。`recompute_cost_v1`按`(committed_history_tokens, -reclaimable_pages, preemption_count, -admission_seq_no, request_id)`升序；任一变更需新policy version和test vectors。

### 6.3 Event/capture/replay contract

- 新增`scheduler.preemption_considered/request_preempt_pending/request_preempted/request_resume_started/request_resumed`。
- considered保存policy version、每候选eligibility/reason/key、required/estimated reclaim；preempted保存实际detach/reclaimed pages。
- resume保存history length、fresh PageHandles摘要、recomputed tokens，以及 pre/post `next_output_position`、`rng_draws_consumed` 与 counter-address digest。
- page release继续使用v0.4事件并携allocation epoch；R0可串起因果但不宣称R1。
- 任一preemption transition/page release关键事件drop，capture标incomplete；不能从最终状态补造victim故事。

### 6.4 资源、并发与失败 contract

- victim只在scheduler step边界选择；stale snapshot/intents完整rollback并replan。
- unresolved reader/writer lease存在时只能`PREEMPT_PENDING`；最后fence resolve后才能detach/reclaim。
- detach原子移除request page table ownership；页面按v0.4 pending_free/epoch规则回收。
- resume前request不参加decode；recompute success后一次性发布new valid history，不发布output。
- resume commit 必须同时发布 matching generation 的 `ResumeCursorV1` 与 base-next-logits；下一 token 从该 logits 采样且沿用原 absolute output position/RNG address。
- 每request抢占次数有界，resume后保证minimum residency；相同主优先级仍由FCFS+aging决定。
- finite accepted且配置允许完成的trace必须forward progress；不可完成时显式defer/reject/fail，而非livelock。

## 8. Correctness and Invariants

### 8.1 Golden/differential

- preemption disabled/enabled使用同arrival/seed；逐request比较最终token、terminal、RNG与transcript。
- recompute 逐层 KV validity 与最终 base-next-logits 对齐 full-context reference；`ResumeCursorV1` 的 valid count/next position 一致，recomputed work 不产生第二份 output。
- victim candidates输入顺序/random hash seed改变，selected victim和DecisionRecord相同。
- pressure消失时preemption path与v0.4 paged结果一致且事件计数为0。

### 8.2 Property/state invariants

- 每个request任一时刻恰处一个状态；terminal吸收且仅一次。
- PREEMPTED request无request-owned pages或unresolved leases；PENDING request可有pages但绝不free。
- pre/post preemption 的 `next_output_position`、`rng_draws_consumed` 与 committed counter-address 集不回退，也不因 recompute 增加；greedy draw count 继续为 0。
- actual reclaimed page count等于detach后最终进入FREE的handles；epoch均递增。
- per-request count≤cap，resume后residency≥阈值（除terminal/fatal error）。
- finite admissible trace无livelock/starvation；waiting age有界或产生显式overload outcome。

### 8.3 Failure/stress matrix

| 场景 | 注入 | 必须结果 | 禁止结果 |
|---|---|---|---|
| in-flight victim | 延迟writer fence | pending后resolve再detach | 立即free |
| stale intent | match后page table变更 | rollback/replan | detach新owner |
| no eligible | 全部超cap/驻留/history过长 | defer/reject reason | 强制victim |
| recompute failure | ticket error | uniquefailed terminal+safe release | 半valid history |
| cancel pending | cancel与fence race | cancel赢terminal，fence后release | resume/cancel双terminal |
| rapid pressure | 小pool churn | cap/residency/progress满足 | livelock/thrash无界 |
| old handle access | reclaim后延迟callback | epoch拒绝 | 写入reallocated page |
| policy unknown | 修改manifest version | engine启动失败 | 随机fallback policy |

| Artifact | 读取v0.4 | 写入格式 | Breaking条件 | 迁移/降级 |

| persisted cache | 不存在 | 不新增 | 任意持久化KV | 禁止迁移 |

### 11.2 Rollback

- 同binary回滚：停止新victim选择；PREEMPT_PENDING intent撤销或等待fence后不detach；RECOMPUTING request完成/明确失败后drain。
- 回v0.4 binary：停止admission、drain所有状态、等待fence、验证pages守恒，销毁pool后重启。
- 不序列化/迁移PREEMPTED state或KV；客户端按terminal/retry policy处理。
- rollback bundle保存状态机快照、pending intents/fences、victim records、recompute/output/RNG摘要。

## 13. Known Limitations

- 只支持释放并full-history重算，不swap/copy；长history成本高。
- history超过单次prefill上限时不可抢占；v0.6才解决chunked resume。
- 只有一个固定victim policy，无deadline/SLO optimizer。
- 无prefix sharing；preemption释放的是request ownership，不是cache eviction。
- R0事件不能重建完整control state。
- 单GPU同步reference path，无fast kernel/overlap/graph。

### 13.1 下一版本输入

- 超长history ineligible、resume阻塞decode和ITL数据成为v0.6 chunked prefill输入。
- v0.5 preemption state、victim/liveness、lease/fence/epoch必须由v0.6保持。
- v0.6可用chunk重建history，但不得同时引入prefix ownership。
