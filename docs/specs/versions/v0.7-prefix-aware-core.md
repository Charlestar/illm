## 1. 本版本学习目标

### 1.1 必须掌握

- 解释radix index是逻辑查找结构、paged KV是物理存储，两者通过epoch handles与lease解耦。
- 设计包含model/weights/layout/tokenizer/template/position/adapter/namespace/token IDs的exact prefix key。
- 分别理解`request_lease_count`、`inflight_reader_writer_count`、`cache_indexed`和`cache_owner`，拒绝含混的单一refcount。
- 实现pure `match/select_evictions`与version-checked `acquire/insert/evict/release`事务。
- 证明eviction的线性化顺序为：验证index version→从index删除→清cache owner→epoch递增并回FREE。
- 处理“整prompt全命中仍需至少一个query token生成next-token logits”的边界。
- 用端到端指标评估saved prefill与lookup/lease/驻留/eviction成本，不把hit ratio当性能结论。

### 1.2 建议先修

- v0.6 full/chunked、mixed ABI、preemption resume、budget/fairness与rollback evidence全部通过。
- 理解radix tree、exact equality/hash collision、RCU/version validation、lease、LRU与线性化点。
- 能解释v0.4 allocation epoch与v0.5 fence-safe reclaim，且不会把cache eviction等同request preemption。

### 1.3 进入门槛与预热实验

- 预计用时 30～45 分钟；使用 CPU radix/index simulator，不要求真实模型权重。
- 门槛：`prefix_index=absent`的v0.6 baseline在重复prefix workload中可复现，locally-computed prompt tokens可准确计数。
- 预热 A：手算长度`1/page_size-1/page_size/page_size+1`的matched/reused/forced-recompute tokens。
- 预热 B：构造同token但不同namespace/model/layout/tokenizer的keys，所有cross-identity命中必须为0。
- 预热 C：模拟acquire与evict并发：acquire先增lease则evict失败；evict先删index则acquire因stale version失败。
- 预热 D：用纸面状态机执行“锁定并验证 version、request/inflight=0、fence complete→删index→清cache owner→epoch++→FREE”，确认cache owner不作为阻止自身驱逐的引用。

### 1.4 Teach-back 产物

- `release/v0.7.0/teach-back.md`：追踪一次exact match/acquire/reuse/release以及一次并发eviction，逐步列出四类ownership字段、index version和PageHandle epoch。

## 3. Scope

### 3.1 本版本新增

- `PrefixIndex` protocol及`NoPrefixIndex`/compressed radix实现；不实现HashBlockIndex。
- `PrefixKeyV1` exact canonical identity和default tenant isolation。
- 只复用完整committed page extents；partial tail重算，extent保存epoch PageHandles。
- physical extent metadata：`request_lease_count`、`inflight_reader_writer_count`、`cache_indexed`、`cache_owner`。
- match/acquire/insert/release与version-checked LRU leaf eviction事务。
- full-hit forced recompute语义、prefix-aware secondary tie-break（不越过FCFS+aging）。
- prefix/ownership/eviction R0 events与registered metrics。

### 3.2 本版本保持不变

- v0.6 `AttentionPlanV2`、fixed chunk size、decode reservation、cursor/budget与mixed backend。
- v0.5 preemption victim/liveness/state；request preemption与cache eviction仍是不同事件/原因。
- v0.4 KVLayout/PageHandle epoch/allocator/page table/lease/fence/MemoryPlan。
- public generation/stream/RNG/terminal contract和所有feature-off oracle。

### 3.3 Feature flags 与 fallback

| 能力 | 默认值 | Reference/fallback | 失败时行为 |
|---|---|---|---|
| `prefix_index.mode` | gate后`radix` | `none` | corruption副作用前disable/fail-stop，绝不近似hit |
| `prefix_cache.eviction` | `lru_leaf_v1` | `none`（满则miss/defer） | 无eligible extent则不碰active lease |
| `scheduler.prefix_tiebreak` | `on` | off | 只在主优先级等价时生效 |
| `prefix_cache.namespace` | tenant-scoped | engine-local default | isolation-required且缺失则INVALID_ARGUMENT |
| `telemetry.profile` | metrics | engine/request/off | 关键cache事务drop使capture incomplete |

## 4. Non-goals

- 改变chunk size、decode reservation、mixed AttentionPlan或preemption policy。
- partial-page sharing、semantic/approximate matching、HashBlockIndex或跨tenant默认sharing。
- 缓存next-token logits/hidden states/prompt logprobs。
- host/disk persistent cache、跨worker/global cache或cache warm migration。
- 用generic `refcount/cache_refcount`替代四字段ownership，或让cache owner阻止自己的eviction。
- R1 reducer/Web UI、R2/R3、fast kernel/compile/graph/overlap、多GPU。

## 5. Architecture Delta

### 5.1 相对上一版本的变化

```text
v0.6: request pages → request-exclusive → terminal/preempt release
v0.7: PrefixKey → pure Radix.match(snapshot)
              → acquire request lease at expected index version
              → reuse full valid page extents in unchanged AttentionPlanV2
successful full extents → cache owner + radix index publication
pressure → pure LRU candidate → version-checked linearized eviction
```

### 5.2 新增或修改的模块

| 模块 | 变化 | 责任边界 | 禁止事项 |
|---|---|---|---|
| `prefix_cache.protocol` | add | pure match/select + transactional mutation | 访问tensor或改scheduler主优先级 |
| `prefix_cache.none` | add | 永远miss reference | 隐式global cache |
| `prefix_cache.radix` | add | exact spans/extents/index version/LRU | partial/approximate match |
| `kv_cache.ownership` | change | 四字段ownership、lease/fence、epoch release | generic refcount推导语义 |
| `scheduler` | change | lookup fact/secondary tiebreak/eviction intents | mutation index/allocator |
| `engine` | change | validate/acquire/insert/evict transaction | 半发布index或半清owner |
| `observability` | change | ownership/linearization事实 | 输出raw token IDs |

### 5.3 数据流与状态迁移

```text
freeze Engine/KV/Prefix snapshots
→ PrefixIndex.match(PrefixKeyV1, snapshot)                  # pure
→ scheduler builds unchanged mixed plan + optional eviction intents
→ validate request/page/index versions
→ acquire:
   atomically verify cache_indexed/cache_owner/epoch/index_version
   then add RequestLeaseId and request_lease_count++
→ execute; each ticket increments/decrements inflight_reader_writer_count
→ release request lease at terminal/preempt after last relevant fence

insert full valid extent:
  install cache_owner (rollback-capable)
  → under one index mutation lock, publish radix entry and set
    cache_indexed=true at expected index version [visibility linearization]
  → producer continues via request lease

evict selected LRU leaf:
  1. validate expected index version, leaf identity, request_lease_count==0,
     inflight_reader_writer_count==0, cache_indexed=true and cache_owner matches
  2. remove extent from index and increment index version [eviction linearization]
  3. set cache_indexed=false, then clear cache_owner
  4. if lease/inflight remain zero, allocator release→pending_free→fence satisfied
     → allocation_epoch++→FREE
```

Cache owner是保持extent驻留的所有权，不是阻止自身驱逐的计数。eviction eligibility只被request leases、in-flight readers/writers、非leaf/pending mutation等外部安全条件阻止；步骤2后新acquire必须因index version/entry缺失失败。

## 6. Contracts

### 6.1 API/CLI contract

- public generation/stream/errors与v0.6兼容；metadata增加`matched_prefix_tokens/reused_prefix_tokens/forced_recompute_tokens/locally_computed_prompt_tokens`。
- `0<=reused<=matched<=prompt_len`，`locally_computed=prompt_len-reused`；生成请求`reused<=max(0,prompt_len-1)`。
- mode/namespace/salt在accepted前冻结；默认跨tenant命中关闭。
- cache miss/eligible不足不是客户端错误；key不完整、digest mismatch、index corruption必须NoPrefix fail closed或worker fail-stop。
- prompt logprobs不支持reuse时强制`reused=0`或UNSUPPORTED，不能返回伪值。
- preemption resume可重新exact match/acquire并chunk剩余history，但不重新采样/发送output。

### 6.2 Config/manifest contract

| 字段/对象 | V0成熟度 | 兼容规则 |
|---|---|---|
| `CachePoolIdentityV1` | `format_frozen_for_v0` | build/model/weights/dtype/layout/RoPE/backend numerical contract/adapter 任一变化必须冷建 pool |
| `PrefixKeyV1` | `format_frozen_for_v0` | 任一identity组件缺失/变化不得hit |
| `PrefixIndexVersion` | `candidate` | match/select pure；mutation携expected version |
| `CacheOwnershipV1` | `format_frozen_for_v0` | 四字段分别序列化/校验，禁止generic refcount |
| `prefix_cache.max_pages` | `candidate` | 属于MemoryPlan usable KV，不占workspace/headroom |
| `lru_leaf_v1` | `candidate` | 只选request_lease=0、inflight=0、indexed+owner匹配的leaf |
| `prefix_tiebreak_v1` | `candidate` | 仅主优先级相等时按estimated saved tokens+request ID |

`CachePoolIdentityV1 = software/model numerical contract digest + spec_id + weights/load-manifest digest + runtime dtype + kv_layout_id + position/RoPE config + attention-backend numerical contract + adapter identity（none 也显式）`。

`PrefixKeyV1 = CachePoolIdentityV1.digest + tokenizer_revision + chat/input_template_digest + tenant/cache namespace/salt + exact token IDs`。SamplingSpec/RNG 不属于 KV identity：同一 exact token prefix 的 K/V 不因这些 token 当初如何被采样而改变。

### 6.3 Event/capture/replay contract

- 新增`kv.prefix_lookup/request_lease_acquired/request_lease_released/inflight_access_started/inflight_access_finished/prefix_inserted/index_entry_removed/cache_owner_cleared/page_evicted`。
- lookup记录matched/reused/forced/local、key/index version、opaque namespace、duration与extent IDs；默认不记录raw token IDs。
- 每个ownership event都保存before/after四字段、extent epoch handles、expected/actual index version和transaction ID。
- eviction DecisionRecord保存candidate leaf/LRU、lease/inflight eligibility；四个线性化阶段分别记录，`page_evicted`只在epoch递增后发出。
- `kv.snapshot`显式保存四字段，不提供`refcount`别名，避免reader误解cache owner。
- 最高仍R0；缺少任一critical ownership event则capture incomplete，v0.8不能凭snapshot补造事务。

### 6.4 资源、并发与失败 contract

- match只返回exact token prefix的完整valid page extents；PageHandle epoch/layout/key identity全部匹配。
- 生成至少执行1 query token：`reused=floor(max(0,prompt_len-1)/page_size)*page_size`；整页全命中时重算最后完整page。
- acquire与evict在相同index version串行化：acquire先成功则lease count阻止evict；evict先删entry则acquire stale失败。
- `request_lease_count`等于live RequestLeaseId集合大小；只有显式request acquire/release改变。
- `inflight_reader_writer_count`等于未resolve tickets对extent的访问数；最后fence resolve才递减。
- `cache_indexed`表示当前index可查；`cache_owner`表示cache retention ownership。二者在稳态同真，在insert/evict事务中按规定短暂过渡。
- request lease/in-flight非零时不得清cache owner或回收；cache owner本身不使selected eviction ineligible。
- eviction步骤2后禁止rollback为可见entry；后续失败进入finish-or-fail-stop recovery，必须清owner或保持quarantined，绝不复活旧index version。
- allocator+cache+request总页数守恒；epoch handle在最终FREE时递增。

## 8. Correctness and Invariants

### 8.1 Golden/differential

- prefix none/radix、cold/warm、preemption off/on最终logits/token/terminal/RNG/transcript一致。
- exact hit覆盖length 1、page_size±1、多页全命中、last page不同、同长度不同token及cross-identity negative。
- full-hit验证query_len≥1且next-token logits与NoPrefix一致。
- eviction前后已完成/active request输出不变；重新请求被驱逐prefix按miss重算并一致。

### 8.2 Property/state invariants

- radix path exact且无跨namespace/digest命中；stale mutation完整rollback或finish-or-fail-stop。
- request lease集合大小=计数；unresolved access tickets= in-flight计数；不使用generic refcount。
- indexed entry必指向matching cache owner和current epoch handles；稳态二者一致。
- acquire/evict竞争只有一个线性化赢家，无新lease落在已删除entry。
- eviction严格按验证→index删除→owner清除→epoch++/FREE；cache owner不阻止其自身清除。
- active request/in-flight访问的page永不evict/reuse；无dangling extent/orphan owner。
- prefix tiebreak不越过FCFS+aging，finite admissible load forward progress。

### 8.3 Failure/stress matrix

| 场景 | 注入 | 必须结果 | 禁止结果 |
|---|---|---|---|
| stale match | match后index变更 | acquire失败/replan | 使用dangling extent |
| acquire wins | lease增后evict | evictrevalidation失败 | active page清owner |
| eviction wins | 删除entry后acquire | acquirestale失败 | 新lease获得 |
| owner-clear failure | index已删后注入error | finish/fail-stop+quarantine | 旧entry复活 |
| writer failure | insert前fence error | 不install/publish | invalidpage indexed |
| active in-flight | 延迟reader fence | in-flight阻止evict | epoch递增 |
| namespace collision | 同token不同namespace | hit=0 | data sharing |
| full-hit boundary | 整页prompt | last fullpage重算 | query_len=0/reuse logits |
| churn+preempt | small pool/races | counts/epoch/progress守恒 | leak/double release/livelock |

至少1,000条insert/match/acquire/access/release/select/evict序列；所有失败seed固化。

## 11. Compatibility and Migration

### 11.1 Compatibility matrix

| Artifact | 读取v0.6 | 写入格式 | Breaking条件 | 迁移/降级 |
|---|:---:|---|---|---|
| config | 是 | additiveprefix/cache fields | key/namespace语义不全 | 默认none |
| API/CLI | 是 | facade不变，prefixmetadata可选 | token/terminal改变 | none回v0.6 |
| event/capture | R0是 | ownership/staged eviction events | generic refcount reader | 旧capture不伪造四字段 |
| manifest | 是 |绑定PrefixKey dependency digests | 任一identity变化 | cold empty index |
| runtime cache | 不读取旧 | 仅进程内 | binary/layout/key变化 | drain/destroy |

### 11.2 Rollback

- 新request切`prefix_index=none`；停止insert/acquire，等待所有request leases和in-flight counts归零。
- 逐extent执行与eviction相同的drain：验证version→删index→清cache owner→fence后epoch++/FREE。
- active lease存在时不可直接清index后强制free；先drain/cancel request并等待fence。
- 回v0.6 binary前cache drain audit必须为：index entries 0、cache owners 0、leases 0、inflight 0；pool随后销毁重建。
- rollback bundle保存四字段终态、index versions、PageHandle epochs和每次drain transaction。

## 13. Known Limitations

- 只共享完整page；partial tail重算，整页全命中时重算最后完整page。
- 只有NoPrefix/Radix，无HashBlock/semantic/persistent cache。
- cache/index只在单进程内，重启冷cache。
- prefix tiebreak为固定secondary policy，不做SLO auto-tuning。
- capture最高R0；尚无canonical checkpoint/delta。
- mixed attention仍reference，单GPU同步core无fast path。
