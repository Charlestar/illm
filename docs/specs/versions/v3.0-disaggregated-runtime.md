> V3.0 把一个 unified replica 拆成 Prefill Service、KV Transfer Engine 与 Decode Service，并用显式资源/所有权事务连接三段。基础边界是同机、同模型 revision、同 dtype/KV layout、已资格化 TP topology 的 P/D；unified/TP/DP 路径始终保留。

## 1. 本版本学习目标

### 1.1 必须掌握

- 能解释 prefill 与 decode 的 compute/memory/batch/SLO 差异，以及 P/D 分离可能得到的隔离收益和 transfer/重复权重/预留成本。
- 能实现唯一 accepted point：router 必须在一个原子 admission bundle 中同时获得 `AdmissionLease` 与 `FutureDecodeCredit`，任何 check-then-accepted 都不合法。
- 能把 future credit 在 prefill 完成后原子转换为具体 destination KV pages，再执行 reserve-before-send transfer；不能先发数据后找容量。
- 能定义 `KVTransferManifest` 与 ticket 状态机，处理 source/destination ownership、generation、fence、幂等 cancel、一次 retry 和 orphan cleanup。
- 能跨服务传递 `DeadlineBudgetV1`：保留 authority-monotonic absolute deadline、有效 calibration identity/error bound 与保守 carried remaining；每跳取 absolute-derived remaining 和逐 hop deduction 的较小值，retry 沿用同一 lineage 且不重置 deadline/budget。
- 能用 entity mutation sequence、causal parent、snapshot barrier 与 R1 state replay 重建 request/admission/prefill/transfer/decode/terminal 全链路。
- 能做等总 GPU、同 workload 的 unified vs P/D 实验，并把功能资格与性能稳定性明确分开。

### 1.2 建议先修

- 完成 V2.1，理解 TP leader commit、DP router、原子 `AdmissionLease`、replica generation、capacity/health、R1 snapshot barrier 与 equal-budget benchmark。
- 熟悉事务状态机、幂等 key、lease/fence、CUDA P2P/IPC、bounded retry、backpressure、deadline propagation 和异步 copy。
- 能解释 TTFT、ITL、E2E、request/output-token goodput 的 registry 定义、分母和 client/server 测量边界。

## 3. Scope

### 3.1 本版本新增

- 同机独立 Prefill、Decode、Transfer 角色；每个角色可使用 V2.0 已 qualification 的 TP group，并由 V2.1 registry/health 管理。
- 原子 `AdmissionBundle = AdmissionLease + FutureDecodeCredit`；一次权威 mutation 同时保留 prefill/request capacity 与 future decode capacity并写唯一 accepted point。
- `FutureDecodeCredit` 在 prefill 完成后按实际 token/layer/page requirement 原子转换为 destination page leases；短缺时整体转换失败，不部分 publish。
- `KVTransferManifest` handshake、reserve-before-send、async copy、fence、length/coverage/digest 校验、原子 page-table publish 和幂等 ticket journal。
- credit-based backpressure、有界队列、wire `DeadlineBudgetV1`（authority-monotonic absolute deadline + calibration + conservative carried remaining）、逐 hop conservative deduction、`max_retries=1`、generation fencing 与 orphan reaper。
- P/D route/prefill/credit/transfer/decode events、mutation sequence、causal links、跨服务 barrier、R1 state reducer 与 Flow Inspector。
- unified 与 P/D 的 exact-token/capacity/fault/cost/equal-budget performance 比较和分级发布。

### 3.2 本版本保持不变

- V2.0 tensor/RankManifest/CollectivePlan/leader full-logits/all-rank commit 与 V2.1 replica health/DecisionRecord/unique terminal semantics。
- generation API、SamplingSpec、stream/error/terminal、Paged KV/prefix namespace、MemoryPlan 与 privacy 默认。
- unified/TP/DP 是完整 reference/fallback；P/D 不得删除、绕过或降级它们。
- 每个 accepted request 只有一个 terminal；已输出 token 的请求不跨 Decode generation 透明重试。

### 3.3 Feature flags 与 fallback

| 能力 | 默认值 | Reference/fallback | 失败时行为 |
|---|---|---|---|
| `pd.enabled` | `false` | V2.1 unified/TP/DP | 关闭时不创建 transfer path |
| `pd.transfer_backend` | `local_p2p` | `local_staged_copy`; mock仅CI | capability失败 readiness false，不在线静默换 backend |
| `pd.admission_bundle` | `atomic_v1` | 无 check-then-accept 模式 | 任一 lease/credit失败整体拒绝并回滚 |
| `pd.max_retries` | `1` | `0` | 超过1启动失败；retry继承原 budget/idempotency |
| `pd.manifest_validation` | `strict` | 无宽松模式 | identity/layout不匹配在发送前 fail closed |
| `pd.cross_node` | `false` | same-host | 基础版配置 true 启动失败 |
| `v1.3-merged` integration | `false` | V2 base sampling | 条件 profile；不构成硬依赖 |

P/D 只有满足 §10 success 和所有正确性/故障门才在 support matrix 标 `stable`；performance no-go 仍可发布 research/functionally-qualified `v3.0.0`，但 P/D 必须 `experimental/default off`。V3.1 可以稳定 unified 路径，不因 P/D no-go 被阻塞。

## 4. Non-goals

- 跨节点/RDMA/NIXL/Mooncake 基础承诺、异构 TP/layout reshard、KV dtype/压缩转换或持久化 KV。
- 自动扩缩、Kubernetes operator、全局平台、计费、多区域容灾或 exactly-once 网络交付。
- accepted 后任意 Decode 迁移、已输出 stream 的透明 retry、`max_retries>1`。
- MoE/pipeline/expert parallel、量化、多模态、LoRA 或新模型架构。
- 以 performance success 取代 transfer correctness/admission/fault gates；以版本号自动把 P/D 标 stable。
- V3.1 的长期 soak、rolling upgrade、自动 replacement、LTS/security 运维资格。

## 5. Architecture Delta

### 5.1 相对上一版本的变化

```text
V2.1: Router → chosen unified replica (prefill + decode + one KV pool)

V3.0: Router/Atomic Admission Authority
          └─ acquire together: AdmissionLease + FutureDecodeCredit
                         ↓ unique ACCEPTED
                  Prefill Service
                         ↓ actual KV shape known
       FutureDecodeCredit ─atomic convert→ DestinationPageLeases
                         ↓ reserve-before-send
                  Transfer Engine → validate/fence/atomic publish
                         ↓
                   Decode Service → stream/terminal

Fallback: Router → V2.1 unified/TP/DP path
```

### 5.2 新增或修改的模块

| 模块 | 变化 | 责任边界 | 禁止事项 |
|---|---|---|---|
| `pd/admission_authority` | add | 原子 acquire/release admission+future credit、唯一 accepted mutation | check 两边后再 accepted |
| `pd/prefill_service` | add | prefill、source KV write commit、handoff manifest | 未有 bundle 接单或提前释放 source |
| `pd/decode_credit_manager` | add | future credit、actual pages conversion、hard capacity | 以 OOM/host queue 做流控 |
| `pd/transfer_engine` | add | manifest、copy/fence/check、ticket journal | 决定 routing/sampling 或读取未授权页 |
| `pd/decode_service` | add | 原子 publish、decode schedule/stream | 读取 PREPARED/TRANSFERRING pages |
| `pd/protocol` | add | capability/generation/idempotency/DecodeCursor/DeadlineBudget lineage | wall-clock deadline、忽略 transit 或 retry 重置预算 |
| `pd/orphan_reaper` | add | generation-fenced ticket/lease/fence cleanup | fence未resolve提前复用 |
| `observability/pd` | change | admission/request/ticket/credit causality与barrier | 用当前状态推测历史 |

### 5.3 数据流与状态迁移

```text
ATTEMPTED
  → AdmissionBundle.acquire(prefill reservation, future decode credit, deadline_budget: DeadlineBudgetV1)
      ├─ atomic success → ACCEPTED
      └─ any failure → REJECTED (both resources unchanged/released)
  → PREFILL_RUNNING → PREFILL_COMPLETE(prompt KV + base_next_logits + DecodeCursor)
  → credit.convert(actual page requirements) → DESTINATION_RESERVED
  → TRANSFERRING → TRANSFER_COMMITTED/DECODE_READY(cursor validated)
  → SAMPLE_FIRST_FROM_BASE_LOGITS → pending-input token
  → DECODING → FINISHED | CANCELLED | FAILED | DEADLINE_EXCEEDED

TransferTicket: CREATED → PREPARED → TRANSFERRING → COMMITTED
                         └────────────→ CANCELLED | FAILED
```

1. candidate snapshots 只排序；admission authority 原子校验 generation/health/budget/capacity，同时创建 `AdmissionLease`、`FutureDecodeCredit` 与 accepted mutation。不存在“检查 decode credit，稍后 accepted”。
2. future credit 保守覆盖可接受请求的 decode page/token upper bound 和有效期；prefill 完成后根据 actual manifest 原子转换为完整 destination page leases，剩余 credit释放。
3. prefill 只 materialize prompt KV，并生成 canonical FP32 raw `base_next_logits`；handoff 的 `DecodeCursorV1` 固定 `committed_output_count=0`、`kv_valid_token_count=prompt_token_count`、`next_output_position=0`、`pending_input_token=none` 以及 SamplingSpec/RNG/grammar/model identity。V3.0 固定由 Decode sampling leader 在 DECODE_READY 后从 base logits 采首 token；Prefill 不提前采样或 stream。
4. conversion 成功且 manifest/capability精确匹配后才允许 source send；payload 同时覆盖 prompt KV、base logits 与 DecodeCursor digest。部分 page allocation 必须回滚，目标页在 COMMITTED 前不可读。
5. transfer launch 后 source read lease、destination/staging lease 持有到 fence resolve；length/coverage/digest通过后原子 publish page table、base logits 与 cursor。Decode 采出的首 token 在下一 model step 前是 pending-input；EOS/length terminal 时可以永不进入 KV。不得重复消费最后 prompt token或把新输出谎称为已 materialized KV。
6. duplicate prepare/commit以 `(request_id,transfer_id,destination_generation,payload_digest)` 幂等；COMMITTED ack丢失返回既有结果，不重复写页。
7. ingress 创建 `DeadlineBudgetV1{authority_id, absolute_deadline_monotonic_ns, lineage_id, seq}`。每个 service 持有有有效期和误差上限的 authority↔local monotonic calibration，并在接收时以保守的 authority-now 上界计算真实 remaining；wire `remaining_budget_ns` 只能取该值与父预算扣除本地 elapsed 后的较小者。这样 queue、IPC/network transit、copy 与 retry 全部消耗同一入口 deadline。calibration 缺失/过期/误差超限时，accepted 前禁用 P/D，accepted 后 fail closed；禁止用 wall clock。
8. retry最多一次，只在尚未向客户端输出且幂等/所有权安全时发生；沿用同一 absolute deadline、budget lineage 与 payload digest，永不重新发放预算。

## 6. Contracts

### 6.1 API/CLI contract

- public generation API 与 V2.1 兼容；debug metadata 可显示 `execution_mode=unified|pd` 和稳定 phase/reason，不暴露地址或 page 内容。
- accepted 的唯一线性化点是 `AdmissionBundle` 的 durable atomic commit：同一 commit sequence 同时创建 `AdmissionLease`、`FutureDecodeCredit` 与权威 accepted mutation；任一部分失败则全回滚。之前不足返回429、路径不可用返回503，之后才计入 request failure/terminal 分母。公开 request terminal enum 严格限定为 `FINISHED | CANCELLED | FAILED | DEADLINE_EXCEEDED`；ticket 的 `COMMITTED/CANCELLED/FAILED` 等协议内部状态不改变这一枚举。
- `illm pd doctor|credits|tickets|drain` 提供 capability、credit、ticket 和 bounded drain；`replay --mode state` 保持为正式接口。
- client deadline 在 ingress 转为 `DeadlineBudgetV1` 的 authority-monotonic absolute deadline；wire 同时传 authority deadline、calibration identity、保守 `remaining_budget_ns` 与 lineage。接收方取 absolute-derived 与 carried remaining 的较小值；不使用 wall clock，也不允许仅从接收时刻重新开始 TTL。
- streaming 开始后 Decode failure 显式 terminal error/close；不能重新 prefill并拼接输出。

### 6.2 Config/manifest contract

| 字段/对象 | 稳定性 | 兼容规则 |
|---|---|---|
| `AdmissionBundle` | stable | V3 major 内兼容；request、prefill lease、future credit、generation、budget lineage和accepted event原子绑定 |
| `FutureDecodeCredit` | stable | bytes/pages/token upper bound、destination pool/generation、expiry、conversion/refund唯一；expiry 先 fence bundle/work，不能按时钟直接 refund |
| `KVTransferManifest` | stable | model/spec/weights/runtime dtype、KV layout/page、positions、layer/head/TP mapping、source generation、payload digest精确匹配 |
| `DecodeCursorV1` | stable | prompt/output/KV valid-through、base-next-logits、pending-input、SamplingSpec/RNG/grammar/model identity 一致；V3.0 固定 Decode 采首 token |
| `TransferTicketJournal` | stable | state/generation/lease refs/fence/retry count/terminal/expiry幂等持久到drain；`EXPIRED` 只能在 source/copy/device fences resolve 后持久化 |
| `remaining_budget_ns` | stable | wire field；非负整数；每跳只减不增；retry沿用同一lineage；缺失/溢出fail closed |
| `DeadlineBudgetV1` | stable | authority-monotonic absolute deadline、lineage/seq、calibration ID/validity/error bound 必填；receiver 取保守最小 remaining |
| `pd.max_retries` | stable | V3.0只允许0或1；默认1；语义是额外attempt数 |
| optional `v1.3-merged` functional profile | experimental | 非硬依赖；SamplingSpec v2、GrammarSpec、`SpecTxnV1`、draft-target KV 与 leader commit 须联合资格；不自动授予 R2 |
| optional `v1.3-merged + encrypted_tokens` capture tier | experimental | functional profile 先通过；敏感 capture、密钥分离/保留和 exact identity 独立资格后才允许 R2 |

`v1.3-merged` functional profile 启用时，V3.0 的 speculation 从 DECODE_READY 后开始；handoff 仍只传 prompt target KV 与 base logits，不传 draft KV、rolled-back pages 或 provisional `SpecTxnV1`。GrammarSpec/RNG/leader commit 的 provisional state 不因服务 hop 提前提交。functional qualification 不代表 capture 具备数值输入；只有显式 `v1.3-merged + encrypted_tokens` capture tier 才可声明 R2，并须重建相同 accept/rollback 与 commit digest。

### 6.3 Event/capture/replay contract

- 新增 `pd.admission_bundle_acquired/rejected/released`、`decode_credit.acquired/converted/refunded/expired`、`pd.prefill.*`、`kv.transfer.*`、`pd.decode_cursor_published/validated`、`pd.decode_ready`、`deadline.budget_received/forwarded/exhausted/calibration_rejected`、`pd.orphan_reaped`。
- 每个 entity mutation 带 `(entity_id,generation,entity_mutation_seq)`；accepted event是AdmissionBundle权威mutation，跨 prefill/credit/ticket/decode/terminal 使用 causal parent，不靠时钟推断。
- snapshot barrier 保存 router/admission/prefill/credit/transfer/decode 各 authority watermark、lease/ticket/page/base-logits/cursor digest、absolute deadline/calibration 与 budget lineage；缺任一参与 generation 则 R1 标 incomplete。
- `illm replay CAPTURE_DIR --level R1 --mode state` 必须重建 accepted/terminal、bundle/credit、ticket/ownership、remaining budget和resource digest；`CAPTURE_DIR` 是 capture 目录字面参数，`--mode state` 不得移除。
- R2 仅在显式 `v1.3-merged + encrypted_tokens` 且 exact software/model/topology/backend capture tier 下运行；默认 `metadata_only/equality_only` 即使 functional profile 通过也仍最高 R1。跨服务展示必须显示 clock calibration uncertainty，deadline 只以 authority-monotonic absolute deadline 与保守 deduction 事实为准。

### 6.4 资源、并发与失败 contract

- acceptance前必须原子拥有 `AdmissionLease` 与 `FutureDecodeCredit`；任一 acquire失败不得出现accepted、prefill work或残留另一资源。
- future credit是Decode MemoryPlan的硬reservation类别；actual destination pages conversion全有或全无，且发生在source send之前。
- source request/cache、future credit、destination pages、staging、ticket分别计数；request结束不得错误释放cache lease。
- destination COMMITTED前不可被attention/prefix index读取；source收到matching generation COMMITTED ack或terminal cleanup前保持可读。
- DecodeCursor/base logits/page table 必须同一 publish generation；首 token 只由 Decode sampling leader从 handoff base logits 产生，随后作为 pending-input 进入下一 step。`committed_output_count` 与 `kv_valid_token_count` 分开推进。
- 每个 hop 的 effective remaining 必须不大于 authority absolute deadline 推导值与 carried remaining；calibration uncertainty 只能保守缩短预算，不能延长。
- wire budget在每hop单调不增；`remaining_budget_ns=0` 不启动新work。一次retry不重置deadline、budget、idempotency或accepted point。
- accepted bundle 的 deadline/credit/ticket 到期时，authority 先原子置 `EXPIRING`，阻止新的 prefill、source send、copy、decode 与 retry，并由唯一 request terminal CAS 选择 `DEADLINE_EXCEEDED`（预算到期）或 `FAILED`（generation/authority 故障）。已 launch 的 source read/DMA/device work 仍持有 lease；只有其全部 fence resolve、destination unpublished pages/staging 回收且 terminal durable 后，才可 refund `FutureDecodeCredit`、释放 AdmissionLease/GroupReservation 并把 ticket 写为 `EXPIRED`。任何 TTL scan 都不得直接复用 in-flight page/credit。
- heartbeat丢失先generation fence/停止新work，再依据local journal/fence安全清理；async copy cancel不等于DMA撤销。
- accepted后任何失败得到唯一terminal；retry只改变内部attempt，不增加accepted或terminal事件。

## 8. Correctness and Invariants

### 8.1 Golden/differential

- unified 与 P/D 对至少100 prompts比较首次decode logits、完整greedy tokens、finish/error/terminal；tokens 100%一致，数值采用固定dtype tolerance profile。
- handoff 前后逐项比较 `DecodeCursorV1`：prompt KV valid count、committed output count、next output position、pending input、base-next-logits digest 与 SamplingSpec/RNG/grammar identity；Decode 从 transferred base logits 采出的首 token 必须等于 unified 首 token。
- source与COMMITTED destination对每layer/page/valid token/head/rank mapping做coverage+digest；missing/duplicate/out-of-range为0。
- mock、staged、P2P backend对同一manifest产生相同destination state digest；full-prefix-hit、partial page、GQA、max context、TP2、cancel和sampling进入矩阵。
- random sampling比较SamplingSpec/RNG key/counter/selected tokens；service到达顺序和一次retry不改变结果。
- 条件 `v1.3-merged` functional 矩阵额外比较 grammar mask、`SpecTxnV1` accept/rollback、draft-target KV exclusion 与 leader commit digest；只有另行启用 `encrypted_tokens` capture tier 时才比较 R2 re-execution digest，二者 outcome 不得合并。

### 8.2 Property/state invariants

- `accepted(request)` ⇔ 恰有一个原子成功 `AdmissionBundle`，且同时存在matching AdmissionLease和FutureDecodeCredit lineage；无双accepted。
- credit conversion全有或全无；`TRANSFERRING`必有source read、完整destination reservation和staging；`COMMITTED`必有fence+coverage/digest+原子publish。
- ticket state单调且COMMITTED/CANCELLED/FAILED互斥；duplicate消息不增加allocation/refcount/retry/terminal。
- `remaining_budget_ns`沿 causal path 单调不增且不大于 authority absolute deadline 推导值；IPC/network transit 与 calibration uncertainty 已计入；retry_count≤1，retry后budget≤retry前，accepted/terminal计数不变。
- handoff 时 `committed_output_count=0` 且 KV 只覆盖 prompt；首 token commit 后作为 pending-input，直到下一 Decode model step 才增加 KV valid count。cursor/base logits/page table 任一 generation/digest 不同均不可 DECODE_READY。
- 每entity mutation seq单调且causal parent可解析；complete snapshot覆盖所有参与service generation。
- 每个accepted request恰有一个terminal；terminal后非cache admission/credit/destination/staging/ticket lease最终为0。
- bundle/credit/ticket 进入 `EXPIRING` 后不再启动 source send/copy/decode/retry；在全部相关 fence resolve 前仍计入 reservation，之后所有资源恰好 refund/release 一次。

### 8.3 Failure/stress matrix

| 场景 | 注入方式 | 必须结果 | 禁止结果 |
|---|---|---|---|
| 双资源一侧不足 | exhaust prefill或decode | admission bundle整体拒绝/回滚，无accepted | 只拿一半/先accepted |
| accepted ack丢失 | drop router reply | idempotent查询同一bundle/accepted event | 第二accepted或双reservation |
| credit→pages部分失败 | fail第N页 | 全部回滚/明确terminal，source不send | partial destination |
| manifest/layout不匹配 | 改identity/TP mapping | PREPARED/send前fail closed | 静默转换 |
| cursor/base logits 损坏 | 改 valid count、position 或 digest | publish 前 fail closed；无首 token输出 | 重复最后 prompt token、猜测 cursor |
| copy中cancel | delay DMA + cancel | logical cancel，等fence后幂等cleanup | 提前复用页/buffer |
| accepted credit/ticket 到期且 DMA in flight | exhaust deadline + delay copy/device fence | 先 EXPIRING/停止新 work，唯一 DEADLINE_EXCEEDED/FAILED，全部 fence 后 refund/reclaim 一次 | TTL 直接回收、source 继续 send、retry、页被提前复用 |
| COMMITTED ack丢失 | drop first ack | 返回同一journal result | 重复copy/refcount |
| service慢+retry | delay queue/IPC/network/each hop | authority deadline 推导预算单调扣减，最多一次 retry，0时 timeout | transit 免费、deadline 重置/无限 retry |
| clock calibration失效 | 过期/扩大 uncertainty | accepted 前关闭 P/D 或 accepted 后 fail closed | 从 receive 时刻重新发放 TTL |
| Decode generation退出 | kill before/after publish | generation fenced；未输出按一次策略，已输出显式失败 | 旧页被新generation读 |
| credit overload | 150% burst | bounded queue/429且无OOM | 无限future tickets |
| capture丢seq/barrier participant | drop events | R1 incomplete并在后续barrier恢复 | 猜测ownership/accepted |

### 11.2 Rollback

- router先停止P/D admission，把新请求送到已qualification的unified/TP/DP capacity；不足时明确429。
- 对已accepted bundle执行bounded drain；未输出请求按冻结策略最多一次内部retry或显式失败，已输出请求显式terminal，禁止拼接。
- 等待transfer/CUDA fence，完成snapshot barrier，幂等释放future credit/destination/staging/source request leases并关闭services。
- 丢弃P/D ticket/credit journal、role-bound cache/graph和transferred KV；保留canonical weights/captures。启动V2.1 config并运行doctor+canary。
- performance no-go可直接按上述路径默认关闭P/D；不需要伪造成功，但rollback容量必须在release evidence中验证。

## 13. Known Limitations

- 基础版仅同机、同模型/dtype/KV layout/TP mapping；不做跨节点或在线转换。
- P/D重复权重并预留future/destination容量，可能比unified使用更多总显存。
- accepted后Decode generation失败可能使请求显式失败；已输出stream不透明retry。
- `max_retries=1`是硬上限且不重置budget；复杂多次重试/迁移不在本版。
- performance no-go时P/D仍experimental/default off；V3.1可先稳定unified，不能把P/D自动写成stable。
- v1.3 advanced generation只在条件profile内，不是V3.0硬依赖。
