> v1.3.0 只增加 standalone draft model 与 lossless speculative transaction：propose、target verify、accept/reject、residual/bonus、commit/rollback 和对应可视化。它不依赖 v1.1 是否 Adopt fast path，也不把 speculation 塞进 M7 分支；实现必须能在 v1.0 eager/reference execution 上独立运行。v1.2 structured outputs 被原样保留并集成，而不是改写其 byte grammar 或 SamplingSpec v2。

## 1. 本版本学习目标

### 1.1 必须掌握

- 能从 target/draft 的 shifted logits 正确构造 `p_i` 与 `q_i`，解释为什么 `p_1` 必须来自 committed prefix 的 base next logits。
- 能实现 stochastic lossless acceptance `min(1,p_i(x_i)/q_i(x_i))`、residual `normalize(max(p_i-q_i,0))` 与 all-accepted bonus，并处理 FP32/FP64 边界。
- 能定义 versioned Philox4x32-10 counter RNG，精确说明 key、128-bit counter tuple、endianness、lane、u32→uniform 与 CDF 边界，并用 known-answer vectors 锁定 CPU/CUDA 行为。
- 能把 target/draft tentative KV、proposal、完整 q evidence、shadow grammar state、RNG addresses 与 fences 组织成可提交或完整回滚的 transaction。
- 能处理 proposal length、EOS、remaining output budget、cancel、OOM、draft/target failure 和 fallback，保持唯一 terminal 与不重复 streaming。
- 能证明 greedy token equivalence 与 stochastic distribution equivalence 是两种不同 gate，并用可视化把每个 accepted/rejected token 与 p/q/RNG/资源状态连接起来。

### 1.2 建议先修

- v1.2.0 的 GrammarSpec、SamplingSpec v2、TokenizerByteManifest、normal structured reference、DFA shadow state 与 conformance corpus全部通过。
- 熟悉 autoregressive shifted logits、categorical/rejection sampling、Philox、浮点归一化、paged KV lease/fence 和事务状态机。
- 能执行小词表 exhaustive test、统计分布检验、GPU memory planning、R1 replay，以及带敏感 logits/token 的 opt-in encrypted capture。

### 1.3 预热与进入门槛（Warm-up / Entry Gate）

- 预计用时 45～60 分钟；先用 CPU reference 手算并核对 p/q、Philox address 与事务回滚，再接触 GPU candidate。
- target 与 draft 的模型、weights、tokenizer、vocab/token ID、special token、SamplingSpec processor 和 dtype manifests 已固定；v1.3 首版要求 target/draft tokenizer 与 token IDs 完全相同。
- target-only normal decode（unconstrained 与 structured）有独立 golden；`base_next_logits` 的所有权、有效 prefix digest 和 lifecycle 已有测试。
- `rng/philox4x32-10-v1.md`、draw-kind registry 和 CPU reference 已评审；任何 key/counter/lane/float 边界未决都会阻止实现。
- proposal/q-store/target verify/draft KV/tentative pages/structured shadow state 的 worst-case bytes 已进入 `MemoryPlan`，admission 保留明确 headroom。
- 预热练习已完成：对 vocab≤4、proposal_len=2 的固定 p/q 手算一次 all-accept 和一次 reject-residual，并把结果与 Philox CPU reference 对齐。

### 1.4 Teach-back 产物

- `release/v1.3.0/teach-back.md`：用一次 all-accepted、一次第 i 个 rejected、一次 structured EOS 展示 p/q 索引、RNG address、residual/bonus、KV 与 grammar commit/rollback。
- 一段不超过 20 分钟的演示：同一 target request 对比 target-only 与 speculative，逐 token 打开 Transaction Explorer，并在 fault barrier 注入 cancel 证明无 partial commit。
- known-answer walkthrough：手算至少一个 Philox raw u32→uniform→accept/CDF 选择，解释 endian、lane 与半开区间边界。

## 3. Scope

### 3.1 本版本新增

- 一个独立 draft runner，使用与 target 完全相同 tokenizer/token IDs；draft identity 和 target identity 都进入 request/capture/cache namespace。
- 有界 `proposal_len` 的 sequential draft proposal 与 batched target verification；支持 greedy exact 和 lossless stochastic 两种明确 profile。
- target/draft/p/q/RNG/grammar/KV 的 `SpecTxnV1`，具备 verify、decision、atomic domain commit、rollback/fence reclamation。
- 完整 FP32 q evidence 的 store 或确定性重算策略、显式 MemoryPlan 与 off-by-one indexing contract。
- structured speculation：proposal、accept/reject、residual、bonus 均复用 v1.2 byte DFA、SamplingSpec v2 与 shadow grammar state。
- Transaction Explorer、acceptance/performance compare、R1 reducer 和版本化 known-answer/conformance evidence。

### 3.2 本版本保持不变

- target model 是最终输出分布唯一权威；draft 不可绕过 target verify，也不可修改 API terminal/usage/stream order。
- target-only eager/reference 永久可运行；speculation 默认可一键关闭，v1.1 performance branch 与 speculation capability 相互独立。
- v1.2 normative grammar、JSON/regex profile、SamplingSpec v2 processor 顺序、EOS 与 tokenizer byte semantics 不变。
- scheduler/paged KV/prefix/preemption、lease/fence、MemoryPlan、R0/R1 与隐私 contract 保持；只增加 tentative ownership。

### 3.3 Feature flags 与 fallback

| 能力 | 默认值 | Reference/fallback | 失败时行为 |
|---|---|---|---|
| `speculative.enabled` | qualification 前 off | target-only | manifest/capability miss 在 admission 前拒绝或显式 target-only policy |
| `speculative.mode` | `greedy_exact` | target-only matching request semantics | 合法值仅 `greedy_exact` / `sampled_lossless`；sampled request 在 greedy 配置下回退 target-only，不可偷偷改变采样语义 |
| `speculative.proposal_len` | manifest 固定且有上限 | target-only one token | runtime k=min(config, remaining budget) |
| `speculative.q_strategy` | `store_fp32` | `deterministic_recompute_fp32` | 无完整 q 时 stochastic profile fail closed |
| `structured_outputs` | 沿用 v1.2 | target-only structured | speculation miss 不得关闭 grammar |

transaction 发生外部可见 commit 后禁止切换 target-only 重新处理同一位置；commit 前 fallback 必须先完整 rollback、等待必要 fence 并生成稳定 reason event。

## 4. Non-goals

- 不支持不同 tokenizer/vocab 的 draft-target mapping、prompt lookup speculation、multi-draft tree/Medusa、multi-token head 或 distributed speculation。
- 不改变 v1.2 grammar/SamplingSpec，不新增 CFG/tool calling，不以 speculative 内部 mask 作为第二套 structured semantics。
- 不承诺固定 seed 下 sampled on/off token 相同；承诺的是给定 target SamplingSpec 的分布等价。
- 不允许 sparse/top-k 截断 q 近似替代完整 q 来宣称 lossless stochastic；近似算法必须新版本、新语义名。
- 不要求 speculation 性能必须胜出；低 acceptance、额外显存或 target verify 成本导致 No-go 时保持默认 off。

## 5. Architecture Delta

### 5.1 相对上一版本的变化

```text
committed prefix at absolute output position t
  ├─ draft: propose x_1..x_k and retain q_1..q_k
  ├─ target: base p_1 + shifted verify p_2..p_{k+1}
  ├─ decision: accept prefix; then residual on reject OR bonus on all-accept
  └─ SpecTxnV1: atomically publish decided tokens/state or rollback all tentative state

structured request: every q_i/p_i uses the same v1.2 shadow DFA state for x_<i
```

### 5.2 新增或修改的模块

| 模块 | 变化 | 责任边界 | 禁止事项 |
|---|---|---|---|
| `draft/runner` | add | proposal logits/tokens/KV 与 q evidence | 不发布用户输出、不决定 correctness |
| `speculative/indexing` | add | base/shifted p/q view 与 position proof | 不用 verify row 0 冒充 p_1 |
| `speculative/rng` | add | Philox address、draw kinds、known answers | 不依赖 batch row/step/stream timing |
| `speculative/txn` | add | tentative leases、decision、commit/rollback | 不边验证边 streaming partial token |
| `speculative/residual` | add | full p/q residual 与 bonus categorical | 不使用截断 q/负概率修补 |
| `grammar/spec_adapter` | change | shadow DFA/mask 与 commit integration | 不修改 v1.2 normative semantics |
| `web/transaction_explorer` | add | p/q/RNG/token/resource 因果链 | 不在无敏感 capture 时反推 logits |

### 5.3 SpecTxnV1 状态机

```text
NEW → PROPOSING → PROPOSED → VERIFYING → VERIFIED → DECIDED
    → COMMITTING → COMMITTED
any pre-commit state → ROLLING_BACK → ROLLED_BACK
```

只有 `COMMITTED` 可发布 token chunk、usage delta 和 authoritative grammar/output transition。`ROLLING_BACK` 先逻辑失效 tentative handles，再等待 target/draft `CompletionFence`，最后归还 page/q buffer/workspace。commit 本身必须验证 request generation、prefix digest、remaining budget 和 grammar version 未变化；不一致只允许 rollback/replan，不得提交 stale decision。

## 6. Contracts

### 6.1 Target/draft shifted-logit indexing

`DraftModelManifestV1` 是 admission 前冻结的 canonical JSON，至少包含：schema version；draft `SupportedModelSpec`、weights 与 `WeightLoadManifest` digest；software/model numerical contract；runtime dtype/backend/device；draft `KVLayoutSpec`；max context；tokenizer/vocab/token-ID mapping digest；对应 target 全部 identity；SamplingSpec/grammar processor compatibility；proposal length 上限；q strategy 与 manifest 自身 digest。draft 与 target 可以是不同 architecture/weights，但 tokenizer vocab 大小、每个 token ID→bytes mapping、special-token/EOS 语义必须精确相同，二者 context limit 都覆盖 prompt + output budget。任一 required 字段缺失或 digest 不同，在 accepted 前禁用 speculation或拒绝；draft/target KV pool 永远按各自 identity 分离。

令 committed output 长度为 `t`，prefix 为 `prompt || y_0..y_{t-1}`，draft proposals 为 `x_1..x_k`。所有位置均以 zero-based absolute output position 表示，`x_i` 的位置是 `t+i-1`。

- `q_i` 是 draft 在条件 `prefix || x_1..x_{i-1}` 下，经当前 SamplingSpec/grammar processors 后的完整 FP32 probability vector；`x_i` 从该 q_i 采样或 greedy 选择。
- `p_1` 必须来自 target 对 committed prefix 保存的 `base_next_logits`，经相同位置的 processors 得到；绝不能取 target verify output 的第一行替代。
- target 一次消费 `x_1..x_k` 后，消费 `x_i` 所产生的 shifted next logits 定义 `p_{i+1}`。因此 verify row `j`（zero-based，对应消费 `x_{j+1}`）给出 `p_{j+2}`；最后一行给出 bonus distribution `p_{k+1}`。
- `sampled_lossless` 对 proposal `x_i` 的 acceptance 比较 `p_i(x_i)` 与 `q_i(x_i)`；`greedy_exact` 使用 §6.4 的 argmax 等价算法，绝不套用 p/q 随机接受。任何 adapter 必须输出 `TargetVerifyResult{base_next_logits, shifted_next_logits[k], prefix_digest}` 以消除 off-by-one。

`sampled_lossless` 的 processed logits 以 FP32 保存并用稳定 max-shift softmax 得到 FP32 p/q。acceptance ratio 把已存 FP32 标量无损 widen 为 FP64 后计算。若实际采出的 `q_i(x_i) <= 0`、p/q 含 NaN/Inf 或 normalization 为 0，transaction fail closed；不夹成 epsilon 继续。

### 6.2 Full-q、residual 与 MemoryPlan

stochastic lossless profile 对每个 i 必须能恢复完整 vocab FP32 `q_i`。合法策略只有：

1. `store_fp32`：保存连续 `[k,V]` FP32 post-processor probability matrix；最低 payload 是 `k * vocab_size * 4` bytes，加 alignment/metadata 后写入 MemoryPlan；
2. `deterministic_recompute_fp32`：保存 draft inputs、processor/grammar shadow snapshots 与 exact model/config digest，并在同一 release/hardware contract 下重算出 byte-identical FP32 q；资格测试任一元素不同即不支持 stochastic，回退 store 或 target-only。

拒绝 `x_i` 时，定义 `d(v)=max(float64(p_i(v))-float64(q_i(v)),0)`，按 token ID 升序 FP64 求和并归一化。若 sum 在规范 tolerance 内为 0，这意味着理论上应总接受；观察到 reject 是 invariant violation。residual categorical 从完整 d 采一个 token，提交 accepted prefix `x_1..x_{i-1}` 加 residual；`x_i..x_k` 不提交。不得使用 top-k q、只保存 q(x_i) 或 backend 私有 sparse logits近似 residual。

### 6.3 Philox4x32-10 v1 RNG contract

- 算法固定 Philox4x32-10。每个 request 的 `seed` 是 unsigned 64-bit；省略时 admission 生成 u64 并写入受隐私策略保护的 replay manifest。
- 64-bit key 明确为两个 uint32 word：`key=(seed & 0xffffffff, seed >> 32)`。word 的 byte serialization 是 little-endian；Philox round 在 uint32 word 上执行，禁止 host-native byte reinterpretation。
- 每个随机 scalar 的逻辑 identity 固定为 `(absolute_output_pos:uint64, draw_kind:uint32, draw_index:uint32)`。128-bit counter words 必须是 `counter=(pos_low32, pos_high32, draw_kind, draw_index)`，逐 word little-endian 序列化；不得把四字段相加、截断 position 或依赖 host-native layout。
- draw kind registry v1：`TARGET=0, DRAFT=1, ACCEPT=2, RESIDUAL=3, BONUS=4`。`draw_index` 是同一 position/kind 下 zero-based scalar ordinal；每个 counter **只消费 lane 0**，其他三 lane 只进入 known-answer backend conformance，不分配给后续 scalar。正常 categorical/accept 各用 `draw_index=0`；未来新增 draw 时递增 draw_index，不改变既有地址。
- raw lane-0 u32 `x` 映射为 `u=float64(x)*2^-32`，范围 `[0,1)`，与 v1.0/v1.2 canonical sampler 完全相同。不得用 `(x+0.5)*2^-32`、`x/(2^32-1)`、FP32 rounding 或 closed interval 替代。
- categorical 将合法 token 按 ascending token ID，用 FP64 累加已冻结的 FP32 probability；token interval 是 `[cdf_prev,cdf_next)`，选择第一个满足 `u < cdf_next` 的 token。若 `u == cdf_next`，进入下一 token；最后一个正概率 token吸收仅由累加 rounding 造成的尾差。
- acceptance 使用 `u_accept < min(1, p_i(x_i)/q_i(x_i))`；严格 `<` 是规范边界。proposal、accept、residual、bonus 分属不同 draw kind，batch row、scheduler step、CUDA stream、其他 request 或 rejection tail 不改变其地址。

以上 Philox draw 只属于 `sampled_lossless`。`greedy_exact` 的 draft proposal、target decision、mismatch token 与 bonus 均不消耗 RNG；logical output position 可以推进，但 `draws_consumed` 保持不变。

`release/v1.3.0/rng/known-answer-vectors.json` 必须包含 seed、64-bit position、kind、draw index、counter words/bytes、key words/bytes、10-round raw lanes、固定 selected lane 0/u32、uniform hex/decimal、CDF probabilities/token 和结果。向量必须覆盖 position 高 32-bit 非零、多个 draw kind 和相邻 draw index；CPU scalar、CPU vectorized、CUDA kernel 逐 raw word 匹配。float/CDF 边界另含 `u==cdf`、u=0、u near 1 与零概率 token。

### 6.4 Proposal、EOS、budget 与 bonus

transaction 开始时 `remaining=max_output_tokens-committed_output_tokens`；配置要求 `configured_proposal_len>=1`，`k=min(configured_proposal_len, remaining)`。remaining=0 不启动 transaction，按既有 budget terminal 结束。remaining>0 时一次有效 proposal 必须至少产生一个 token；draft 在首 token 前失败或无法提议时 rollback 并走 target-only `TARGET` draw，而不是把零 proposal 冒充 all-accepted bonus。draft sequential proposal 每次使用下一个 absolute position，遇到合法 EOS 后将 EOS 包含为最后 proposal并立即停止；EOS 后禁止生成 tail。

`greedy_exact` 从 i=1 顺序计算 target processed logits 的 canonical argmax（tie 取最小 token ID）：若 `x_i` 等于 target argmax，则接受并继续；首次不等时，提交此前相等 proposal 加该位置的 **target argmax**，不采 residual、不消耗 acceptance RNG，并停止验证。该 mismatch target token 尚未被 target 消费，按 pending-input 处理，verify 产生的 mismatch/tail KV 全部 rollback。若所有实际 proposals 相等：遇 EOS 或 budget 耗尽时只提交 proposals；否则从 `p_{k+1}` 取 canonical target argmax 作为最多一个 bonus，同样不消耗 RNG。由此 greedy speculative 的 token、finish reason 与 usage 必须逐步等于 target-only greedy。

以下决策只适用于 `sampled_lossless`：从 i=1 顺序验证，首次 reject 后停止 acceptance loop，提交 accepted prefix 加一个 residual，且无 bonus。若所有实际 proposals 接受：

- 若最后 token 是 EOS，commit proposals，无 bonus；
- 若 commit proposals 后 remaining 为 0，commit proposals，以 length terminal 结束，无 bonus；
- 其他情况从 `p_{k+1}` 用 `BONUS` draw kind 采至多一个 bonus；structured request 使用 proposals 后的 shadow grammar mask，bonus 若为 EOS同样服从 accepting rule。

proposal 数可以因 EOS 小于 configured k；其他提前停止都作为 draft failure rollback，不产生 bonus。bonus 的位置始终是 `t+actual_proposal_count`。一个 transaction 的决定 token 总数永不超过进入时 remaining。draft failure before decision 可 rollback 后 target-only；target verify/decision error 不可用未验证 proposal继续。

### 6.5 Structured transaction 与资源 contract

draft proposal 在 v1.2 authoritative grammar state 的 clone 上逐 token mask/transition，得到 shadow state `g_i`；target p_i 与 q_i 必须使用相同 `g_{i-1}`。acceptance 不推进 authoritative state。residual 使用 reject position的 p/q（两者已受同一 mask），bonus 使用 all-proposals state的 p_{k+1} mask。commit 逐决定 token应用 v1.2 transition并核对最终 state digest；rollback丢弃全部 shadow state。

target/draft tentative KV page、q matrix、logit workspace和 shadow state都有 transaction ID、generation和最后 fence。target verify 对 rejected/tail 产生的 KV 永不成为 authoritative；只按现有 KV materialization contract提升 accepted prefix 对应 lease。residual/bonus 尚未被相应模型消费时标为 pending-input，在下一模型 step前不得声称 KV 已 materialized。draft KV若保留 accepted prefix，也必须在 residual/bonus 后显式 catch-up 或 invalidation，禁止把不连续 prefix复用。

## 8. Correctness and Invariants

### 8.1 Golden/differential

- tiny model手工 logits覆盖 k=1/max、p=q、p>q、p<q、q(x)=0 invariant、首次/中间/末尾 reject、all accept、residual与bonus。
- 每个 p/q fixture显式断言 p_1 base source、verify row→p_{i+1} mapping、absolute position、processor/grammar state与 full vector digest。
- greedy target-only/speculative输出 token、finish reason、usage与 authoritative state完全一致，包括 EOS/budget/structured/fallback。
- sampled 小词表枚举验证算法的 target marginal；Monte Carlo suite 使用预注册 seed count、alpha、multiple-test correction 和 effect bound验证分布等价，不要求 seedwise token一致。
- Philox scalar/vector/CUDA raw lanes逐 word等于 known answers；u32→uniform和 exact CDF boundary vectors逐 case一致。

### 8.2 Property/state invariants

- proposal token只有通过对应 p_i/q_i target verify才能提交；draft永不独立决定最终输出。
- transaction只有 COMMITTED 或 ROLLED_BACK 一个终态；rollback后 authoritative output/KV/grammar/RNG usage/stream chunk均无变化。
- committed token数不超 entering remaining；EOS 后无 token；reject后恰好一个 residual且无 bonus；all accept最多一个 bonus。
- stochastic mode每个 q_i是完整 FP32 vector或byte-identical deterministic recompute；MemoryPlan覆盖worst-case k×V bytes。
- RNG address只由 seed、absolute position、draw kind与logical ordinal决定；不依赖 batch/step/stream/timing。
- structured commit final DFA digest等于 v1.2 normal decode逐 token reference；rollback authoritative DFA不变。
- accepted request仍恰好一个 terminal；tentative page/buffer在最后 fence前不复用。

### 8.3 Failure/stress matrix

| 场景 | 注入 | 必须结果 | 禁止结果 |
|---|---|---|---|
| cancel during draft | proposal i barrier | rollback、无 output/state advance、fence后回收 | partial proposals streaming |
| target verify OOM | verify allocation fault | rollback；policy允许时 target-only retry | 未验证 proposal commit |
| q store不足 | 降低 MemoryPlan headroom | admission拒绝或 target-only | sparse q冒充 lossless |
| shifted off-by-one | 交换 base/row fixture | golden必失败 | 统计测试掩盖索引错误 |
| EOS in proposal | draft第 i 个输出 EOS | proposal截断、验证后无 tail/bonus | EOS 后继续输出 |
| stale prefix | verify期间触发 cancel/version变更 | commit revalidation失败并rollback | stale transaction commit |
| draft async error | fence后注入 error | transaction失败；内存未知则worker fail-stop | 回收/复用未完成 buffer |
| structured reject | 中途拒绝并采 residual | shadow tail rollback、authoritative逐commit决定token | grammar state按proposal tail推进 |

## 10. Performance Hypothesis

### 10.1 本版本性能立场

lossless correctness先于速度。只有在固定 target/draft、proposal len、MemoryPlan与workload下，端到端 target-step reduction转化为SLO goodput收益且所有分布/资源guardrail通过，speculation才可成为guarded default；否则v1.3仍可作为默认off的正确实验能力发布。

### 10.2 Experiment card

```yaml
question: 固定 draft 能否在 lossless target distribution 与同 SLO 下提高 output-token goodput？
hypothesis: sufficient accepted proposals amortize target decode steps more than draft, verify and memory overhead
primary_metric: illm.benchmark.output_token_goodput.slo.v1
guardrails: [illm.correctness.target_distribution.v1, illm.server.ttft.request_weighted.p99.v1, illm.server.itl.token_weighted.p99.v1, illm.client.e2e.request_weighted.p99.v1, illm.gpu.memory.peak_bytes.v1, illm.request.terminal.failure_rate.accepted_request_weighted.v1]
tuning_suite: benchmark/suites/v1.3-speculative-tuning.yaml with immutable digest
held_out_suite: benchmark/suites/v1.3-speculative-held-out.yaml with immutable digest
budget: proposal_len candidates <=4, max 8 configs, 3 pilots and 5 confirmations, equal GPU-hours
success: five-run median primary improves >=10%, bootstrap CI clears noise, distribution/correctness exact gates and every guardrail pass
no_go: equivalence fails, acceptance is insufficient, memory/warmup/failure cost violates a guardrail, or effect misses threshold by timebox
```

报告同时列 proposal acceptance by position、committed tokens/target verify、draft/target GPU time、q-store bytes和 `illm.speculative.transaction.server_duration.request_weighted.p99.v1`。失败/取消/timeout使用accepted-request分母，不得从 goodput/SLO 隐藏。structured 与 unconstrained 是两个预注册 cohort，不互相平均掩盖退化。

### 11.2 Rollback

运行时先将新admission的 `speculative.enabled=false`；in-flight transaction按原binary完成commit或rollback，不能中途热切换其q/KV。随后drain并可回退v1.2 binary；所有tentative draft/target KV和q buffers丢弃，normal target prefix仅按原v1.2 identity规则保留。v1.3 capture在v1.2 reader只展示通用request事件，不能重执行 speculation。known answers、raw distribution evidence和outcome不可覆盖。

## 13. Known Limitations

- 首版只支持相同 tokenizer/vocab/token IDs 的一个 draft 与一个 target，单进程单 GPU。
- 完整 q matrix 的显存成本可观；大 vocab/大 k 可能使admission回退target-only。
- sampled on/off相同seed可能产生不同token序列；只对target distribution做规范承诺。
- draft acceptance强依赖模型/workload；默认off或No-go是合法结果，不代表transaction实现失败。
- 默认R0/R1不保存敏感p/q/token/key，Transaction Explorer某些数值显示redacted/unavailable。
- residual/bonus与KV materialization存在一step语义边界，必须按engine contract解释，不能把logical commit误写成KV已materialized。

### 13.1 下一版本输入

- 后续多GPU/PD若引入speculation，必须把SpecTxnV1 ID、RNG address、target/draft identity与tentative ownership纳入distributed manifest，不能只复制token。
- 不同tokenizer mapping、tree speculation或approximate sparse-q必须新SPEC并使用不同语义名，不修改lossless v1 contract。
- v1.3 target-only、normal structured与greedy exact paths继续作为未来优化oracle。
- performance No-go的revisit trigger只在draft质量、硬件或workload证据变化时重开，不在稳定性版本顺手调优。
