> V2.1 只在 V2.0 的完整 TP/unified replica 之上增加 Data Parallel replicas 与一个全局 router。它解决 replica 选择、cache affinity、health、admission、容量与横向吞吐；不修改 rank 内 collective/sampling，不引入跨节点或 Prefill/Decode 分离。

## 1. 本版本学习目标

### 1.1 必须掌握

- 能区分 TP group 与 DP replica：前者共同执行一个请求，后者各自完整执行不同请求；能解释 TP×DP 的两层所有权。
- 能实现一次原子的 route-and-reserve：router 只有成功取得目标 replica 的 `AdmissionLease` 后才写唯一 `request.accepted`。
- 能用 ready/healthy/draining/generation、capacity snapshot 和 cache affinity 选择副本，同时保证 stale snapshot 只导致重试/拒绝，不会超卖。
- 能设计有界 global admission、排队、拒绝和公平性；分母清晰地区分 admission attempt、accepted request、failure 与 reject。
- 能测量 DP goodput、load skew、cache-affinity hit/miss、reject、failover 和 per-replica SLO，并用权威 DecisionRecord 解释选择。
- 能在 replica crash、router restart、drain 与 cancel 下维持一个 accepted point、一个 terminal outcome 和可回放资源状态。

### 1.2 建议先修

- 完成 V2.0，理解 `RankManifest`、`CollectivePlan`、TP leader commit、本地 `GroupReservationV1`、entity mutation sequence、causal parent 与 R1 snapshot barrier。
- 理解 consistent/rendezvous hashing、least-loaded、token bucket、bounded queue、heartbeat/generation 与 basic load-balancing failure modes。
- 能使用 V2.0 per-replica `MemoryPlan`、cache namespace、readiness 和 benchmark 指标，而不是从 GPU free memory 猜容量。

## 3. Scope

### 3.1 本版本新增

- 单机同构 DP2；每个 replica 是 V2.0 完整 unified/TP group，并有独立 scheduler、KV/cache、MemoryPlan 与 generation。
- global router 的候选过滤、版本化 health/capacity、cache affinity、load score、deadline/fairness 和稳定 DecisionRecord。
- router-to-replica 原子 `AdmissionLease` protocol；lease acquire 是唯一 accepted linearization point，不存在先检查后 accepted。
- bounded global attempts/queue、per-replica capacity、429/503 分类、health/readiness/draining、generation fencing 与 failover。
- DP events、权威 entity mutation sequence/causal parent、cross-replica snapshot barrier、R1 state reducer 与 Router Inspector。
- equal-total-GPU unified/TP baseline 与 DP goodput/latency/cache/failure/capacity 实验。

### 3.2 本版本保持不变

- V2.0 rank 内 tensor/collective/leader sampling/all-rank ack/commit contract；router 不读写 rank page table 或 sampling state。
- generation API、streaming、SamplingSpec、error 与 terminal semantics；每个 accepted request 恰有一个 terminal。
- 每个 replica 自己的 MemoryPlan、Paged KV、prefix namespace 和 TP fail-stop；router 只消费版本化摘要和 lease endpoint。
- unified/TP path 始终可独立运行并作为默认 reference/fallback。

### 3.3 Feature flags 与 fallback

| 能力 | 默认值 | Reference/fallback | 失败时行为 |
|---|---|---|---|
| `parallel.dp.enabled` | `false` | V2.0 unified/TP | 关闭时不启动 global router |
| `parallel.dp.replicas` | `2` when enabled | one replica | 任一 identity 冲突 readiness false |
| `router.policy` | `capacity_affinity_v1` | `capacity_only_v1` | 未知 policy/digest fail closed |
| `router.global_queue_limit` | explicit finite | immediate reject | 满时 429，不扩无界 host queue |
| `router.retry_before_accept` | `1` | no retry | 只在尚未取得 lease 时可换目标；accepted 后不路由迁移 |
| `v1.3-merged` functional integration | `false` | V2.0 SamplingSpec v1 | 仅声明条件 functional profile 时启用；不构成硬依赖，也不自动授予 R2 |
| `capture.input_mode` | `metadata_only` | R0/R1 | 只有 `v1.3-merged + encrypted_tokens` 独立 capture tier 可声明 R2 |

DP 的发布稳定性由 §10 决定：性能成功才可设 default on/stable；performance no-go 时仍可发布 functionally-qualified `v2.1.0`，但 `parallel.dp.enabled=false` 且 support matrix 标 experimental，V2.0 unified/TP 保持默认。

## 4. Non-goals

- 修改 TP shard/collective/leader commit、在 replica 间共同执行一个请求，或在 accepted 后迁移 live KV/request。
- 跨节点服务发现、网络负载均衡、P/D 分离、KV transfer、elastic autoscaling 或 Kubernetes/operator。
- prefix cache 跨 replica 共享/复制、持久化全局 cache、全局 KV 去重。
- 多租户计费/配额平台、复杂优先级拍卖、preemption、区域容灾。
- 以更高吞吐掩盖 correctness、failure、lease 或 overload 门；performance no-go 不允许默认开启 DP。

## 5. Architecture Delta

### 5.1 相对上一版本的变化

```text
V2.0: Client → one unified/TP replica

V2.1: Client → Global Router
                    ├─ candidate snapshot + policy DecisionRecord
                    ├─ atomic lease acquire ─→ Replica A (complete V2.0 engine)
                    └─ atomic lease acquire ─→ Replica B (complete V2.0 engine)

accepted point = successful target AdmissionLease acquisition + authoritative accepted mutation
```

### 5.2 新增或修改的模块

| 模块 | 变化 | 责任边界 | 禁止事项 |
|---|---|---|---|
| `dp/registry` | add | replica identity/generation/readiness/health/capability | 以进程存在代替 ready |
| `dp/capacity_feed` | add | 发布版本化 MemoryPlan 可租容量与 cache摘要 | 发布 GPU free memory 当可接受容量 |
| `dp/router` | add | 候选、policy、lease acquire、唯一 accepted mutation | 修改 replica 内部 scheduler/rank state |
| `dp/admission_protocol` | add | idempotent lease acquire/release/fence | check 后无 lease 写 accepted |
| `dp/health_drainer` | add | heartbeat、generation、unhealthy、drain | accepted 后透明迁移请求 |
| `observability/router` | change | DecisionRecord、capacity/health/lease sequence与 barrier | UI 重新执行 policy 猜原因 |

### 5.3 数据流与状态迁移

```text
ATTEMPTED
  → snapshot candidates(policy input digest)
  → candidate ordered list + DecisionRecord
  → replica.acquire_lease(request, expected_capacity_epoch, request_budget)
       ├─ success: lease + authoritative ACCEPTED mutation (唯一 accepted point)
       └─ durable REJECTED/FENCED_NO_ACCEPT certificate: before-accept retry at most once or REJECTED
  → replica V2.0 execution → FINISHED | CANCELLED | FAILED | DEADLINE_EXCEEDED
```

- router 不先 `check_capacity` 再写 accepted；候选 snapshot 只用于排序，目标 replica 在一个原子事务内校验 generation/capacity epoch、提交底层 `GroupReservationV1`、创建跨 replica `AdmissionLease` 并返回 accepted mutation identity。
- `request.accepted` 的权威事件由 lease authority 产生，router 只链接它；重复 acquire 用 `(request_id, attempt_generation)` 幂等返回同一 lease/result。
- acquire timeout、连接断开或 outcome unknown 时，router **只能查询原 authority 的同一 idempotency key**，不得改投其他 replica。只有原 authority 以同一原子写入持久 `FENCED_NO_ACCEPT` 并返回带 generation/sequence 的 `LeaseOutcomeCertificate`，证明旧 attempt 以后不可能 accepted，router 才能递增 attempt generation 并尝试下一 replica。
- replica、capacity、lease、request、router decision 各有权威 writer 与单调 `entity_mutation_seq`；跨实体事件记录 causal parent。snapshot barrier 记录 router watermark 和所有 replica watermarks。

## 6. Contracts

### 6.1 API/CLI contract

- generation API 与 V2.0 兼容；debug metadata 可返回 replica/group identity 和 route reason code，不暴露内部地址或其他租户数据。
- 只有 `AdmissionLease` 原子 acquire 成功才算 accepted。该 durable acquire/CAS 同时写入 lease identity 与权威 accepted mutation，是唯一线性化点；lease 前容量耗尽返回 429，无 ready replica/identity mismatch 返回 503，accepted 后 replica failure 计入 failure 并产生唯一 terminal。公开 request terminal enum 严格限定为 `FINISHED | CANCELLED | FAILED | DEADLINE_EXCEEDED`；route、lease、health 等内部状态不得泄漏为 request terminal。
- `illm dp doctor|capacity|drain` 提供只读诊断与有界 drain；drain 后该 replica 不再接受 lease。
- router restart 可从 lease authority/capture snapshot 恢复；不能把 in-memory “已转发”当 accepted 事实源。

### 6.2 Config/manifest contract

| 字段/对象 | 稳定性 | 兼容规则 |
|---|---|---|
| `ReplicaManifest` | stable | V2 major 内兼容；replica/generation、TP topology、model/weight/config/cache namespace digest 唯一且可验证 |
| `CapacitySnapshot` | stable | 含 epoch、lease slots/token/KV bytes、queue、expiry；过期只可用于展示，不可强制接单 |
| `AdmissionLease` | stable | request/replica/generation/capacity epoch/GroupReservation/deadline/idempotency/terminal refs 不变；首次提供跨 replica durable outcome；expiry 是 fenced cleanup 协议而非按时钟直接释放容量 |
| `LeaseOutcomeCertificate` | stable | 仅 lease authority 签发 `REJECTED` 或原子 `FENCED_NO_ACCEPT`；固定 request/attempt/replica generation 与 mutation sequence，是跨 replica retry 的必要凭证 |
| `RoutingDecisionRecord` | stable | 输入 snapshot digest、过滤原因、score components、ordered candidates、chosen/none 与 policy digest |
| `router.policy` | stable | V2 major 内同名版本语义不变；新语义用新 policy ID |
| optional `v1.3-merged` functional profile | experimental | 非硬依赖；SamplingSpec v2、GrammarSpec、`SpecTxnV1`、draft-target KV 与 leader commit 已在每 replica 完整资格后才能组合 DP；不自动授予 R2 |
| optional `v1.3-merged + encrypted_tokens` capture tier | experimental | functional DP profile 先通过；敏感 capture、密钥分离/保留与 exact identity 独立资格后才允许 R2 |

V2.0 的 tensor `distribution`、`RankManifest` 和 `CollectivePlan` 原样继承；V2.1 不增加或修改其枚举/语义。

functional merged profile 与 replay capture tier 是两个正交 capability：前者证明 DP routing 不改变 SamplingSpec v2、GrammarSpec、`SpecTxnV1` 和 leader commit；后者才证明 encrypted numerical re-execution。默认 `metadata_only/equality_only` 即使 functional profile 通过也仍最高 R1，manifest 必须保存两个独立 digest/outcome。

### 6.3 Event/capture/replay contract

- 新增 `route.attempted/candidates_scored/lease_requested/accepted/rejected`、`replica.registered/ready/unhealthy/draining`、`capacity.published`、`admission_lease.acquired/released/expired/attempt_fenced`、`router.snapshot_barrier.*`。
- 所有 entity mutation 带 `(entity_id,generation,entity_mutation_seq)`；route event 以 causal parent 连接 capacity/health snapshot、lease authority accepted event 与 request terminal。
- DecisionRecord 是当时选择的唯一解释事实源；UI 不用当前 policy 重算历史。拒绝必须记录无敏感数据的稳定 reason 与尝试计数。
- R1 必须通过 `illm replay CAPTURE_DIR --level R1 --mode state` 重建 router/replica/capacity/lease/request terminal digest；`CAPTURE_DIR` 是 capture 目录字面参数，snapshot 缺 replica watermark 时标 incomplete。
- metric event 必须带 registry ID 和 denominator counters；reject 与 failure 永不混为同一分母。

### 6.4 资源、并发与失败 contract

- 每个 replica 的 lease authority 是其 `GroupReservationV1`/MemoryPlan capacity 的单一 writer；global router 无本地“影子容量”可直接接单。
- acquire 原子执行 generation/epoch/health/deadline 检查、资源 reservation、lease creation、accepted mutation；任一步失败均不 accepted。
- retry 仅发生在 accepted 前，最多一次且保留 original deadline/budget；换 replica 前必须持有上一 authority 的 durable `REJECTED/FENCED_NO_ACCEPT` certificate。timeout/unknown 只查询原 authority或进入 fail-safe reconciliation；一旦 accepted，router 不换 replica、不重复 acquisition。
- replica unhealthy 立即拒绝新 lease；既有 lease 由该 generation drain 或显式失败。旧 generation ack/terminal 不能修改新 generation。
- accepted `AdmissionLease` 到期时，authority 先以原子 mutation 将其置为 `EXPIRING` 并禁止新 work、续租和跨 replica retry；随后由同一个 request terminal CAS 产生 `DEADLINE_EXCEEDED`（deadline 到期）或 `FAILED`（authority/generation 故障）。只有 matching GroupReservation、ExecutionTicket、collective/device fence 全部 resolve，且 terminal 已 durable 后，才可释放 reservation、写 `EXPIRED` 并发布 `admission_lease.expired`。TTL/本地时钟本身绝不能直接复用仍被 in-flight work 引用的容量。
- global/per-replica queue、inflight request、token/KV reservation 和 retry 均有 hard limit；过载用有界 429/503 表达。

| S7 | Router Inspector、equal-budget benchmark、rollback 和 packaging | S6 | UI, benchmark, release | independent demo + bundle |

## 8. Correctness and Invariants

### 8.1 Golden/differential

- DP off/unified 与 DP2 对至少 100 prompts 的 tokens、RNG key/counter、finish reason、error/terminal 100% 一致；其他请求到达/取消不得改变单请求 deterministic fixture。
- router policy golden fixture 固定 capacity/health/cache snapshots，候选过滤、score、tie-break 和 DecisionRecord digest 完全一致。
- lease protocol 对 duplicate/delayed/reordered acquire/release 返回幂等结果；accepted event identity 不重复。
- 条件 `v1.3-merged` functional 矩阵比较 GrammarSpec/`SpecTxnV1`、draft-target KV 与 leader commit，并验证 DP routing 不改变 sampling semantics；只有另行启用 `encrypted_tokens` capture tier 时才比较 R2 digest，二者证据和 outcome 不得合并。

### 8.2 Property/state invariants

- `accepted(request)` 当且仅当存在唯一 matching active/terminal `AdmissionLease`；一个 request 不会被两个 replica 接受。
- per-replica active reservation 总和不超过版本化 MemoryPlan；stale capacity snapshot 永不使 lease authority 超卖。
- accepted 前 retry ≤ 1；accepted 后 route target 不变；每个 accepted request 恰有一个 terminal。
- replica generation 单调；旧 generation 的 lease/heartbeat/terminal 不改变新 generation state。
- `EXPIRING` lease 不产生新 work/route attempt；其 reservation 在唯一 terminal durable 且全部 fence resolve 前仍计入容量，之后恰好释放一次。
- route/replica/lease/request mutation seq 单调且 causal parent 可解析；complete barrier 覆盖 router 与所有参与 replica。
- cache affinity 只影响排序，不绕过 health、deadline、capacity、fairness 或 hard limit。

### 8.3 Failure/stress matrix

| 场景 | 注入方式 | 必须结果 | 禁止结果 |
|---|---|---|---|
| 最后 slot 竞态 | N 并发 acquire | 恰好一个 accepted，其余 429/retry | 超卖/双 lease |
| snapshot 过期 | delay capacity feed | lease authority 拒 stale/full；router更新/拒绝 | 按旧容量接单 |
| replica 在 acquire 前退出 | kill target | 只有拿到旧 generation 的 `FENCED_NO_ACCEPT` certificate 后才至多换一次目标；否则 fail-safe 查询/对账 | outcome unknown 时改投、accepted event 无 lease |
| acquire commit 后 ack 丢失 | drop response | router 查询原 authority并取回同一 lease/accepted result | 第二 replica accepted |
| replica 在 acquire 后退出 | kill after barrier | 已 accepted 请求唯一失败/按 drain完成 | 透明迁移/双 terminal |
| accepted lease 到期且 work in flight | advance authority deadline + delay device/collective fence | 先 EXPIRING/停止新 work，唯一 DEADLINE_EXCEEDED/FAILED，fence 后恰好释放一次 | 跨 replica retry、TTL 直接复用容量、双 terminal |
| router 在 accepted ack 前退出 | kill router | 重启后查询同一 idempotent lease/result | 第二 replica 再接单 |
| health flap/旧 heartbeat | reorder generations | 旧消息被 fence；新 lease只到 ready generation | replica 复活 |
| affinity hot key | burst same prefix | hard capacity/fairness 优先，可见 miss/reroute/reject | 单 replica OOM |
| exporter/reducer stall | block observability | data path bounded运行或拒绝 | 无界 event queue |

## 10. Performance Hypothesis

### 10.1 本版本性能立场

验证 DP2 在相同总 GPU、模型、workload 与 SLO 下是否提升 request goodput。正确性/lease/fault/overload 门不可放宽。若只有性能 no-go，仍发布 functionally-qualified `v2.1.0`，但 DP 保持 `experimental`、默认 off，V2.0 unified/TP 默认；只有 success 才可把 DP support 标 stable/default eligible。

Registry 口径：`illm.server.ttft.request_weighted.p99.v1` 分母为 accepted 且产生首 token 的请求；`illm.server.itl.token_weighted.p99.v1` 分母为相邻输出 token intervals；`illm.client.e2e.request_weighted.p99.v1` 分母为 accepted 且 terminal 的请求；`illm.request.terminal.failure_rate.accepted_request_weighted.v1` 分母为 accepted requests；`illm.request.reject.rate.admission_attempt_weighted.v1` 分母为 admission attempts；`illm.dp.cache_affinity.hit_rate.eligible_route_attempt_weighted.v1` 分母为有可复用 prefix 的 route attempts。replica skew 统一使用 `illm.dp.replica_load.skew_ratio.v1`，显存峰值使用 `illm.gpu.memory.peak_bytes.v1`。

## 11. Compatibility and Migration

### 11.1 Compatibility matrix

| Artifact | 读取上一版本 | 写入格式 | Breaking 条件 | 迁移/降级 |
|---|:---:|---|---|---|
| config | 是 | V2 config + optional `dp/router` | DP off 时 V2.0 配置直接可用 | 关闭 DP 使用单 replica |
| public API/CLI | 是 | API v1 + DP operator CLI | generation payload不变 | 旧客户端无需修改 |
| event/capture | 是 | route/replica/lease/barrier events | seq/schema ID 不复用 | V2.1 reader读V2.0；旧reader忽略未知 |
| model/weight manifest | 是 | 每 replica 复用 V2.0 manifest | identity不同不可同一 pool | 各 replica 从 canonical weights冷载 |
| cache/graph artifact | 仅同 replica identity | 加 replica/generation namespace | replica/generation/TP/config变化 | 丢弃并冷建，不跨 replica移动 |
| route policy/state | 否 | policy ID + DecisionRecord schema | policy语义/score变化 | 关闭DP；capture只读保留 |
| optional v1.3 functional profile | 否 | 独立 `v1.3-merged` manifest | SamplingSpec/GrammarSpec/`SpecTxnV1`/draft-target KV/leader-commit digest 改变 | 关闭 functional profile，回 SamplingSpec v1 |
| optional R2 capture tier | 否 | `v1.3-merged + encrypted_tokens` manifest | functional identity、capture mode、encryption/retention 或 R2 digest 改变 | functional profile 可保留，但 capture 降为 R1 |

### 11.2 Rollback

- 先关闭新 DP admission；选定一个已 qualification unified/TP replica 接收新请求，容量不足明确 429。
- router 对其他 replica bounded drain；accepted 请求在原 target 完成或显式 terminal，不迁移 KV/stream。
- 完成 cross-replica snapshot barrier，释放 lease 并停止 router；丢弃 replica/generation-bound cache/graph，保留 canonical weights/capture。
- 使用 V2.0 binary/config 运行 doctor、20-request canary 和 terminal/lease digest检查；不复用未 drain 的 router journal。
- 回退 optional profile 时先停止新的 `SpecTxnV1` admission并 drain；撤销 `encrypted_tokens` tier 只停止敏感 capture、按保留策略清理密钥/数据并降为 R1，不得把 capture-tier 变化伪装成 functional rollback。

## 13. Known Limitations

- 仅单机同构 DP replicas；不支持跨节点 discovery、network partition 或 autoscaling。
- cache affinity 使用摘要且不共享 KV；可能 miss 或为容量/fairness主动放弃 hit。
- accepted 后不迁移请求或 KV；replica failure 对已 accepted 请求可见。
- performance no-go 时 DP 仍是 experimental/default off；v2.1 版本号不代表默认开启。
- v1.3 advanced generation 仅条件 integration profile，不是 V2.1 硬依赖。

### 13.1 下一版本输入

- V3.0 在 global acceptance 时除 `AdmissionLease` 外同时原子取得 `FutureDecodeCredit`，不得复用 check-then-accept。
- V3.0 复用 replica health/capacity/DecisionRecord，但将统一 replica 内执行拆成 Prefill、transfer 与 Decode 服务。
- V3.0 必须保留 unified/TP 路径；P/D 性能收益单独 qualification，不能由 DP goodput外推。
