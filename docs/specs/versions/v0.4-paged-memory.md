## 1. 本版本学习目标

### 1.1 必须掌握

- 解释逻辑 token 地址、物理 KV page、page table、页内碎片与 contiguous reservation 浪费。
- 实现 `reserve → commit_allocation/rollback → begin_write → commit_write/abort_write → release`，并证明总页数守恒。
- 区分 allocation 已提交与 device write 已可见，理解 reader/writer fence、lease 和 `pending_free`。
- 用显式 `KVLayoutSpec` 和 homogeneous `AttentionPlanV1` 约束 dtype、strides、GQA、position、block table 与 valid mask。
- 通过 `PageHandle{allocator_instance_id, page_id, allocation_epoch}` 防止 allocator restart 与地址复用后的 ABA；旧 handle 即使 page_id/epoch 碰巧相同也必须失效。
- 用 contiguous reference gather 验证 paged layout，而不是在本版追求 fused kernel 性能。

### 1.2 建议先修

- 已完成 v0.3 continuous batching、纯 scheduler、hard admission、cancel/terminal race 和固定 workload trace。
- 理解分页、事务 rollback、generation handle、引用生命周期、CUDA event/stream 与 property-based state machine。
- 能用 v0.3 contiguous KV oracle 复现逐步 logits、token、terminal、RNG 和 stream transcript。

### 1.3 进入门槛与预热实验

- 预计用时 30～45 分钟；全部预热先在 CPU-only allocator/reference attention 上完成。
- 门槛：`v0.3.0` release bundle 完整，contiguous oracle 在同一环境连续 5 次结果一致，模型/权重/采样 manifest digest 已冻结。
- 预热 A：用 16 个逻辑 token 和 4-token page 手算 `logical_token → page entry → slot`，覆盖 3/4/5 token 边界。
- 预热 B：写 CPU-only allocator model，随机执行 100 次 reserve/commit/rollback/release，并在每步检查守恒。
- 预热 C：制造 page_id 立即复用，证明只比较 page_id 会误接受 stale handle，而比较 allocation epoch 会拒绝。
- 任一预热失败都先修复为最小回归 fixture；不得把不清楚的 ownership 直接带入 GPU path。

### 1.4 Teach-back 产物

- `release/v0.4.0/teach-back.md`：用两个请求的 page-grid 解释 reserve、allocation commit、write commit、release 和 epoch 变化，并演示 stale `PageHandle` 被拒绝。

## 3. Scope

### 3.1 本版本新增

- 启动时一次性预分配 per-layer fixed page pool；page size/layout/dtype/alignment 由 `KVLayoutSpec` 冻结。
- transactional allocator、per-request page table、partial-page append、allocation/device validity 分离。
- `PageHandle(allocator_instance_id, page_id, allocation_epoch)`；allocator instance 每次 pool/process generation 唯一，每次 page 从 owned/pending-free 回到 free 时 epoch 单调递增，溢出必须 fail-stop。
- homogeneous paged Attention ABI 和 correctness-oriented reference gather backend。
- `KVWriteLease`、`DeviceBufferLease`、`WorkspaceLease`、`CompletionFence`、`pending_free` 回收队列。
- page transaction/snapshot R0 events，以及 page use、fragmentation、stale-handle rejection 指标。

### 3.2 本版本保持不变

- v0.3 public facade、hard admission、bounded queue、FCFS + aging、两个同质 execution groups。
- prompt 仍在一个 full-prefill group 完成；单次 invocation 只含 prefill 或 decode，不 mixed、不 chunked。
- fixed model/weights/SamplingSpec、per-request RNG、terminal arbitration 与同步 step/resolve。
- contiguous KV path长期保留为 oracle和回退路径。

### 3.3 Feature flags 与 fallback

| 能力 | 默认值 | Reference/fallback | 失败时行为 |
|---|---|---|---|
| `kv_cache.mode` | gate 后 `paged` | `contiguous` | 仅 engine 启动时回退；manifest 记录选择 |
| `attention.backend` | `paged_reference_gather` | contiguous reference | capability 不支持则副作用前 fail closed |
| `kv_cache.poison_free_slots` | test on/release off | off | 只诊断，不改变输出 |
| `kv_cache.validate_epoch` | `on`且不可关闭 | 无 | stale/overflow/corruption 使 worker fail-stop |
| `telemetry.profile` | `metrics` | engine/request/off | 关键事务丢失则 capture incomplete |

## 4. Non-goals

- recompute/copy/swap preemption、victim policy、`PREEMPTED` 状态或恢复语义。
- chunked prefill、mixed prefill/decode plan、dynamic chunk size。
- prefix index、跨请求 KV sharing、cache owner、cache eviction。
- optimized paged-attention Triton/CUDA kernel、compile/graph/overlap。
- R1 reducer、交互式 KV Cache Explorer、R2/R3。
- runtime 读取 free CUDA memory 后热扩/缩 pool；capacity 只来自 immutable `MemoryPlan`。

任何新增需求若改变 Non-goals、公开候选契约或 DoD，必须提交 amendment/ADR。

## 5. Architecture Delta

### 5.1 相对上一版本的变化

```text
v0.3: request → contiguous max-length KV slot → homogeneous attention
v0.4: request → PageTable(logical range)
                  → PageHandle(allocator_instance_id, page_id, allocation_epoch)
                  → fixed PagePool → homogeneous paged reference attention
                  → fence-safe pending_free → epoch++ → FREE
capacity pressure: defer/reject (unchanged; no victim selection)
```

### 5.2 新增或修改的模块

| 模块 | 变化 | 责任边界 | 禁止事项 |
|---|---|---|---|
| `kv_cache.allocator` | add | fixed pool、transaction、epoch、守恒、reclaim | 选择 victim/请求优先级 |
| `kv_cache.page_table` | add | logical range 到 epoch handle/slot 的版本化映射 | 执行 attention |
| `domain.kv_layout` | add | layout identity/capability contract | 读取 runtime tensor 猜 layout |
| `backends.attention.paged_reference` | add | 按 plan gather并计算 | 猜 position/mask/head mapping |
| `scheduler` | change | 按 free-page snapshot产生 reservation intents | 直接 mutation allocator |
| `engine/executor` | change | validate、lease、launch、resolve、rollback | fence 前复用地址 |
| `observability` | change | 记录 page transaction/epoch事实 | 从最终 snapshot 补造事务 |

### 5.3 数据流与状态迁移

```text
plan(snapshot, free_pages)
→ validate allocator/page-table versions
→ reserve(PageHandle candidates)
→ commit_allocation or rollback all
→ begin_write(token range, lease)
→ launch homogeneous reference paged attention + fence
→ resolve
   ├─ success: commit_write → publish valid range/output
   ├─ cancel: suppress output → abort pending range
   └─ error: abort/invalidate → explicit terminal/fail-stop
→ last reader/writer fence resolves
→ detach owner → pending_free → allocation_epoch++ → FREE
```

allocation state、device validity 与 lease/fence 三组状态正交。epoch 在进入 FREE 的线性化点递增，`PageHandle` 的任一使用必须同时验证 page_id、epoch、allocator instance 和 expected table version。

## 6. Contracts

### 6.1 API/CLI contract

- v0.3 generation/stream/error/admission 对客户端保持兼容；paged 细节只经 metadata/metrics/capture/inspect 暴露。
- `--kv-cache paged --page-size-tokens N` 只接受 capability manifest 声明值；不支持值在 ready 前失败。
- paged/contiguous 对同一 accepted request 的 token、terminal、actual seed、`next_output_position`、`rng_draws_consumed`、committed counter-address 集和 transcript 相同。
- pool 不足时仅 `DEFERRED_KV_CAPACITY`，达到既有 hard admission watermark 才拒绝；不得释放别的 request 页面。
- stale/unknown handle 返回结构化内部错误并 fail-stop 受影响 worker，不能重新绑定到当前 page owner。

### 6.2 Config/manifest contract

| 字段/对象 | V0 成熟度 | 兼容规则 |
|---|---|---|
| `KVLayoutSpec` | `format_frozen_for_v0` | axes/strides/page size/alignment/dtype/layers/KV heads/head_dim任一变化使 identity 失效 |
| `MemoryPlan` | `candidate` | 记录非KV reserve、usable KV bytes、page count/headroom；run内immutable |
| `PageHandleV1` | `format_frozen_for_v0` | `{allocator_instance_id,page_id,allocation_epoch}`完整比较；不可只比较page_id |
| `PageTableVersion` | `candidate` | attach/detach/append单调增加；stale plan不得commit |
| `AttentionCapabilities` | `candidate` | 显式声明dtype/head_dim/page size/homogeneous；mixed=false |

`allocation_epoch` 使用无符号 64-bit；每次 page 进入 FREE 前检查加一，达到最大值启动受控 drain/fail-stop，禁止 wrap-around。

### 6.3 Event/capture/replay contract

- 新增 `kv.page_reserved/allocation_committed/write_started/write_committed/write_aborted/page_released/snapshot/stale_handle_rejected`。
- 每个事件保存 allocator instance、page_id、allocation_epoch、expected/actual table version、token range和reason；不保存K/V。
- `page_released` 的 post-state epoch 是下一 allocation 可见 epoch；旧 epoch 事件不得被新 owner 解释为同一 allocation。
- R0 viewer可播放事务；snapshot只是诊断事实，不是R1 checkpoint。关键事件drop则bundle标`incomplete/non_replayable`。

### 6.4 资源、并发与失败 contract

- 总页数守恒；每页恰处于 `FREE|RESERVED|ALLOCATED|PENDING_FREE` 一态，reservation全commit或全rollback。
- 每个 exclusive allocated page 恰有一个 request owner；本版不存在 cache owner、共享 request lease或eviction。
- logical ranges单调无重叠；每个 committed token恰映射一个相同epoch的page/slot。
- `valid_tokens`只在writer fence成功后增加；pending/unused slot永不进入attention valid set。
- 最后reader/writer fence前地址不得进入FREE；进入FREE时epoch加一后才可再次reserve。
- homogeneous `AttentionPlanV1` 显式携带query/context/sequence length、absolute position、block table(epoch handles)、write slot、mask、GQA map、scale。
- backend fallback在reserve/write/RNG副作用前完成；运行中不转换active KV layout。

## 8. Correctness and Invariants

### 8.1 Golden/differential

- contiguous/paged逐prefill和decode step比较logits tolerance、selected token、terminal、RNG与transcript。
- ABI覆盖GQA、长度1、page_size±1、多页、partial page、非连续page_id、padding poison与absolute position。
- reference gather从page table重建连续K/V，与v0.3逐层比较。
- 同page_id不同epoch的handle必须一律失败；当前epoch handle在相同fixture成功。

### 8.2 Property/state invariants

- allocator总页数守恒，无double-free、dangling handle、half commit或双owner。
- page table range/slot/position正确；所有stored handle epoch等于allocator当前allocation epoch。
- valid range只随成功fence增长；失败/取消恢复step前值。
- last-use fence前不复用；FREE poison不影响有效输出并捕获越界。
- finite且capacity可满足的accepted trace forward progress；不可满足时有界defer/reject而非OOM。

### 8.3 Failure/stress matrix

| 场景 | 注入 | 必须结果 | 禁止结果 |
|---|---|---|---|
| reservation partial failure | 第k页失败 | 全rollback，版本/页数恢复 | half commit/leak |
| writer failure | ticket error | abort pending，明确terminal | valid_tokens增加 |
| cancel partial page | append后cancel | 旧valid保留，fence后回收 | 覆盖旧K/V |
| delayed reader | 双stream延迟fence | pending_free等待 | 地址早复用 |
| ABA reuse | 保存old handle后释放重分配 | epoch不同，old handle拒绝 | old handle访问new owner |
| epoch overflow | 注入MAX epoch | drain/fail-stop | wrap为0 |
| unsupported layout | probe拒绝 | 副作用前fallback/fail closed | 静默cast/transpose |
| pool exhausted | 固定小pool | defer/reject reason | victim/preemption/OOM |

至少执行1,000条state-machine sequence和100次fault injection；失败seed固化为fixture。

## 11. Compatibility and Migration

### 11.1 Compatibility matrix

| Artifact | 读取v0.3 | 写入格式 | Breaking条件 | 迁移/降级 |
|---|:---:|---|---|---|
| config | 是 | additive layout/page fields | layout缺失/不支持 | 明确选择contiguous或fail closed |
| API/CLI | 是 | facade不变，KV inspect增加 | token/terminal变化 | contiguous回到v0.3 |
| event/capture | R0是 | additive page/epoch events | epoch语义变化 | 旧capture不伪造page |
| manifest | 是 | run manifest绑定layout/MemoryPlan | digest/layout变化 | reload并重建pool |
| runtime KV | 否 | 仅进程内 | binary/plan/layout变化 | drain后销毁重建 |

### 11.2 Rollback

- 关闭paged必须停止admission、drain、等待所有fence、验证无pending_free，再销毁pool并以contiguous重启。
- active request不能在线把page table合并为contiguous；只允许正常drain或显式失败/重试。
- rollback bundle保存allocator invariant snapshot、所有page/epoch/fence和最后schedule plan。
- rollback不迁移任何KV；model/weights只在digest相同且v0.3支持时复用。

## 13. Known Limitations

- paged attention是correctness reference，可能慢于成熟fused kernel。
- 无preemption；pool不足仍defer/reject，可利用率尚受活跃request持页影响。
- 无chunked prefill，长prompt仍阻塞decode。
- 无prefix sharing；每页只属一个request，terminal后释放。
- page events仅R0，不能任意checkpoint重建状态。
- 单进程单GPU同步core，无compile/graph/overlap。

### 13.1 下一版本输入

- v0.4 allocator/page table/epoch/lease/fence成为v0.5 preemption的不可破坏基线。
- pool exhausted与长history压力trace作为v0.5 victim/liveness实验输入。
