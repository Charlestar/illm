> V0.1 第一次执行真实 Transformer。目标是获得可信、可逐 op 定位的同步 reference runner；本版故意不做 KV cache、streaming 和 batching。

## 1. 本版本学习目标

### 1.1 必须掌握

- 能说明 embedding、RMSNorm、RoPE、GQA attention、MLP、LM head 的 tensor shape 与数据流；
- 能把固定模型 config 规范化为 `SupportedModelSpec`；
- 能从 safetensors 生成可审计 `WeightLoadManifest`，并验证 fusion/transpose/tied weights；
- 能逐层比较 reference runner 与 Transformers oracle，并定位首个 divergence；
- 能实现版本化 `SamplingSpec` 与每请求 counter-based RNG。

### 1.2 建议先修

- V0.0 的 domain/event/replay/evidence 规则；
- PyTorch inference、矩阵乘法、softmax、FP32/FP16/BF16 基础；
- decoder-only Transformer 与 tokenizer 基础。

### 1.3 进入门槛与预热实验

| 预热实验 | 命令/材料 | 通过标准 | 预计时间 |
|---|---|---|---:|
| Tensor shape walk | 只用 PyTorch 实现 `[B,T,H] @ [H,3H]`，拆 Q/K/V 并写 shape assertions | 能在纸上和测试中解释 batch、sequence、head、head_dim | 2 h |
| 单层 decoder micro-lab | 用仓库 tiny weights 跑 embedding→norm→attention→MLP，不生成文本 | 每个中间 tensor 有 shape/dtype/finite assertion | 3 h |
| Canonical sampler | 对手写 8-token logits 实现 greedy、top-k、top-p 和一个 Philox test vector | tie、边界 CDF、非法参数结果与 fixture 完全一致 | 2 h |

术语和缩写见[统一学习术语表](../GLOSSARY.md)。三个 micro-lab 是学习门槛，不扩大 V0.1 release Scope。

### 1.4 Teach-back 产物

- `teach-back-v0.1.md`：画出一个 token 经过一层 decoder 的 shape 变化；
- 对一个故意转置错误的权重，演示如何定位首个不一致 op。

## 3. Scope

### 3.1 本版本新增

- tokenizer adapter 与固定输入规范；
- dense decoder-only reference module；
- exact model config whitelist 与权重映射；
- full-context、无 KV 的同步 `Engine.generate()`；
- greedy、temperature、top-k、top-p sampling；
- model/op/sampling 事件与静态模型摘要。

### 3.2 本版本保持不变

- V0.0 的 event envelope、capture 完整性、R0 playback、error registry；
- 领域层仍不依赖 Transformers；Transformers 只作为测试 oracle；
- exporter failure 不得改变生成结果。

### 3.3 Feature flags 与 fallback

| 能力 | 默认值 | Reference/fallback | 失败时行为 |
|---|---|---|---|
| model backend | `illm_eager` | Transformers oracle 仅测试 | unsupported spec fail closed |
| sampling | greedy | canonical CPU/PyTorch sampler | unsupported parameter 返回错误 |
| dtype | fixture=FP32, real=BF16/FP16 | FP32 debug | 超出 tolerance 不发布 |
| telemetry | request | metrics/off | 输出不得变化 |

## 4. Non-goals

- KV cache、prefill/decode 分离、streaming/cancellation；
- variable batch、continuous batching、paged attention；
- compile、CUDA Graph、Triton/CUDA 自定义 kernel；
- 支持第二模型 architecture、量化、LoRA、多模态；
- OpenAI-compatible HTTP API 或交互式 Web UI。

```text

         → SAMPLING → RUNNING_FULL_FORWARD ... → FINISHED
         ↘ FAILED（validation/numerical/internal）
```

每生成一个 token 都重新执行完整上下文，这是本版有意保留的正确性基线。

## 6. Contracts

### 6.1 API/CLI contract

- `GenerationRequest` 必含 model config、input text/token IDs、max new tokens、`SamplingSpec`；
- 空输入由 input contract 注入明确 BOS 或返回 `INVALID_ARGUMENT`；
- 未实现 sampling 参数返回 `UNSUPPORTED_SAMPLING_PARAMETER`；
- `Engine.generate()` 返回完整 token IDs、finish reason、actual seed 和 timings；不提供 streaming；
- accepted request 恰好一个 FINISHED/FAILED terminal outcome。

### 6.2 Config/manifest contract

| 字段/对象 | 稳定性 | 兼容规则 |
|---|---|---|
| `SupportedModelSpec v1` | format_frozen_for_v0 | canonical JSON 决定 spec_id；到 V1.0 才成为 public stable |
| `WeightLoadManifest v1` | format_frozen_for_v0 | tensors 全覆盖，weights_digest 唯一；到 V1.0 才成为 public stable |
| `SamplingSpec v1` | format_frozen_for_v0 | processor 顺序、dtype、RNG algorithm/version 固定；到 V1.0 才成为 public stable |
| tokenizer/input contract | experimental | revision/template 进入 input identity |

`SupportedModelSpec` 至少固定 architecture、vocab/hidden/intermediate size、layers、Q/KV heads、head_dim、Norm epsilon、activation、bias、RoPE、weight tying、max positions、dtype/layout。

`SamplingSpec v1` 的 canonical 语义不得只靠 backend 默认值：

```yaml
schema_version: 1
mode: greedy | sample
temperature: float       # greedy=0；sample 必须 >0
top_k: int               # 0 表示关闭
top_p: float             # 1.0 表示关闭；范围 (0, 1]
compute_dtype: fp32
processor_order_version: 1
rng_algorithm: philox4x32-10
rng_contract_version: 1
actual_seed: uint64
```

- `greedy` 要求 `temperature=0, top_k=0, top_p=1.0`，直接对 FP32 raw logits 做 argmax，tie 选择最小 token ID且不消耗 RNG；带冲突 sampling knob 的请求 fail closed。
- `sample` 固定执行 `FP32 logits → temperature → top-k → softmax → top-p → retained-set renormalize → one uniform draw`。`temperature` 必须有限且 `>0`；`top_k=0` 表示关闭，否则按 score 降序、token ID 升序打破 tie，保留前 `min(top_k, finite_candidate_count)` 个。
- 令 top-k 后候选为 `K`、FP32 score 为 `s_i`、`m=max(s_i)`。只按 token ID 升序计算 `w_i=exp_fp32(fp32(s_i-m))`，再用 FP64 按同一顺序求 `Z=sum(fp64(w_i))`；冻结 `p_i=fp32(fp64(w_i)/Z)`，随后按 token ID 升序用 FP64 求 `T=sum(fp64(p_i))`，top-p 的输入概率固定为 `r_i=fp64(p_i)/T`。`Z/T` 必须有限且 `>0`。
- `top_p` 合法域为 `0<top_p<=1`；`top_p=1.0` 保留整个 `K`。否则按 `(r_i descending, token_id ascending)` 排列，以 FP64 按该顺序累加并把最后一个累计值规范化为 `1.0`，保留累计概率第一次达到 `top_p` 的最小非空前缀。
- retained set 只按 token ID 升序用 FP64 求 `S=sum(r_i)` 并定义 `q_i=r_i/S`；再按 token ID 升序构造半开 CDF，最后一个正概率 token 的累计值强制规范化为 `1.0`。uniform 选择唯一第一个满足 `u < cumulative_probability` 的 token；不得使用 backend 私有 reduction/tie/CDF 顺序替换这些步骤。
- 任一 raw logit 为 NaN/±Inf、筛选后没有有限候选、参数越界或 normalization 非有限时返回 `NUMERICAL_ERROR`/`INVALID_ARGUMENT`，不能任意选 token。
- `actual_seed` 规范化为 little-endian `uint64`，直接拆成 Philox key `k0=low32(seed), k1=high32(seed)`。逻辑 draw identity 为 `(absolute_output_pos:uint64, draw_kind:uint32, draw_index:uint32)`，按 little-endian 打包到 128-bit counter；v1 token draw 固定 `draw_kind=0, draw_index=0`。
- 每个 counter 只消费 Philox 输出 lane 0；`uniform = lane0_uint32 × 2^-32`，范围 `[0,1)`。CDF 使用 retained FP32 probabilities、按确定 token order 以 FP64 累加，并选择第一个满足 `uniform < cumulative_probability` 的 token。known-answer vectors 冻结 key/counter bytes、四个 lanes、uniform、候选排序、selected token 和 next logical position。
- request state 分开保存 `next_output_position` 与 `rng_draws_consumed`/已提交 counter-address 集。前者从 0 开始并随每个 committed output token 加一；后者只在一次随机 draw 所选择的 token 同时 commit 时增加，并记录对应 `(absolute_output_pos, draw_kind, draw_index)`。greedy 只推进 `next_output_position`，其 draw count 为 0、address 集为空；不能再用单个“RNG counter 等于输出数”表达两种状态。

### 6.3 Event/capture/replay contract

- 新增 `model.forward/layer/attention/mlp`、`sampling.started/selected/failed`；
- V0.1 支持 R0；R1 只重建 request/model/sampling 控制状态，不数值重跑；
- R2 未启用，即使 capture 含输出摘要也不得声称数值重执行；
- 默认不保存 prompt/output，只保存长度、digest 和 selected token 的可选测试 fixture 标识。

### 6.4 资源、并发与失败 contract

- 一次仅允许一个 active request；
- model weights 在 engine 生命周期内只读；
- non-finite logits、无有限候选或非法 sampling 参数显式失败；
- CUDA/PyTorch OOM 使当前请求失败；V0.1 不尝试恢复或 admission；
- 所有 tensor 由同步 reference call 持有，不跨异步 stream 生命周期。

## 8. Correctness and Invariants

### 8.1 Golden/differential

- tiny FP32 对齐 embedding、每层 residual、attention、MLP、final norm、logits、selected token；
- 至少 20 个固定输入的 greedy token 与 Transformers 完全一致；
- real BF16/FP16 tolerance profile 在运行前冻结；
- 覆盖位置 0/1、RoPE 边界、vocab 边界、GQA mapping、tied embedding；
- canonical sampler 与 fast/vectorized 实现逐 token differential。

### 8.2 Property/state invariants

- `missing_keys/unexpected_keys/duplicate_keys` 全为空；
- 每份 canonical tensor storage 在 manifest 中精确覆盖一次；声明的 tied-weight group 可以有多个 parameter alias，但这些 alias 必须引用同一 storage range/checksum/digest，未声明 alias 或复制分叉均失败；
- greedy tie 选择最小 token ID且不消耗 RNG；
- SamplingSpec v1 的 processor order、top-k set、`exp_fp32` 权重、FP64 `Z/T/S` 顺序和、top-p retained set、规范化 CDF、Philox test vector 和 selected token 与 canonical fixture 完全一致；
- `next_output_position == committed_output_count`；`rng_draws_consumed` 等于已提交且不重复的 counter-address 数。greedy 的 draw count/address 集恒为 0；sample v1 每个 committed token 恰有 `(absolute_output_pos, 0, 0)` 一个地址，未 commit 结果不进入该集合；重复执行不受日志/telemetry 影响；
- accepted request 只有一个 terminal event。

### 8.3 Failure/stress matrix

| 场景 | 注入方式 | 必须结果 | 禁止结果 |
|---|---|---|---|
| 未知 config | 加 rope/bias 语义字段 | loader fail closed | 静默忽略 |
| 缺/重复权重 | 删除或复制 tensor | manifest 拒绝 | 带错误权重运行 |
| shape/layout 错 | 交换 QKV/transpose | 首个不一致 op 可定位 | 只报告最终 token 错 |
| raw non-finite logits | 在 processor 前注入 NaN/+Inf/-Inf | `NUMERICAL_ERROR` | 采样任意 token；后续版本把 canonical mask `-Inf` 误判为 raw error |
| OOM | 缩小 device budget | 请求失败、进程状态可诊断 | 半写 capture 标成功 |

### 11.2 Rollback

- feature flag 关闭 sampling，退回 greedy；
- real model 失败时退回仓库 tiny fixture，不能更换未固定的模型；
- model spec/weights/dtype 改变后禁止复用旧测试 oracle 或 capture 的数值结论。
- 完整回退到 V0.0 时，先停止 V0.1 process，安装固定 `v0.0.0` artifact/config，只运行 toy scheduler/replay；V0.1 权重、model/sampling manifest 与数值 capture 移到隔离 evidence 目录并保持只读，不能由 V0.0 解释。回退后明确失去真实模型、generate 和 sampling 能力。

## 13. Known Limitations

- 每 token 重跑完整上下文，复杂度与内存不代表真正 decode；
- 单请求、同步、无 streaming/cancel；
- 只支持一个精确 architecture/revision；
- R1 只回放控制状态，R2 未启用。

### 13.1 下一版本输入

- V0.2 引入 request lifecycle、prefill/decode 分离、contiguous KV、streaming 与 cancellation；
- V0.1 reference model/sampler 永久保留为 cache-off oracle；
- SupportedModelSpec、WeightLoadManifest 与 tokenizer/input identity 进入 reusable KV（后续 prefix）identity；`SamplingSpec` 只进入 request/capture/replay identity，不进入可复用 KV/prefix key。
