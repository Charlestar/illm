> V2.0 只解决“一个逻辑引擎如何在单机多个 GPU rank 上正确运行”。本版引入 Tensor Parallel（TP）、rank/collective 契约与 leader commit；不引入 Data Parallel、副本路由或跨节点服务。

## 1. 本版本学习目标

### 1.1 必须掌握

- 能解释 column/row parallel linear、attention head 与 vocabulary 分片何时需要 collective，以及 TP1/TP2 的显存、通信和延迟差异。
- 能从逻辑权重生成逐 rank tensor manifest，并区分 `partitioned(axis)`、`replicated`、`rank_local` 与 `tied_alias`。
- 能建立 `RankManifest` 和 `CollectivePlan`，保证所有 rank 以相同 sequence 执行 collective，失败时整个 group fail-stop。
- 能实现 leader-only admission、schedule 与 canonical sampling：leader 汇集 full logits，广播 provisional `SampleDecision`，收齐 all-rank ack 后才提交 token、RNG 和 terminal state。
- 能用单调 mutation sequence、causal parent 和 snapshot barrier 重建 rank/group/request 状态，定位 rank skew、collective stall 与通信占比。

### 1.2 建议先修

- 完成 V1.1，能解释 Paged KV、`AttentionPlan`、`MemoryPlan`、lease/fence、SamplingSpec v1、R0/R1 replay 与 held-out 实验纪律。
- 熟悉 CUDA stream/event、PyTorch distributed 或 NCCL 的 rank/process group/collective 基础，以及 PCIe/NVLink 拓扑。
- 能读懂目标模型的 attention、MLP、embedding、LM head tensor shape 和 tied-weight 关系。

### 1.3 进入门槛与预热实验

先用系统 Python 建立 CPU 学习环境：`python scripts/bootstrap.py --profile learning-cpu --locked --write-manifest out/v2.0-learning/toolchain.json`。此后预热命令只通过该 manifest runner 执行。

## 3. Scope

### 3.1 本版本新增

- 单机同构 GPU 的 TP1/TP2；TP4 只有在单独 qualification 后进入支持矩阵。
- column/row parallel linear、attention head 分片、vocabulary/embedding 分片与 tied alias；每个 tensor 显式声明 distribution。
- `RankManifest`：world/rank/local device/process/group generation、model/weight/config digest、device capability 与拓扑身份。
- `CollectivePlan`：静态 step identity、op、participants、shape/dtype/bytes、stream、dependency、timeout 与 sequence digest。
- leader-only request acceptance、逻辑 `SchedulePlan`、full-logits canonical sampling、provisional decision/all-rank ack/atomic commit。
- distributed events、rank clock calibration、entity mutation sequence、causal parent、snapshot barrier、R1 state replay 与 TP Inspector。

### 3.2 本版本保持不变

- V1.1 generation API、stream/terminal/error、SamplingSpec v1、Paged KV、prefix namespace 和单请求语义。
- TP1 eager/full-context、unfused reference kernel 与 V1 single-GPU engine 保留为 oracle/fallback。
- 一个 accepted request 只有一个 terminal outcome；不支持参数、模型、dtype 或拓扑一律 fail closed。
- 调度与 sampling 是一个逻辑 group 的行为，非 leader rank 不能独立 admission、排队、选 token 或推进 RNG。

### 3.3 Feature flags 与 fallback

| 能力 | 默认值 | Reference/fallback | 失败时行为 |
|---|---|---|---|
| `parallel.tp_degree` | `1` | V1.1 unified TP1 | TP2 capability/manifest 不通过则启动失败，不在线变 degree |
| `tp.collective_backend` | `nccl` | deterministic CPU simulator 仅 CI | release 环境初始化失败则 readiness false |
| `tp.canonical_sampling` | `leader_full_logits` | TP1 reference sampling | 不允许 shard-local sampling |
| `tp.snapshot_barrier` | `true` | 无关闭路径 | barrier 不完整则 capture 标 incomplete，R1 不声称完整 |
| `parallel.dp_degree` / `router` | unsupported | 无 | schema 拒绝；留给 V2.1 |

## 4. Non-goals

- Data Parallel、TP×DP、global router、cache affinity、replica health/admission/capacity；全部属于 V2.1。
- 多节点、Prefill/Decode 分离、KV 网络传输、pipeline/expert/sequence parallel。
- MoE、多模态、LoRA、量化、异构 GPU、运行中 reshard 或 elastic world size。
- 在 rank 之间做 shard-local/top-k approximate sampling；本版 canonical path 必须得到 full logits。
- 以 TP 性能成功替代 correctness、fault 或 replay 门；通信优化不得删除 TP1/reference path。

## 5. Architecture Delta

### 5.1 相对上一版本的变化

```text
V1.1: API → one Engine/Scheduler → one GPU

V2.0: API → TP Leader ── one logical SchedulePlan ─┬→ rank 0 local ops ─┐
                                                   └→ rank 1 local ops ─┤ collective sequence
                                                                       ↓
                                             leader gathers full logits
                                               → provisional decision
                                               → all-rank ack
                                               → atomic visible commit
```

### 5.2 新增或修改的模块

| 模块 | 变化 | 责任边界 | 禁止事项 |
|---|---|---|---|
| `parallel/tensor_manifest` | add | logical tensor 到 per-rank tensor/alias 映射 | 用名字猜 axis 或复制策略 |
| `parallel/rank_runtime` | add | rank 生命周期、generation、heartbeat、local execution | 非 leader 接收公开请求 |
| `parallel/collective_plan` | add | 构建/验证确定性 collective sequence | kernel 临时插入未声明 collective |
| `parallel/tp_coordinator` | add | group admission、plan broadcast、barrier、fail-stop | 维护第二份 scheduler 真相 |
| `sampling/leader_commit` | add | full logits、provisional decision、ack、atomic commit | ack 前推进 token/RNG/terminal |
| `observability/distributed` | change | sequence、causal link、barrier、rank spans | 用 wall clock 猜权威顺序 |

### 5.3 数据流与状态迁移

```text
leader commits GroupReservationV1 → ACCEPTED (继承的本地唯一 accepted point)
  → plan(epoch, step) broadcast → all ranks validate
  → local compute / CollectivePlan[n]
  → leader assembles full logits → canonical sampler creates PROVISIONAL SampleDecision
  → decision broadcast → every live rank validates/applies provisional local state → ACK
  → leader receives all-rank ACK → COMMIT(token, RNG counter, terminal?)
  → commit broadcast → next step or exactly one terminal outcome
```

- V2.0 复用 V0.3 的本地 reservation/accepted 原子事务，并把 capacity 扩展到整个 TP group，命名为 `GroupReservationV1`；它覆盖 group queue slot、各 rank token/KV reservation 与 request identity。它不是跨 replica、可恢复的 `AdmissionLease`，后者到 V2.1 才引入。
- leader 是 request、sampling 与 terminal 的唯一权威 writer；各 rank 的 local mutations 仍各有单调 `entity_mutation_seq`，并通过 `causal_parent=(leader_event_id, plan_epoch, step_id)` 关联。
- snapshot barrier 在 leader 发起，记录每 rank 的 last applied mutation seq、plan/collective step、allocator digest 和 RNG provisional/committed counter；任一 rank 缺席则 R1 snapshot 不完整。

## 6. Contracts

### 6.1 API/CLI contract

- 公开 generation API 与 V1.1 兼容；debug metadata 可显示 `tp_degree/group_id/group_generation`，不得泄露内部地址。
- `illm tp doctor` 验证 rank/device 唯一性、peer/NCCL capability、manifest/plan digest、端口和显存预算；失败时服务不 ready。
- 每个请求只在 leader 原子提交 `GroupReservationV1 + request.accepted` 时 accepted；之前容量不足为 429、group unavailable 为 503，之后只有一个 terminal。公开 request terminal enum 严格限定为 `FINISHED | CANCELLED | FAILED | DEADLINE_EXCEEDED`；collective、sampling、reservation 等内部状态不得作为 request terminal 输出。
- cancel/deadline 由 leader 转为 plan control record；所有 rank ack 后提交 terminal。rank failure 使整个 generation fail-stop，不将请求偷偷移到 TP1。

### 6.2 Config/manifest contract

| 字段/对象 | 稳定性 | 兼容规则 |
|---|---|---|
| `RankManifest` | stable | V2 major 内兼容；包含 world/rank/device/process/group generation 与所有 identity digest；全 rank 一致字段必须相等 |
| `TensorDistributionManifest` | stable | V2 major 内兼容；每个逻辑 tensor 的 `distribution` 只能是 `partitioned(axis=N)`、`replicated`、`rank_local`、`tied_alias(target=tensor_name)`；`N` 为已校验整数 axis |
| `CollectivePlan` | stable | V2 major 内兼容；step id/op/participants/shape/dtype/bytes/dependency/sequence digest 精确匹配；未知 op fail closed |
| `TopologyManifestV1` | stable | node/device UUID、link kind、rank/group mapping、capability 与 digest 固定；world size 在 process generation 内不可更改 |
| `GroupReservationV1` | stable | group leader 单一 writer；同一事务保留每 rank 容量并写 accepted，失败全部 rollback；不提供跨 replica retry/durability |
| `SamplingCommitRecord` | stable | 包含 logits digest、SamplingSpec/RNG before、provisional decision、ack set 与 committed digest |
| optional `v1.3-merged` functional profile | experimental | 非硬依赖；声明后才允许 SamplingSpec v2、GrammarSpec、`SpecTxnV1`、draft-target KV 与 leader commit 联合资格；不自动授予 R2 |
| optional `v1.3-merged + encrypted_tokens` capture tier | experimental | 只有 functional profile 已通过且 capture 明确 opt-in `encrypted_tokens`、密钥分离/保留策略和 exact identity 全通过时才可声明 R2 |

`v1.3-merged` 是条件 functional integration profile，不改变 `depends_on: [v1.1.0]`。未启用时 V2.0 只承诺 SamplingSpec v1；启用时所有 rank 必须报告同一 profile digest，GrammarSpec/`SpecTxnV1` 的 provisional/rollback 与 leader commit 使用同一 commit barrier。functional qualification 只证明生成语义，不代表 capture 含 token/p/q 或具备 numerical re-execution；R2 必须再声明独立的 `v1.3-merged + encrypted_tokens` capture tier 和 digest，默认 `metadata_only/equality_only` 仍最高 R1。

### 6.3 Event/capture/replay contract

- 新增 `tp.group_started/failed`、`rank.ready/heartbeat/failed`、`tp.plan_broadcast/acked`、`collective.enter/exit/timeout`、`sample.provisional/broadcast/acked/committed/aborted`、`snapshot.barrier_started/rank_reached/completed`。
- 每个可变实体事件必须携带 `(entity_id, entity_generation, entity_mutation_seq)`；权威 writer 对该实体 seq 严格递增且不复用。跨实体变化必须携带 `causal_parent_event_id`，不能靠时间戳推导因果。
- barrier completion 保存所有 rank 的 mutation watermark 和 state digest；R1 reducer 只能在连续 seq 或显式 snapshot 上声称 complete。
- CLI 必须保留 `illm replay CAPTURE_DIR --level R1 --mode state`；`CAPTURE_DIR` 是 capture 目录字面参数，`--mode state` 显示 reducer state/sequence/gap，不退化为只有 timeline。
- rank 时钟只用于 duration/skew；权威顺序来自 seq/causal parent/collective step，校准误差必须可见。

### 6.4 资源、并发与失败 contract

- group `MemoryPlan` 是所有 rank 权重、KV、workspace、collective buffer 和 admission headroom 的单一事实源；一个 rank 超预算即整个 config 不 ready。
- `GroupReservationV1` 的 commit 与 accepted transition 是同一权威事务；没有 reservation 的请求不能进入任一 rank queue。
- `CollectivePlan` step 只有 all-rank ready 才 launch；timeout 后 generation fenced，禁止剩余 rank 继续执行后续 collective。
- provisional `SampleDecision` 不可见且不可消费 RNG；仅 all-rank ack 后 leader 原子提交 token、RNG counter、finish reason，再广播 committed record。
- retry 不跨 group generation；accepted 请求遇 rank failure 显式失败。reservation/lease/fence cleanup 必须幂等并等待已 launch CUDA/NCCL work resolve。

## 8. Correctness and Invariants

### 8.1 Golden/differential

- TP1/TP2 对固定模型至少 100 prompts 比较关键 per-layer tensor、full logits、greedy tokens 与 finish reason；token 100% 一致，数值遵循固定 dtype tolerance profile。
- 每个 manifest tensor 的元素 coverage 恰好一次（replicated/tied alias 按语义计数）；missing、overlap、错误 axis 或 untied duplicate 均为 0。
- eager/unfused TP1、TP2 simulator、TP2 GPU 对相同 input/seed 产生相同 sampling commit digest；随机采样比较 RNG key/counter 与 selected token。
- `v1.3-merged` functional 条件矩阵额外比较 grammar mask、`SpecTxnV1` proposal/accept/rollback、draft-target KV transaction 与 leader commit；只有另行启用 `encrypted_tokens` capture tier 时才比较 R2 re-execution digest，二者证据和 outcome 不得合并。

### 8.2 Property/state invariants

- 一个 group generation 只有一个 leader、一个逻辑 `SchedulePlan`、一条 `CollectivePlan` sequence；非 leader acceptance/sampling/terminal mutation 数为 0。
- accepted ⇒ 存在唯一 active `GroupReservationV1`；reservation count/bytes 不超过各 rank `MemoryPlan`，terminal 后非 cache reservation/lease 最终归零。
- `committed_step=n` ⇒ 所有 rank 已 ack 同一 `(decision_digest,n)`；任何 ack 缺失时 token/RNG/terminal committed state 不变。
- 每实体 mutation seq 严格递增；每个非根 mutation 有已知 causal parent；complete snapshot 含所有当前 generation rank 的 barrier watermark。
- rank failure、collective timeout、manifest mismatch 后 generation 不再产生 data-plane commit；每个 accepted request 恰有一个 terminal。

### 8.3 Failure/stress matrix

| 场景 | 注入方式 | 必须结果 | 禁止结果 |
|---|---|---|---|
| tensor axis/alias 错误 | 修改 manifest digest | ready 前 fail closed | 部分权重加载后接单 |
| collective order 不同 | rank 插入/跳过 step | conformance 拒绝或 timeout fail-stop | 永久挂起、后续 commit |
| provisional 后 rank crash | kill rank before ack | generation fenced；token/RNG 未提交；请求唯一失败 | leader 单独继续 |
| commit broadcast 丢失 | 丢一个 rank 的消息 | 重发相同 committed record或 group fail-stop | 再采样/双推进 RNG |
| accepted 竞态 | 并发填满最后一个 slot | 仅 GroupReservation winner accepted，其余 429 | check-then-accept 超卖 |
| capture 丢 mutation | drop seq range | R1 标 gap/incomplete，可从下一 barrier 恢复 | 猜测缺失状态 |
| cancel 与 collective 完成竞态 | 随机 barrier 注入 | 唯一 terminal；fence 后释放 | double terminal/提前复用 |
| rank skew/slowdown | delay one rank | skew 可见，有界 timeout | 无限等待或 silent rank eviction |

## 9. Visualization Learning Story

### 9.1 本版本必须回答的问题

1. 一个逻辑 tensor 在各 rank 上是什么 shape、为什么分片或复制？

3. token 何时只是 provisional，何时经过 all-rank ack 成为对用户可见的 commit？
4. rank 故障时哪些 request、lease、collective 和 mutation 因果相连？

## 10. Performance Hypothesis

### 10.1 本版本性能立场

验证 TP2 能否在固定大模型/长上下文 fixture 上用可接受通信代价获得可运行容量。本版即使性能 no-go，只要 correctness、failure、replay 和独立 demo 全通过，仍可发布 functionally-qualified `v2.0.0`，但 TP2 保持 experimental/default off，TP1 默认；不得放宽正确性门。

Registry 口径：`illm.server.ttft.request_weighted.p99.v1` 分母为所有 accepted 且产生首 token 的请求；`illm.server.itl.token_weighted.p99.v1` 分母为所有相邻输出 token interval；`illm.client.e2e.request_weighted.p99.v1` 分母为所有 accepted 且 terminal 的请求；`illm.request.terminal.failure_rate.accepted_request_weighted.v1` 分母为 accepted requests；`illm.request.reject.rate.admission_attempt_weighted.v1` 分母为 admission attempts，reject 不计入 failure。TP 通信占比统一使用 `illm.tp.collective.device_time_share.v1`，显存峰值使用 `illm.gpu.memory.peak_bytes.v1` 并与 MemoryPlan limit 比较。

### 10.2 Experiment card


## 11. Compatibility and Migration

### 11.1 Compatibility matrix

| Artifact | 读取上一版本 | 写入格式 | Breaking 条件 | 迁移/降级 |
|---|:---:|---|---|---|
| config | 是 | V1 config + `parallel.tp_degree` | TP2 manifest/topology 必填 | 设 TP1 并使用 V1.1 config |
| public API/CLI | 是 | API v1 + TP operator CLI | generation payload 不变 | 旧客户端无需修改 |
| event/capture | 是 | distributed/rank/commit/barrier events | seq/schema number 不复用 | V2 reader 读 V1；旧 reader 仅看已知事件 |
| model/weight manifest | 是 | tensor distribution + per-rank digest | degree/axis/alias/model digest 改变 | 从 canonical weights 重新分片 |
| cache/graph artifact | 条件 | 含 TP degree/rank/plan digest | 任一 identity 改变 | 丢弃并冷建 |
| optional v1.3 functional profile | 否 | 独立 `v1.3-merged` integration manifest | 任一 SamplingSpec/GrammarSpec/`SpecTxnV1`/draft-target KV/leader-commit digest 改变 | 关闭 profile，回 SamplingSpec v1 |
| optional R2 capture tier | 否 | `v1.3-merged + encrypted_tokens` manifest | functional identity、capture mode、encryption/retention 或 R2 digest 改变 | 保留 functional profile但降为 R1；不可读取敏感 payload |

### 11.2 Rollback

- 停止新 acceptance，leader 以 bounded deadline drain；未完成请求得到明确 terminal，不跨 generation 迁移。
- 等待 collective/CUDA fence 与 snapshot barrier，关闭所有 rank；删除 TP-degree-bound KV/cache/graph 和 rank-local shard，不删除 canonical weights/captures。
- 启动 V1.1/TP1 binary 与 config，运行 reference smoke 和 20-request canary；容量不足通过 429，不超卖。
- 若 `v1.3-merged` 已启用，先 drain GrammarSpec/`SpecTxnV1` transaction，再回退 SamplingSpec v1；若只撤销 `encrypted_tokens` capture tier，停止新敏感 capture、按保留策略清理密钥/数据并降为 R1，不得影响已资格的 functional profile。二者都不影响基础 V2.0 rollback。

## 13. Known Limitations

- 仅单机同构 TP；不提供 DP/router、跨节点、elastic rank 或 P/D。
- canonical sampling 需要 leader full logits，可能有 vocabulary gather 开销；正确性优先于 shard-local 优化。
- rank failure 会使整个 group generation 和已 accepted 请求失败，不做透明重启/迁移。
- TP2 可能仅 functionally-qualified；若性能 no-go，默认仍是 TP1，TP2 为 experimental/off。
- V1.2/未来 V1.3 advanced generation 不作为硬依赖；只有 `v1.3-merged` 条件 profile 才承诺组合语义。

### 13.1 下一版本输入

- V2.1 在 TP group 之上增加独立 replica 与 global router：replica-local capacity 必须复用本版 `GroupReservationV1`，跨 replica 首次引入 durable `AdmissionLease` 与 retry fencing。
- V2.1 不得让 router 写 rank/group 内部状态；group 仍遵守 leader commit 与 fail-stop。
- 本版 per-group capacity、health、cache namespace 和 performance evidence 将成为 V2.1 路由事实源。
