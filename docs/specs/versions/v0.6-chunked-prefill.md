> 本版本只交付 M5a：fixed-size chunked prefill、decode-first reservation 和统一 mixed `AttentionPlanV2`。它解决长 prompt/recompute 对 decode 的阻塞，但不加入任何 prefix index、跨请求 KV sharing 或 cache eviction。

## 1. 本版本学习目标

### 1.1 必须掌握

- 解释长prefill如何形成head-of-line blocking，以及chunk size与TTFT/ITL/goodput的Pareto关系。
- 把prompt和preemption recompute history表示为可提交的chunk progress；失败/cancel不越过commit点。
- 每step先为eligible decode保留token，再用剩余compute-token budget调度prefill chunks。
- 构造同时含ragged prefill rows和`query_len=1` decode rows的`AttentionPlanV2`。
- 证明跨chunk/page边界时context length、absolute position、write slot、mask和GQA映射连续。
- 区分scheduler budget、planned query tokens、actually committed tokens和GPU padding，不以batch rows计费。

### 1.2 建议先修

- v0.5 preemption oracle、liveness、lease/fence/epoch与feature-off rollback全部通过。
- 理解ragged tensor/indptr、causal attention、token-budget scheduling、commit protocol与尾延迟分位数。
- 能用full-prefill reference跑同一long-prefill+decode workload并获取精确metric IDs。

### 1.3 进入门槛与预热实验

- 预计用时 30～45 分钟；无 GPU 时所有调度练习使用 deterministic CPU schedule-latency fixture。
- 门槛：v0.5 held-out中至少有一条长prefill或resume造成decode ITL尖峰的可复现真实 trace，且非telemetry artifact；若当前无 GPU，可用带固定虚拟 service time 的 CPU fixture取得 `learning_complete`，但该证据必须标 simulator，不能满足 GPU functional/performance qualification。
- 预热 A：手算prompt length 10、chunk size 4的`[0,4)、[4,8)、[8,10)`进度与position/write slots。
- 预热 B：在CPU scheduler中给3条decode各保留1 token，再用剩余budget选chunk，验证总query tokens不超预算。
- 预热 C：在第二chunk writer失败，证明progress仍停在第一chunk末且重试不跳position。
- 预热 D：构造ragged mixed rows并与分开执行prefill/decode的reference attention比较。

### 1.4 Teach-back 产物

- `release/v0.6.0/teach-back.md`：逐step解释“一条长prefill+两条decode+一条preempted resume”的budget、row、indptr、position、page write与commit，并画出chunk size Pareto。

## 3. Scope

### 3.1 本版本新增

- request `prefill_cursor/committed_context_tokens`和versioned chunk progress。
- fixed-size chunk selection；最后chunk可短于配置，禁止运行时自适应。
- 每step active-decode reservation、remaining-token-budget和waiting aging。
- `AttentionPlanV2`：ragged prefill/decode rows、query indptr、row type、position、block/write slots、valid mask。
- executor按token mask事务commit；padding/invalid row绝不推进KV/RNG/output。
- preemption resume history允许用相同chunk机制重建。
- chunk/mixed-plan R0 events、metrics与inspect。

### 3.2 本版本保持不变

- v0.4 paged allocator、KVLayoutSpec、PageHandle epoch、lease/fence与MemoryPlan。
- v0.5 victim policy/state/liveness以及output/RNG不回退contract。
- v0.3 hard admission、bounded queue、FCFS+aging主公平顺序和terminal arbitration。
- 无prefix index；所有page保持request-exclusive，terminal/preemption按既有规则释放。

### 3.3 Feature flags 与 fallback

| 能力 | 默认值 | Reference/fallback | 失败时行为 |
|---|---|---|---|
| `prefill.mode` | gate后`chunked` | `full` | capability不足则副作用前fallback/fail closed |
| `prefill.chunk_size_tokens` | fixture 8/GPU manifest固定 | full | ≤0或>step budget启动失败 |
| `scheduler.decode_reservation` | `one_token_per_eligible_decode_v1` | v0.5 homogeneous groups | unknown policy启动失败 |
| `attention.backend` | `mixed_reference_v1` | separate full/decode reference | ABI不支持则副作用前fail closed |
| `preemption.mode` | inherited | disabled | resume使用相同frozenprefill mode |

## 4. Non-goals

- PrefixIndex/NoPrefixIndex/Radix、prefix key、hit/reuse、cache owner或cache eviction。
- adaptive/dynamic chunk、deadline optimizer或online auto-tuning。
- reuse logits、hidden states或prompt logprobs缓存。
- 修改preemption victim policy或page ownership/epoch语义。
- optimized mixed/paged custom kernel、compile/CUDA Graph/overlap。
- R1 reducer/Web UI、R2/R3、multi-GPU。

## 5. Architecture Delta

### 5.1 相对上一版本的变化

```text
v0.5: step → homogeneous decode group + one full-prefill group
v0.6: snapshot
       → reserve 1 query token per eligible decode
       → fill remaining token budget with fixed prefill chunks
       → SchedulePlan{rows, chunk_ranges, budget, decisions}
       → mixed AttentionPlanV2{query_indptr, positions, block/write slots}
       → one transactional launch/resolve
       → commit each successful request range atomically
```

### 5.2 新增或修改的模块

| 模块 | 变化 | 责任边界 | 禁止事项 |
|---|---|---|---|
| `scheduler` | change | decode reservation、chunk ranges、budget与aging | allocator mutation/adaptive chunk |
| `domain.AttentionPlanV2` | V2 | 完整mixed/ragged execution ABI | 可变Python对象/backend推断 |
| `engine` | change | validate cursor/table versions、commit progress | 创建prefix/cache identity |
| `executor/attention` | change | mixed rows、token masks与transaction | 按row错误推进RNG |
| `kv_cache` | unchanged protocol | 为chunk预留/写page | 跨request sharing |
| `observability` | change | chunk/budget/plan事实 | 把padding当processed token |

### 5.3 数据流与状态迁移

```text
freeze Engine/KV snapshot
→ scheduler reserves decode tokens
→ choose fixed chunks from committed cursor within remaining budget
→ SchedulePlan(expected request/page-table versions)
→ validate → reserve pages → build AttentionPlanV2
→ begin_write(valid query ranges) → launch → fence → resolve
   ├─ success prefill: commit KV + advance cursor
   ├─ success decode: commit KV/output position/conditional RNG draw accounting
   ├─ cancel: suppress output + abort uncommitted ranges
   └─ error: abort affected ticket + explicit terminal/fail-stop
→ next step sees only committed cursors
```

同一request每step最多一个连续prefill range；`context_before + query_len = sequence_after`。preemption resume把history视为prefill source，但不重新采样或发布历史output。

## 6. Contracts

### 6.1 API/CLI contract

- public generation/stream/error与v0.5兼容；可选metadata报告`prefill_chunks/computed_prompt_tokens/recomputed_prompt_tokens`。
- full/chunked对同accepted request最终token、terminal、actual seed、RNG与transcript一致。
- `prefill.mode/chunk_size/reservation policy`在request accepted前冻结；active request不得热切。
- prompt logprobs如reference backend不能跨chunk正确聚合，则明确UNSUPPORTED或走full path，不能漏位置。
- request取消/失败后只保留已commit context；未commit chunk不算processed，也不进入账单/metric numerator。

### 6.2 Config/manifest contract

| 字段/对象 | V0成熟度 | 兼容规则 |
|---|---|---|
| `AttentionPlanV2` | `format_frozen_for_v0` | query_indptr末值=valid query tokens；每token有position/write slot |
| `ChunkPolicyV1` | `candidate` | fixed positive size、run/request冻结；变更config digest |
| `DecodeReservationV1` | `candidate` | 每eligible active decode预留1 token；versioned tie-break |
| `PrefillProgressV1` | `format_frozen_for_v0` | committed cursor单调，只在writer success后增加 |
| `AttentionCapabilities` | `candidate` | 继承 v0.4 并新增 supports_mixed=true 及 max query tokens/rows |

token budget按有效query tokens计：`sum(row.query_len) <= max_query_tokens_per_step`；padding、cached context（本版无prefix）和既有KV不进入budget numerator。

### 6.3 Event/capture/replay contract

- 新增`scheduler.decode_budget_reserved/prefill_chunk_planned/chunk_deferred`和mixed`scheduler.batch_formed`payload。
- chunk event保存range、cursor before/after、planned/committed tokens、reason和config digest。
- AttentionPlanV2 capture保存row type、lengths、positions/block-table/write-slot/valid-mask digests，不保存K/V。
- preemption resume event关联多个chunk IDs与总recomputed tokens，但不改变v0.5 victim reason。
- R0最高能力不变；critical chunk/commit event drop则capture incomplete，不能从最终cursor补造中间过程。

### 6.4 资源、并发与失败 contract

- scheduler先为每个eligible active decode预留1 token；若capacity/constraint阻止执行，记录具体defer reason。
- 剩余budget按FCFS+aging选择prefill request；chunk size最多为`min(config, remaining_prompt, remaining_budget)`。
- 每个valid query token恰有一个absolute position与write slot；prefix/page/chunk边界不重置position。
- row/padding masks与query indptr一致；invalid token不得write/commit/计metric。
- plan/request/page-table任一version stale则整plan rollback/replan，不半执行旧chunk。
- chunk progress仅随writer fence成功推进；cancel/error保留previous cursor。
- finite admissible mixed workload中decode与waiting prefill均forward progress；reservation不能让prefill永久饥饿。

## 8. Correctness and Invariants

### 8.1 Golden/differential

- full/chunked在sizes `{1,page_size,2*page_size+1}` 下逐step/最终logits tolerance、token、terminal、RNG一致。
- mixed plan与拆成独立prefill/decode invocation的reference比较，覆盖ragged rows、GQA、跨page/chunk和padding poison。
- preemption resume full/chunked最终输出一致，recomputed work不发布output。
- chunk size只改变执行边界与性能，不改变tokenization、position或SamplingSpec。

### 8.2 Property/state invariants

- query_indptr单调且末值=valid query tokens；row range不重叠。
- `context_before+query_len=sequence_after`，positions连续，write slots对应当前epoch PageHandle。
- cursor单调；失败/cancel/stale plan不推进cursor或RNG。
- planned/committed/aborted token accounting守恒；padding不计入任何processed numerator。
- 每step budget不超限；active decode reservation满足policy。
- finite admissible load下decode和prefill均forward progress；max waiting age守恒。

### 8.3 Failure/stress matrix

| 场景 | 注入 | 必须结果 | 禁止结果 |
|---|---|---|---|
| mixed row invalid | 错position/slot | launch前拒绝或ticket受控失败 | 部分静默commit |
| middle chunk failure | writer error | cursor保持上次commit | 跳过range |
| cancel race | launch后cancel | suppress output/abort pending/unique terminal | cursor/RNG前移 |
| stale plan | table/cursor变化 | full rollback/replan | 写old handle |
| tiny budget | budget<chunk size | 缩短chunk或defer | 超budget |
| decode saturation | decode占满budget | prefill aging记录并在admissible条件progress | 永久饥饿 |
| chunked resume | 长history+pressure | 多chunk重建、output/RNG不变 | 重发历史token |
| forbidden prefix | 注入prefix config | unsupported before ready | 隐式index/cache state |

至少1,000条ragged schedule/plan property序列；失败seed固化。

## 10. Performance Hypothesis

### 10.1 本版本性能立场

验证固定chunking是否在long-prefill+interactive-decode流量降低ITL或提高request goodput，同时不让TTFT、E2E、失败率和waiting age越界。无Pareto收益可保留full默认，但mixed correctness仍是学习成果。

### 10.2 Experiment card

```yaml
question: fixed chunked prefill 是否改善长prefill与decode混合流量的SLO goodput
hypothesis: 至少一个预注册chunk size降低server_itl_token_weighted_p99或提高request_goodput_accepted_per_second，且TTFT/E2E不过guardrail
primary_metric: request_goodput_accepted_per_second
guardrails: [correctness_pass_rate, server_ttft_request_weighted_p99, server_itl_token_weighted_p99, client_e2e_request_weighted_p99, max_waiting_age_seconds, request_failure_rate, peak_device_memory_bytes]
denominator: TTFT 分布只包含 accepted 且实际产生首个可交付 token 的请求；accepted 但在首 token 前 failed/cancelled 的请求不得伪造无限或零 TTFT，必须计入 `ttft_censored_before_first_token`、failure/outcome 计数并作为 SLO miss。E2E 按 accepted+terminal 分 outcome 报告；ITL 只包含至少两个输出 token 的 accepted 请求之相邻 token interval，并按 interval 加权。admission_rejected 单列且进入 offered-load/SLO 报告，不进入 accepted latency 分布
tuning_suite: fixtures/workloads/v06-chunk-tuning.json@digest
held_out_suite: fixtures/workloads/v06-chunk-heldout.json@digest
budget: 3 GPU-hours
success: 3个size各5次，至少一个held-out点Pareto优于full且correctness/fairness guardrail全过
no_go: 所有点被full支配或尾延迟/调度开销抵消；保留full默认并提交Pareto归因
```

## 11. Compatibility and Migration

### 11.1 Compatibility matrix

| Artifact | 读取v0.5 | 写入格式 | Breaking条件 | 迁移/降级 |
|---|:---:|---|---|---|
| config | 是 | additiveprefill/plan fields | active request热切policy | 缺字段默认full |
| API/CLI | 是 | facade不变，chunkmetadata可选 | token/terminal改变 | full回到v0.5 |
| event/capture | R0是 | additivechunk/mixed payload | V2 ABI语义变化 | 旧viewer只显示known fields |
| manifest | 是 | config绑定AttentionPlanV2/policy | capability不支持 |副作用前fallback |
| runtime KV | 否跨进程 | v0.4 layout不变 | binary/layout变化 | drain/rebuild |

### 11.2 Rollback

- 同binary将新request设为full；active chunked request继续其frozen policy至terminal，或安全cancel/retry。
- 回v0.5 binary前停止admission、drain mixed tickets/requests、等待fence并销毁pool；不迁移chunk cursor/KV。
- preempted/recomputing request必须完成、取消或明确失败，不能把中间cursor交给v0.5 full path。
- rollback bundle保存每request cursor、plan/ticket、pending fence和output/RNG摘要。

## 12. Definition of Done

### 12.1 Must

## 13. Known Limitations

- chunk size与decode reservation固定，不按实时SLO自适应。
- 无prefix reuse；重复prompt仍全部计算。
- mixed attention仍是reference backend，ragged metadata/gather可能昂贵。
- 一次request每step最多一个连续prefill range，不做跨step speculative work。
- R0事件无canonical state reducer。
- 单GPU同步engine，无compile/graph/overlap/custom kernel。

### 13.1 下一版本输入

- v0.6 mixed AttentionPlanV2、cursor/budget和feature-off oracle成为v0.7 prefix reuse基线，不得再改语义。
- 重复prompt workload与locally computed prompt token成本成为v0.7 prefix实验输入。
- v0.7只能新增exact prefix index/ownership/eviction；不得重新设计chunk policy。
